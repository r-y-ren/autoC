# Hao2024 任务优先级感知的多 UAV 协同边缘计算联合卸载

## 单行摘要
论文在多 UAV 协同 MEC 中显式引入任务优先级与二元卸载，通过潜空间混合动作 DRL 联合优化轨迹、卸载和资源分配。

## 题目驱动研究框架
- 研究场景：多架 UAV 协同为地面 UE 提供边缘计算服务的动态 MEC 系统。
- 研究对象：UE 任务流、多架 UAV、边缘云与通信/计算资源。
- 核心问题：在任务优先级不同且采用二元卸载模式时，如何联合决定卸载、轨迹和资源。
- 标题承诺的方法：joint task offloading, resource allocation, and trajectory design。
- 期望效果：提升长期平均系统增益，并兼顾任务时延与能耗。
- 标题与正文的偏差：正文真正的技术亮点是“离散-连续混合动作如何被潜空间 DRL 有效处理”。

## Algorithm Design 快照
论文将多 UAV 协同 MEC 的联合优化问题表述为长期平均系统增益最大化问题，并特别强调任务优先级和二元卸载模式带来的离散-连续混合动作难题。为此，作者先通过离散动作嵌入表与条件变分自编码器构造混合动作潜空间，再把这一潜空间与 TD3 结合，形成能够同时处理轨迹设计、二元卸载、计算资源与通信资源管理的 DRL 方案。

## 图1系统框架草案
- 系统实体：多个 UE、多架协同 UAV、边缘云。
- 任务/数据流：任务可本地执行、由 UAV 执行，或经 UAV 转发至其他 UAV/边缘云。
- 控制/优化变量：任务优先级感知的二元卸载、UAV 轨迹、计算资源分配、通信资源管理。
- 约束来源：UAV 协作、任务优先级差异、混合动作空间、长期时变任务需求。
- 画图提醒：最好把“优先级队列 -> 潜空间动作解码 -> 轨迹/资源执行”画成反馈闭环。

## System Model
- 系统是时隙化的多 UAV 协同 MEC 场景，UE 每个时隙可能生成不同优先级任务。
- 论文采用二元卸载而不是部分卸载，因此“是否卸载”与“给谁执行”需要更明确的离散表达。
- 多个 UAV 既能直接提供算力，也能协同转发任务到其他 UAV 或边缘云。
- 系统目标是长期平均系统增益最大化，而不是单时隙即时最优。

## Algorithm Design 详解
- 第一步构建包含二元离散动作和连续资源动作的混合动作空间。
- 第二步利用嵌入表和条件 VAE 构建动作潜空间，避免粗暴离散化造成性能损失。
- 第三步将潜空间与 TD3 结合，形成适应混合动作的 DRL 求解器。
- 第四步在训练阶段同步更新编码器/解码器和 actor/critic，使潜空间表示持续适应环境变化。

## Introduction 写作素材
- 在多 UAV 协同 MEC 场景里，并不是所有任务都应该被一视同仁地调度。
- 当任务优先级和二元卸载同时存在时，传统连续动作 DRL 很难直接适配。
- 这篇论文适合支撑“系统调度需要从平均性能走向优先级感知”的写作论点。

## Related Work 写作素材
- 与只考虑部分卸载的工作不同，本文强调二元卸载在真实任务中的补充价值。
- 与传统 DRL 直接处理离散-连续混合动作相比，本文先构造潜空间再学习策略。
- 与不考虑任务优先级的多 UAV MEC 工作相比，本文把任务差异性显式写进模型。
