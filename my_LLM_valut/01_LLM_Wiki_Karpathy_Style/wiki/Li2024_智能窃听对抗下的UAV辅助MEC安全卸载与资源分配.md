# Li2024_智能窃听对抗下的UAV辅助MEC安全卸载与资源分配

## 单行摘要
论文研究存在智能窃听 UAV 的多 UAV-MEC 安全卸载场景，通过对抗式 MARL 交替优化合法 UAV 与窃听 UAV 的策略，以最大化最坏情况下 IoT 设备的能效。

## 题目驱动研究框架
- 研究场景：多架合法 UAV 为 IoT 设备提供 MEC 卸载服务，同时多架窃听 UAV 智能机动实施监听。
- 研究对象：合法 UAV 集群、窃听 UAV 集群、IoT 设备、无线链路、计算与能量资源。
- 核心问题：当窃听者不是固定目标、而是会根据环境主动调整轨迹时，传统安全卸载策略容易过拟合并失效。
- 具体方法：把合法 UAV 与窃听 UAV 之间的对抗关系建成零和博弈，用 `ARL-MAPPO` 交替更新双方策略。
- 期望效果：在最坏窃听策略下仍保持更高的 IoT 能效、更低时延和更高任务成功率。

## Algorithm Design 快照
本文不再把窃听者看成固定噪声源，而是看作会学习、会协同、会主动接近合法链路的智能对手。这样一来，合法 UAV 的安全卸载问题不只是轨迹/频谱/算力联合优化，而是一个真正的 min-max 对抗问题。作者先定义 IoT 设备能效指标，把任务执行成功率、执行时延和能耗合并进统一度量，再把合法 UAV 最大化该指标、窃听 UAV 最小化该指标的过程改写成零和博弈。求解上，以 MAPPO 为基础框架，通过“合法 UAV 训练阶段”和“窃听 UAV 训练阶段”交替进行，并利用历史对手策略池缓解过拟合，从而学到更鲁棒的安全卸载策略。

## 图1系统框架草案
- 系统实体：IoT 设备、合法 UAV 集群、窃听 UAV 集群、双天线合法 UAV、MEC 服务器。
- 任务/数据流：IoT 设备在每时隙生成任务；部分任务本地处理，部分卸载给合法 UAV；合法 UAV 一边接收任务一边发送人工噪声；窃听 UAV 根据环境机动调整轨迹。
- 控制/优化变量：合法 UAV 轨迹、IoT 发射功率、人工噪声功率、带宽分配、CPU 频率分配、卸载比例；窃听 UAV 轨迹。
- 约束来源：任务最大时延、UAV 剩余能量、每 UAV 可服务 IoT 数、带宽与 CPU 资源限制。
- 画图提醒：必须把“合法 UAV 训练”和“窃听 UAV 训练”画成交替回路，否则看不出它是对抗式而不是普通 MARL。

## System Model
### A. 对抗式 UAV-MEC 场景
- 系统包含 `N` 架合法 UAV、`K` 架窃听 UAV 和 `M` 个 IoT 设备。IoT 设备在每个时隙生成任务 `D_m=(S_m,C_m,L_m)`。
- IoT 设备可把任务全部或部分卸载给至多一架合法 UAV；每架合法 UAV 在单时隙内可服务的 IoT 数受容量上限约束。

### B. 通信与抗窃听机制
- 合法 UAV 采用双天线：一根接收 IoT 卸载数据，另一根发送人工噪声抑制窃听。
- 系统联合优化带宽、IoT 发射功率、人工噪声功率与 UAV 轨迹，因此链路质量和安全性高度耦合。

### C. 计算卸载与能耗
- IoT 本地计算与卸载计算并行进行，总时延取二者最大值。
- 合法 UAV 处理 IoT 卸载任务时还需承担飞行能耗与发送人工噪声的能耗。
- 论文最终把 IoT 端和 UAV 端的时延与能耗统一进能效指标。

### D. Min-Max 目标
- 合法 UAV 的目标是最大化 IoT 能效，窃听 UAV 的目标是最小化该能效。
- 因此，安全卸载不再是单边优化，而是合法侧与攻击侧同时适应的零和博弈。

## Algorithm Design 详解
- 第一步是问题重构：将原始多目标问题重写为“合法 UAV 最大化 / 窃听 UAV 最小化”的 max-min 问题。
- 第二步是交替分解：固定窃听策略时优化合法 UAV；固定合法策略时优化窃听 UAV。
- 第三步是 MARL 建模：两类 UAV 都采用 CTDE 风格的 MAPPO，动作包含轨迹与资源相关决策。
- 第四步是奖励设计：合法 UAV 奖励与 IoT 能效正相关，窃听 UAV 奖励与之相反。
- 第五步是对手策略池：把历史窃听策略保存并按更“难”的策略给予更高采样概率，用来减少合法 UAV 对单一对手的过拟合。

## Introduction 写作素材
- 在 UAV-MEC 中，真正危险的不是“有无窃听者”，而是窃听者会不会学习并主动机动。
- 如果安全卸载策略只在固定或随机窃听模型下训练，那么一旦对手变聪明，系统性能会突然崩塌。
- 因而，安全卸载需要从“静态防御”转向“对抗式鲁棒决策”。

## Related Work 写作素材
- 与固定位置或简单随机轨迹窃听模型相比，本文显式引入了智能窃听 UAV 的策略更新。
- 与普通安全 MARL 工作相比，本文更强调最坏情况性能，而不是仅在训练分布内的平均安全率。
- 与只把窃听者作为环境一部分的工作相比，本文把攻击侧提升为真正的学习智能体。
