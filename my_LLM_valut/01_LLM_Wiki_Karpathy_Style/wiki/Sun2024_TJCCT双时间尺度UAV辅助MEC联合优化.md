# Sun2024 TJCCT双时间尺度UAV辅助MEC联合优化

## 单行摘要
论文提出 TJCCT 双时间尺度框架，在 UAV 辅助 MEC 中联合处理计算资源分配、任务卸载与轨迹控制，以提升系统效用并兼顾 QoE 与能耗。

## 题目驱动研究框架
- 研究场景：地空协同的 UAV 辅助 MEC 网络。
- 研究对象：移动设备 MDs、MBS、四架 UAV、动态任务与移动轨迹。
- 核心问题：如何在任务、资源、用户移动和 UAV 飞行动态共同变化的系统里做跨层联合优化。
- 标题承诺的方法：two-timescale joint computing resource allocation, computation offloading, and trajectory control。
- 期望效果：提高系统效用、处理率和完成率，同时控制延迟与飞行能耗。
- 标题与正文的偏差：正文的关键不只是“两时间尺度”，还包括价格激励的资源分配、匹配式卸载和凸优化轨迹控制三种方法的分工协作。

## Algorithm Design 快照
论文面向 UAV 辅助 MEC 网络中计算密集且时延敏感的任务处理问题，研究移动设备、地面基站和 UAV 服务器之间如何联合组织计算资源、卸载决策和飞行轨迹。难点在于用户移动与任务到达发生在快时间尺度，而 UAV 轨迹调整和全局资源组织更适合慢时间尺度处理。为此，作者提出 TJCCT 框架：在短时间尺度上通过价格激励方法分配计算资源，并结合匹配机制完成任务卸载；在长时间尺度上再用凸优化控制 UAV 轨迹。该设计把快变业务响应与慢变飞行控制解耦，从而兼顾时延、效用和能量约束。

## 图1系统框架草案
- 系统实体：移动设备、MBS、四架 UAV MEC 服务器。
- 任务/数据流：MD 在每个短时隙产生任务，根据价格和链路状态决定本地处理或向地空 MEC 服务器卸载；UAV 在较长周期上调整轨迹。
- 控制/优化变量：服务器计算资源价格与分配、任务卸载决策、UAV 长周期轨迹。
- 约束来源：MD 预算、任务截止期、链路容量、UAV 速度与能量约束、服务效用函数。
- 画图提醒：建议画成“双环控制”结构，内环是每个 epoch 内的资源与卸载，外环是跨 epoch 的轨迹控制。

## System Model
- 系统由一座 MBS 与多架 UAV 共同提供 MEC 服务，移动设备位置随时间变化。
- 任务具有大小、计算强度和截止期；地面与空中服务器具有不同的频谱、算力与能量约束。
- 效用函数不是简单时延最小化，而是综合了 MD 与 MEC 服务器的收益、QoE 与成本。
- 轨迹控制与计算/卸载决策共用同一全局目标，但更新频率不同，因此引入双时间尺度建模。

## Algorithm Design 详解
- 短时间尺度资源分配：用价格激励方式分配 MEC 服务器计算资源，反映供需关系。
- 短时间尺度卸载：用匹配机制决定 MD 任务卸载去向，使任务与服务器之间形成稳定匹配。
- 长时间尺度轨迹控制：在每个较长控制周期内，用凸优化更新 UAV 轨迹，适配全局负载分布。
- 相比把所有变量一次性扔给单一优化器，这篇论文更像是一个“方法编排框架”，很适合沉淀到[[双时间尺度优化]]页面。

## Introduction 写作素材
- 在 UAV 辅助 MEC 中，业务与飞行动态本身就处于不同时间尺度，强行统一求解往往带来不可控复杂度。
- 价格机制能够把资源供需反馈显式写入卸载系统，而不只是把资源约束隐藏在求解器里。
- 这篇论文可以用来支撑“卸载研究从单一时隙最优转向跨时间尺度系统组织”的写作判断。

## Related Work 写作素材
- 与纯 DRL 联合控制相比，本文使用价格、匹配和凸优化三类工具分工求解。
- 与仅处理卸载或轨迹的工作相比，本文同时处理资源、卸载和轨迹三层耦合。
- 与单时间尺度方法相比，本文把快变需求和慢变机动显式分离。
