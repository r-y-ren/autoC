# Li2024_无人机群辅助IoT多目标优化虚拟天线阵列

## 单行摘要
本文面向多 IoT 集群到远程基站的数据采集与分发场景，在地面传感器和空中 UAV 群两侧同时引入协作波束形成，构造 GVAA 与 AVAA 虚拟天线阵列，并通过 EMSSA 在任务完成时间、面向窃听者的旁瓣电平以及 UAV 总能耗三者之间寻找 Pareto 折中。

## 题目驱动研究框架
- 场景：多个 IoT 集群需要把数据传到远程 BS，但传感器传输能力弱、UAV 频繁飞行代价高。
- 研究对象：由地面 IoT 集群、UAV 群、多个远程 BS 和潜在窃听者组成的协同数据采集与分发系统。
- 存在问题：如果 UAV 反复在 IoT 与 BS 之间飞行，会带来很高时间成本和推进能耗；而增强链路能力又可能放大窃听风险。
- 具体方法：在地面和空中同时做 collaborative beamforming，用多目标优化统一考虑时间、能耗和安全，再用 EMSSA 处理混合变量大规模问题。
- 期望效果：减少长距离或频繁飞行，在不同应用偏好下给出多组可选折中解，而不是只输出单一加权解。

## Algorithm Design 快照
作者的核心动作不是单纯优化 UAV 轨迹，而是重构整个传输范式：让每个 IoT 集群内的传感器先组成地面虚拟阵列，把数据定向发给选中的 UAV；随后 UAV 群内部广播共享数据，再组织空中虚拟阵列按顺序向多个 BS 分发。这样可以把“靠移动弥补链路能力不足”的思路，改成“用协作波束形成增强链路能力，从而减少移动成本”。由于完成时间、窃听方向旁瓣和 UAV 能耗彼此冲突，论文把问题建成三目标 MOP，并提出 EMSSA 处理二进制、整数、连续和排序变量混合出现的复杂解空间。

## 图1系统框架草案
- 地面层：`N_IoT` 个 IoT 集群，每个集群含多个传感器。
- 空中层：`N_UAV` 个 UAV，既是中继节点，也是空中虚拟天线阵列元素。
- 接收层：多个远程 BS。
- 威胁层：一个潜在窃听者，可监听 G2A 与 A2G 传输。
- 数据流：
  1. 每个 IoT 集群的传感器组成 GVAA，把数据发给被选中的单个 UAV 接收器。
  2. 接收 UAV 将数据广播给 UAV 群其他成员。
  3. UAV 群根据访问顺序组成不同 AVAA，依次向多个 BS 分发数据。
- 优化变量：传感器选择、空中接收 UAV 选择、UAV 三维位置、两类阵列激励权重、AVAA 构建时间、BS 访问顺序。

## System Model
### 1. 网络与阵列模型
- 监控区域内存在 `N_IoT` 个 IoT 集群，每个集群有 `N_SN` 个传感器。
- UAV 群记为 `U = {1,...,N_UAV}`，远程 BS 集合记为 `B = {1,...,N_BS}`。
- 每个 IoT 集群先选传感器组成 `GVAA`，再选择一个 UAV 作为空中接收端。
- 数据在 UAV 群内部完成广播后，多个 UAV 组成 `AVAA` 向不同 BS 进行顺序式分发。

论文把传感器侧与 UAV 侧都写成阵列因子模型：
- 传感器侧阵列因子 `AF_h^SN(theta, phi)` 依赖传感器是否被选中、激励电流权重以及阵元空间位置。
- UAV 侧阵列因子 `AF_k^U(theta, phi)` 依赖 UAV 位置与 UAV 激励权重。

这种双侧虚拟天线阵列设计，是论文区别于只在空中做 beamforming 的关键。

### 2. 传输与安全模型
- 论文采用 3GPP 风格的概率 LoS 模型，LoS 概率依赖 UAV 高度和地面水平距离。
- 接收速率由总发射功率、阵列增益、信道增益和噪声共同决定。
- 针对窃听者，不是直接最大化 secrecy rate，而是把“窃听方向的总旁瓣电平”作为一个独立优化目标压低。

这意味着它的安全建模更接近“阵列方向图安全整形”，而不是主动窃听或对抗博弈。

### 3. UAV 推进能耗模型
作者采用典型旋翼 UAV 推进功率模型，把 UAV 群能耗拆成两部分：
- 悬停/传输能耗 `E_tran`
- 执行 AVAA 构形与机动的推进能耗 `E_perf`

因此该文的能耗不仅取决于通信过程，也取决于 UAV 为形成合适阵列几何而进行的位置调整。

## Algorithm Design 详解
### 1. 三目标优化问题
论文把问题写成三目标最小化：
- `f1`：任务完成时间 `T^MCT`
- `f2`：面向窃听者方向的总旁瓣电平
- `f3`：UAV 群总能耗

其中任务完成时间由三段构成：
- `T^G2A`：地面集群到空中接收 UAV 的上传时间
- `T^A2A`：UAV 群内广播同步时间
- `T^A2G`：AVAA 向多个 BS 的分发时间

### 2. 混合变量难点
问题同时含有：
- 二进制变量：哪些传感器参与 CB
- 整数变量：哪个 UAV 作为空中接收器
- 连续变量：激励电流权重与 UAV 三维位置
- 排序变量：BS 访问顺序

论文证明该问题是：
- `NP-hard`
- `mixed-variable`
- `large-scale`

这也是作者不选凸优化或普通 RL 的直接原因。

### 3. EMSSA 的三类增强
作者在 MSSA 基础上主要增强了三步：
- 初始化：对二进制、整数、排序和连续变量分别设计可行初始化；连续部分引入 Weierstrass 函数生成更均匀初始种群。
- 参数更新：把关键参数映射到 chaos 域，用 Sine/Gauss 型混沌映射平衡 exploration 与 exploitation。
- 解更新：分别为二进制、整数和排序变量设计 mutation、随机扰动与 PMX 交叉等更新方式，保证每种变量在更新后仍保持原有物理意义。

### 4. 部署层面的三步工作流
论文还给出一个较有价值的 deployment 视角：
1. UAV 先获取环境信息，尤其是窃听者大致方向。
2. 同一 IoT 集群内部先做数据同步，让多个传感器拥有相同待传数据。
3. 系统运行 EMSSA，输出 Pareto 解集，再由决策者选取最符合当前偏好的折中解。

这部分很适合你后面做“从论文方法到工程实现映射”的桥接素材。

## 代表性结果
- 全 LoS 小规模场景下，EMSSA 得到 `f1 = 238.24 s`、`f2 = -181.61 dB`、`f3 = 8.43 x 10^5 J`。
- 全 LoS 大规模场景下，EMSSA 得到 `f1 = 439.71 s`、`f2 = -293.07 dB`、`f3 = 2.58 x 10^6 J`。
- 概率 LoS 小规模场景下，EMSSA 得到 `f1 = 290.98 s`、`f2 = -205.80 dB`、`f3 = 9.95 x 10^5 J`。
- 概率 LoS 大规模场景下，EMSSA 得到 `f1 = 522.57 s`、`f2 = -311.56 dB`、`f3 = 3.11 x 10^6 J`。
- 与两类非 CB 基准相比，CB 方法在大多数场景下显著降低任务时间；能耗上多数情况更优，但在少数大规模场景中会因 UAV 同步机动过快而不一定占优。

## Introduction 写作素材
- 传统 UAV-assisted IoT 方案往往把“移动”作为弥补链路不足的主要手段，因此 UAV 需要频繁往返于传感器和 BS 之间。
- 这篇论文的切入点是：不只优化飞行，而是提升传输本身，让 UAV 少飞一些。
- 一旦把时间、能耗与安全都纳入同一系统，就不能再只靠单目标加权或单一约束法来描述真实设计张力。

## Related Work 写作素材
- UAV-assisted IoT 相关文献大多聚焦于轨迹设计、部署设计或能量效率优化。

- 多目标 swarm intelligence 文献能处理 Pareto 折中，但面对二进制、整数、连续和排序变量混合出现的场景，往往需要做专门增强。
