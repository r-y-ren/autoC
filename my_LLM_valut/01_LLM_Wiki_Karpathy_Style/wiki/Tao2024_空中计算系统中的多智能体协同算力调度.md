# Tao2024 空中计算系统中的多智能体协同算力调度

## 单行摘要
论文面向 UAV 赋能的 [[空中计算]] 系统，研究多 UAV 在悬停点间协同飞行与算力服务问题，通过多智能体协作同时优化能效与服务公平性，并联合设计轨迹、起飞站位置和悬停点布局。

## 题目驱动研究框架
- 研究场景：多架 UAV 从同一出发站起飞，在多个悬停点上完成数据收集与轻量计算服务。
- 研究对象：出发站、悬停点、多架 UAV、地面用户及其服务公平性。
- 核心问题：UAV 电池有限、用户需求异质，如果只优化能效，可能让部分用户长期得不到服务。
- 标题承诺的方法：multi-agent cooperation for computing power scheduling。
- 期望效果：通过协同轨迹与位置规划提升任务执行能力，同时兼顾整体能效和用户公平。
- 标题与正文的偏差：正文不仅在调度“算力”，更在调度整个服务几何结构，包括出发站和悬停点位置。

## Algorithm Design 快照
论文研究的是多 UAV 空中计算系统中的协同服务组织问题。多个 UAV 从同一出发站出发，在不同悬停点为地面用户收集数据并提供轻量计算，但有限电池和异构需求使得“如何飞”和“在哪里服务”同样关键。为此，作者把问题拆成两部分：一部分是通过多智能体学习进行 UAV 轨迹规划，以提高能效；另一部分是优化出发站和悬停点的位置，以降低最小跳数标准差、改善服务公平性。整体上，这是把传统 UAV 轨迹优化扩展成“几何布局 + 多智能体协同调度”的系统设计问题。

## 图1系统框架草案
- 系统实体：出发站、多架 UAV、多个悬停点、地面用户与收集终端。
- 任务/数据流：UAV 从出发站起飞，经由悬停点完成数据收集与算力服务，再返回出发站。
- 控制/优化变量：UAV 轨迹、出发站位置、悬停点位置、任务服务覆盖关系。
- 约束来源：UAV 电池容量、覆盖要求、最小跳数、服务公平性、返航约束。
- 画图提醒：图中应区分“飞行轨迹规划”和“站点/悬停点布局规划”两层决策。

## System Model
- 多架 UAV 从单一出发站出发，以去往多个悬停点的方式为地面用户提供计算服务。
- 每个悬停点可覆盖一部分地面用户，系统希望实现完全覆盖并限制每架 UAV 的往返次数。
- 优化目标同时包括能效与公平性，因此不能只最短路式规划航线。
- 出发站与悬停点位置不再是固定常量，而是需要联合优化的系统变量。

## Algorithm Design 详解
- 第一部分通过多智能体学习或自适应 Q-learning 进行轨迹规划，以降低总能耗。
- 第二部分通过位置规划调整出发站与悬停点布局，使用户的最小跳数分布更均衡。
- 奖励设计中同时考虑能效目标和公平性目标，而不是只用单一累计收益。
- 该文体现了空中计算系统中“算力调度”其实深度依赖于空间结构设计。

## Introduction 写作素材
- 空中计算系统中的“算力调度”不能仅理解为 CPU 分配，还包括无人机服务几何的组织问题。
- 纯能效目标容易牺牲边缘区域或弱连接用户，公平性应被显式纳入设计。
- 多 UAV 协同系统比单 UAV 更强调起飞站和悬停点的全局布局作用。

## Related Work 写作素材
- 现有空中计算研究多将出发站或悬停点视作给定条件，该文把它们重新拉回优化变量集合。
- 与典型多 UAV 轨迹优化不同，该文把服务公平性而非单纯吞吐/时延放到显著位置。
- 这类工作适合作为空中计算系统级调度研究的代表作。
