## 二、工程发现（internal，多数带测试钉死）

| # | 发现 | 影响 |
|---|---|---|
| 1 | **官方 loader 在 exec 后 sys.path.pop()**——回合期 import 必 ModuleNotFoundError，被静默 except 吞掉=DTSP v1 线上零接合 | 修复：装载窗口内急切导入；接合证明门 test_p41_engagement_gate 常驻；"本地测试过≠生产过"的教训制度化 |
| 2 | **孪生可做到对官方回放 100% 逐位保真**（184 局/132,296 步点+552 注入点零分歧）——离线评估从此有了与线上同字义的地面真理 | 双胞胎=永久资产；一切反事实从此可信 |
| 3 | **零消费窗口内同日起卖批次重排收入中性**（逐件价只随库存水位走）——售卖竞速对我方 stock-follower 架构结构性为零 | v14.3 不发射的机制级依据 |
| 4 | **杂草与商店共用同一条 RNG 流**——状态任何微小偏差经 RNG 复利放大，逐位保真是全有或全无 | 保真门的价值定位 |
| 5 | 两处**席位错位通道**（bc_eval 与 planner_offline_bench.rollout_with_replay_opponent 恒 mine→seat0）：v3 复裁 5/9、7/13 与 BC"执行头胜专家"均系伪影 | 评估数字必须声明席位口径；线上实证才是最终裁决 |
| 6 | **select.aggregate_scores trimmed_mean 按名字序而非值序裁切**（悲观模型恒被裁=折扣死代码）——既有契约测试键序巧合未暴露 | 修复留档待独立复裁 |
| 7 | v13.8 是 obs 纯函数（中途冷启动接续自身状态终局逐位一致）——但 DTSP 分叉后的局面它接不住（换脑错配：FEED 15 日≈0 畜群饿尽） | 混合架构的换脑语义必须 whole-season 连续 |
| 8 | Kaggle 提交镜像自带过时引擎（1.29.3）——打包场景自加载使我方免疫宿主版本 | 工程决策被线上验证 |
| 9 | main 在线收口等纪律修正：**最后两次提交=终榜唯二**，任何新提交挤出最旧者——终局序列必须以"想要的终榜对"倒排 | 终局零提交静默期制度 |
