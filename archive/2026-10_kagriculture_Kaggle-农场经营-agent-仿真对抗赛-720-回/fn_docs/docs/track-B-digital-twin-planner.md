## 0. 结论（一段话）

**放弃"把启发式调得更准"，改为"把整局赛季当成一个可解的优化问题"**：引擎是确定性的、46KB 纯 Python、可整体打包进提交；市场价格是**无噪声的确定性供给曲线**；对手资金/地块/动物全公开、棚仓可 97.3% 精度重构；每回合 1s+60s 预算内可做 **8~40 次完整终局 rollout**。因此可以在 bot 内嵌一个"数字孪生"引擎副本，每天黎明把**剩余整季**在 30~100 个候选战略计划（作物结构×畜群时序×买地×饲料×卖出曲线）× 3 类对手模型下各模拟一遍，选鲁棒最优计划执行当天、次日重规划（MPC）。这条路把"市场自适应结构"从手写分支规则升级为**按局求解**，直接优化真实目标函数（终局资金），从构造上消除折磨了 round-15~21 六轮的"本地涨线上跌"问题。同类赛与公开讨论均未见任何选手在此赛做 bot 内前瞻规划（公开面只有克隆与启发式微操）——这是无主的开阔地。

## 2. 五个改变战局的事实

**F1 引擎是确定性、可内嵌的超廉价模拟器。**
价格不是随机场：`price = base ± amp·f(|inv−10000|)`，无噪声、无均值回归，只随共享库存变化（kaggriculture.py:27-58,192-206）——**任意动作序列的卖出收入可精确算出**。日内零随机（F7，worker_route_scheduler_design §1）、全episode确定性可复现；随机性仅杂草（p=0.005/格/天）与商店抽取，且公式已知 `Random((seed*1000003)^day)`，只差一个未暴露的 seed。场景代码仅 46KB 纯 Python，现役提交本就是多文件 tar.gz——**整个引擎可以合法打包进提交**。interpreter 路径整局 720 步仅 0.022~0.096 ms/步、0.96s/局（本日实测），绕开框架 env.step（0.787ms/步）后：1 步前瞻可评估数千候选、1 天 MPC 约 200-1500 条、**整局终局 rollout 每回合 8~40 次**（engine-factsheet §可行性）。

**F2 状态近乎全可见，"信息战"已被我方打赢。**
farms 全公开：对手资金/地块/动物/单位位置逐回合互见（kaggriculture.json:86-97）；仅 shed/seeds/随身私有，而我方 observer 四通道整数记账已达 validated-fill exact **0.9733**、turn lag 0（opp_supply_observer_design v3）。市场 inventory 与 prices 每回合直读。规划所需的全部状态在回合内可组装。

**F3 天梯顶部没人做前瞻规划。**
公开讨论的顶部分析与自述：top 10 选手以规则/启发式为主；克隆泛滥（top 选手 turns 1-51 跨种子 byte-identical）；"卖单提前一回合"是克隆系标配微操（web-comp-intel §讨论区：discussion/734952、738079、738619、740588）。RL 是社区共识劣势路线：PPO 经济天花板 2 万-8 万 vs 规则系 15 万+（discussion/732902 等）。同类赛里 bot 内 MCTS 也只做到 1-2 步轻量前瞻（prior-art §9）——因为他们的引擎贵；**我们的引擎便宜到能整局重放，这是本赛独有的结构性机会，无人占用**。

**F4 目标函数完全对齐：score = 终局资金（kaggriculture.py:958-964）。**
本地引擎与线上同字节（vendored 1.32.7 ≥ 官方要求 1.32.6），规划器在孪生里优化的数字就是天梯胜负判定的数字。当前六轮"本地 quickwin +N%、线上跌"的根因是**启发式的固定 regime 不随局变化**（sprint_forensics_0919：赢局结构=草莓 20-31 格+瓜 12-18+外购饲料 10-40 倍，而我方被写死的小麦化 regime 压住）——规划器**按局**优化结构，恰好是蓝图已认定的"顶部 bot 核心能力=市场自适应重构"的工程化正解。

**F5 天梯与定榜机制给了明确的操作窗口。**
仅最近 2 次提交被跟踪且唯二参与终榜；BT 定榜用"全程双方在锦标赛时刻仍 active"的 episode，团队分取两次提交较高者（host 原话，discussion/732931、739410）；新提交 K=220 起步、爆发期 ~16 局/时，~100 局/3 天收敛（discussion/736314、736219）。天梯现状（9460 队，CSV 快照 2026-09-18T18:25Z）：#1=3208.4，prize 区≈3023+，top100≈2832，top500≈2630，**中位数仅 781**；我方保底锚 v9.2=663.3 / v10.3=658.2（战役台账）。即：**从 663 到前 500 需要的是结构性换代，不是参数打磨**。

## 3. 为什么不是另外两条路（诚实排除）

- **端到端自博弈 RL（PPO/AlphaZero 系）**：社区实测天花板低于规则系一个量级（F3）；KB-2 仅 2 张种子卡、无 imitation/world-model 储备；本机算力未知、Kaggle GPU 30h/周为次级口径；10 天窗口贴边。**不做主线**。
- **行为克隆顶部回放**：配方公开（Lux S3 3rd 纯 IL 拿铜；本赛 diffmap/kaggicultureRL 的 behavior_mimicry 模式），但顶部选手"主动退役防克隆"+ 赛中 balance patch 使克隆品天然滞后（discussion/739179、733431），且克隆只学到"他们当时那手"，学不到"按局自适应"。**降级为 Track-B 失败时的 fallback B**，不占主线资源。

## 4. DTSP 架构（五个组件，全部有本地先例可依）

```
每个黎明（~30 个决策点/局）：
  组装孪生初态（obs 组装 + observer 补对手棚仓 + 商店/杂草保守建模）
  → 对每个候选计划 π ∈ Π（~30-100 个）× 对手模型 ω ∈ Ω（3 类）：
       用内嵌引擎副本 rollout 剩余整季 → 终局资金 J(π,ω)
  → 鲁棒选择 argmax（对手模型集上取 trimmed-mean / worst-case）
  → 执行当日：现有四层调度器按选中计划参数包运行（v13.8 引擎原样复用）
  → 次日重规划（MPC 闭环）
任意异常/超时 → fail-open 回退现役反应式 v13.8（沿用既有 fail-open 纪律）
```

1. **数字孪生**：vendored 场景 46KB 原样打包进提交（多文件 tar.gz 官方支持，限 100MB 社区口径）；启动时指纹校验（防漂移）；克隆走写时复制，禁逐步 deepcopy（engine-factsheet 风险③）。
2. **规划空间 Π**：不发明新空间——直接复用 `phase_branch_plan v1.5` 的参数包体系（P0-P5 结构分支 × C1-C3 容量档 × 作物配额/买地时点/畜群时序/卖出曲线旋钮），离散组合 + 少量连续缩放（配额 ±25%、扩张提前/推后 1-2 天）。v1.5 的分支触发条件全部公开可观测，天然就是搜索空间的坐标轴。
3. **rollout 策略**：候选计划的"执行"由现役四层引擎（mission→solver→executor→market）在孪生内完成——v13.8 是已验证的强执行器（本地终局资金 13-15 万档），规划器只换"脑"、不换"手"，风险被隔离在战略层。
4. **对手模型 Ω**：①被动延续（对手按已观测行为外推，动作生成复用 m2 画像风格 bot）；②冻结画像池（60 局语料 + round2-21 多代官方回放已建库）；③悲观成交（对手在我方卖出时段倾销、成交价加安全折扣）——对应引擎唯一的硬耦合通道：per-unit 锁步成交会压价（kaggriculture.py:544-628）。
5. **时间治理器**：预算 = 1s/回合 + 60s 全局透支池。黎明决策点约 30 个/局 × 每次 15-40 rollouts × 20-70ms ≈ 9-84s → 治理器按剩余透支池动态调 rollouts 数并留 2-5× 硬件余量（Kaggle 评审机单核速度未知，engine-factsheet 风险①）；非决策点回合零规划开销。

## 5. 为什么它能解开"本地涨线上跌"死结

| | 现役 Track-A（启发式 regime） | Track-B（孪生规划器） |
|---|---|---|
| 结构决策 | 人工预设分支+阈值，全局恒定 | 每局按市场/对手状态求解，局内自适应 |
| 优化目标 | 代理指标（本地 quickwin 经济） | 真实目标（终局资金 rollout） |
| 本地→线上迁移 | 依赖"对手分布=本地池"假设，已被 round-15~21 反复证伪 | 孪生=官方同字节引擎，差异只剩对手模型误差与杂草噪声（可用种子系综平均） |
| 对手耦合 | 干扰模块规则触发 | 直接在 rollout 里算"对手卖单压我价格"的净效应 |
| 失败模式 | 结构性（写死） | 可归因（哪类对手模型下亏→补哪类模型） |

sprint_forensics_0919 的跨代法证已证明"结构由代际决定、组内胜负分层"——Track-B 把"选结构"从一次性的 compile-time 决定变成 per-game run-time 决定，正对根因。

## 8. 风险与红线

1. **规则红线**：禁网 §2.12（本方案全离线 ✓）；外部数据/模型与"公开回放训练" host 明文允许/鼓励；借鉴公开代码合法（host："fair use"）；**利用引擎 bug 无宽恕条款**（§3.8.d/§3.16，可 DQ）——孪生只用官方语义，不做引擎外溢利用；官方原则 "engine is the source of truth" 与孪生路线天然同向（web-comp-intel §3/§7）。
2. **赛中补丁风险**：8 月已有 balance changes 先例，旧 agent 变 stale——孪生内嵌副本与 vendored 上游做启动指纹校验，patch 后 24h 内重建（web-comp-intel §11）。
3. **算力不确定**：评审机速度未知 → 治理器留 2-5× 余量+时间片中断+fail-open；P3 用 validation episode 实测预算后再放大 rollouts。
4. **对手模型误差**：三模型集+鲁棒选择+悲观成交折扣兜底；P2 失败归因清单驱动补型。
5. **杂草/商店噪声**：公式已知仅 seed 未知 → 种子系综（8-16 个采样 seed）取均值/坏情形；商店增量观测+保守可用集。
6. **克隆防御**：强 agent 会被克隆（顶部先例）——规划器行为按局状态分化，天然难克隆；终局两周不公开任何代码/notebook（09-23 共享锁之后本来也不能再共享）。
7. **止损**：P2 离线打不过 v13.8 反应式（两轮修复后）→ Track-B 降级 fallback B（行为克隆残差策略）或并回 Track-A，保底锚 v9.2+v10.3 与 Track-A 节奏不受任何影响。
