# 第八轮实验约束

本轮继续改进已提交的 v7。3000–3200 是线上目标，不是本地金币或胜率可以换算出的承诺。线上评分尚待用户下一次反馈。

## 冻结与分组

- `league_seeds.json` 在策略筛选前冻结：20 个 development 世界，40 个 confirmation 世界，40 个 reserve 世界。每组由独立标签的 SHA-256 生成，不使用游戏隐藏随机种子决定在线动作。
- 常规对抗交换双方位置。统计以世界为抽样单位；同一世界的双方位置及不同对手不算独立地图。引擎的商店随机数还受两人农场空格数量影响，因此相同种子不保证不同策略拥有完全相同的未来商店。
- 新下载的两位领先者回放每人 24 场用于研究，另外各 5 场封存；排除上一轮已研究和封存的回放。回放代理属于我们自己的复现程序，不能代表原作者的私有智能体。
- 候选文件及对手文件哈希随任务固定，变化必须使用新文件和新实验名称。逐局 JSONL 可续跑，已完成的任务不重复计入。

## 对抗与检查

使用未经修改的官方 `kaggle-environments==1.32.7`，720 状态、719 个行动回合，默认比赛配置。各场重新加载官方最后一个可调用入口；检查双方 DONE、stderr、可见的内部错误/退化计数、动作耗时、期末未送回物资。

并发测试耗时受本机负载影响，最终包另做串行、隔离进程和连续两局复位验收。公开源码中的可选 `V92_SELL_LIB` 文件入口在本轮运行环境不存在。

不同机制先做开发对照，失败候选保留记录。默认不把没有收益或只在已知地图生效的改动放入发布；生产扩种还要检查实际卖出数量、额外人工、溢出和遗漏，不能用请求产量代替实际收入。

最终选定哈希后才检查 confirmation 对抗结果。若确认失败，该组不能再次充当未见数据；后续修订使用 reserve 组。比较报告提供配对分差、积分变化、分对手结果及按世界重采样的置信区间；不从这些结果推算 Kaggle 评分。

## 对手池与限制

包含 v6、v7、公开 V56、Orderbook、Master2965、Fieldcraft，以及 DSM 回放构建的严格状态兼容与任务重规划代理。多个公开程序共享代码祖先，不能视为八个完全独立的策略家族。弱代理的胜率必须单独报告，不能用大量轻松取胜掩盖强对手退步。

对特定生产触发条件的主动取样是诊断集，不属于随机留出胜率。若只跑到第 433 状态检查触发，必须标记为前缀检查，不能计作完整对局。自定义配置的运输/仓库功能测试也不得混入排名对抗成绩。

## 第二候选与选择校正（读取确认强度前追加）

DSM现金合同修复先冻结7735版本，但官方入口不合格；240次尝试在开始完整比赛前报错，计作失败执行，不计作完成对局。237681版本只加唯一末尾可调用入口，官方文件完整一局719动作与旧显式策略等价。策略未因确认集成绩而改变。两份冻结及官方入口验证记录均保留。

237681先完成同样的20世界、6对手、双席240开发局。若其总体积分至少达到主候选开发积分，且无未解释的运行错误，则进入相同40确认世界，复用v7与主候选已有对照。否则不进入独立确认，选择原主候选。

如果两个冻结候选都进入确认，同时报告：主候选-v7、DSM修复-v7、DSM修复-主候选三组配对比较。每组均报告原始95%区间，并用Bonferroni的每组98.333%区间控制这三个比较的合计错误率。代码参数为`--familywise-candidates 3`，按世界重采样10000次。这仍是有限样本bootstrap估计，不是任意总体的精确覆盖保证。

发布候选必须通过提交技术验收，且相对v7积分改善的校正区间下限大于0；若两者均通过，选择平均确认积分较高者，公开它与另一个候选差异的校正区间，区间跨0时明确相互优劣仍不确定。若都不通过，不宣称本轮新策略已验证更强。任何后续新策略改动不得继续使用本组确认作为独立验收，改用reserve或新的预先冻结面板。
