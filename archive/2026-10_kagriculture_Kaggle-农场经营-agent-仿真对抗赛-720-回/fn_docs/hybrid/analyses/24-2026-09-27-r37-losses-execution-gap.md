## 五、改进提案（≥3 含激进）

### P1 [默认·结构] 条件路由库+同开局面拼接
- 现象：调研强证据——Tschinkel 95.5% 路由（84.6→95.5，44k 局 held-out）、OpenKaggle hybrid 决策树选锚、cha22 同架构；我方固定 41 路由+店对表（step144 一次性锁存）。
- 假设：`_router`（职责=step144 锁存路由）只用店对二元信息——"同开局面拼接"（step144 用 screen_continuations 选续段）是公开验证的单变量 +11pp 杠杆。
- 改进方向：step144 续段选择器（同开局族拼接/冻结锚点决策树），路由库按败局世界补覆盖（牛奶流/羊毛流/鹅蛋流对手的开局族）。
- 预期信号：对榜前 550 对手胜率 0/5 → ≥30%；d21-28 段 margin 中位转正；总胜率回 ≥85%。
- 分流：结构性（回 fn-divide）。

### P2 [执行面] 同回合卖单竞速+晚季批量化
- 现象：败局对手卖单更少更大（337 vs 405）；调研 cha22 复盘"稳健胜负差=同回合卖单成交竞速（实际单价 +8-10%）"；d21-28 变现窗 9/12 败。
- 假设：`_sell_lead`/`_clamp_sells`（卖单时点/量职责）与 layer D 槽序（执行面）——我方卖单碎、同回合竞速无机制。
- 改进方向：晚季（d21-28）卖单批量化（少而大）+同回合抢价执行（对手挂单前成交）。
- 预期信号：d21-28 段 margin 中位 +7k 级（胜局基线）；实现单价 +5% 级。
- 分流：参数/逻辑级（[改造] 卖侧链+layer D）。

### P3 [激进] Rust 仿真器判决基建+败局世界定向路由
- 现象：debmalyaroy 仿真器实测 16x、byte-identical、自带 McNemar 逐对手分解+screen_continuations(at_step=144)（路由库现成工具）；我方判决实验 6-40 分钟/轮。
- 假设：判决速度 16x=试错吞吐 16x——P1/P2 的参数空间可穷举；败局世界（牛奶/羊毛/鹅蛋三型）补路由需要大量试验。
- 改进方向：集成 Rust 仿真器为判决基建（kaggsim 纯 stdlib、agent 原样跑），P1 路由库穷举+P2 参数扫描全走快车道。
- 预期信号：判决轮时长 ↓10x；P1/P2 调参迭代 ≥5 轮/日。
- 分流：基建级（工具链，非作品代码）。

### P4 [队列管理] 零执行单占槽+补洞机制
- 现象：调研（lynnsakurai/cha22）：零执行单占槽+后位补洞是公开执行细节；我方 `_ig_close_queue` 有置穴机制但无补洞。
- 假设：市场单槽管理面（职责=槽位语义）——占槽浪费降低有效挂单。
- 改进方向：零执行单识别+槽位补洞（沿空槽位次语义）。
- 预期信号：有效挂单占比升；实现单价 +2% 级。
- 分流：参数/逻辑级。

**不推**（调研负证据）：BUY_PRODUCT 喂麦（公开负结果）、day0 作物重排（全场同构、期望值低）、V93 敌指纹路由（无效果实验；降级为克隆门控+败因诊断）。
