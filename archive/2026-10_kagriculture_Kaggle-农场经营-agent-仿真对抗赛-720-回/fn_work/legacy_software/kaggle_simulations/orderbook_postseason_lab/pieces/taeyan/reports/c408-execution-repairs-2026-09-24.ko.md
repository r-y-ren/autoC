# c408 실행 결함 수리 — 개발 계약

2026-09-24 Codex. 사용자 요청: c407 감사에서 확인된 급식·가축 탈출, 운반 작업 정체, 빈 작업 및 화물 폐기를 수정한다. c407과 과거 동결 후보·검증은 보존한다.

## 선행과 달라진 점

- o302는 농부의 이후 FEED 수만큼 픽업을 보충하되 다른 일손 예약량을 빼고 남은 창고 재고만 쓴다. 감사의 d26 조건에서는 여유가 없어 보충되지 않았다. c408은 **기존 `_r97_supply`의 선행 공급**에도 이 농부 픽업 수요를 반영한다.
- c401은 다음 raw 시장이10칸일 때만 선구매하던 조건을 HIRE 포함으로 넓혔지만 작물 전환에 따른 생산·폐기 회귀로 보류됐다. 이번에는 검증 c407을 부모로 쓰고 작물 선택은 바꾸지 않는다. **고용 턴 뒤 두 번의 field 단계까지**, 자기 계획상 픽업 수요를 기존 예산·시장칸·구매체결·밤 폐기 보호 안에서 공급한다.
- 공개 SL의 6양 전담 일손은 필요한 밀 전량이 없으면 가진 밀로도 일을 진행하지 않았다. 밀4개·창고0의 `PICKUP WHEAT 0`21턴은 그 실행 증거다. **차액만 픽업하고, 창고가 비면 현재 소지분부터 급식**한다. 실제 전담 일손의 잔여 급식량도 기존 공급기에 포함한다.
- 공개 OV는 이미 자정 폐기 방지 기능이 있다. 새 기능을 만들지 않고 **후속 field/시장 overlay 이후, c405 결산 전에** 같은 보호를 다시 적용한다. 밤이 지난 뒤 재고 벡터를 보존하는 범위만 허용한다. 이 제한으로 회수할 수 없는 폐기는 별도로 남을 수 있다.
- 빈 수확·급수 등은 정확 field 적용 결과가 무변화일 때만 PASS로 정리한다. 경로나 고용 위치를 앞당기지 않는다. **명령 정규화가 수확량 증가나 시간 절약은 아니다.** 실질적으로 놓친 수확·자정 폐기와 구분한다. c330의 기존 courier 및 c379/c383 최종 운반 보존을 재사용한다.

## 실행·판정

노출된 결함6세계와 큰 패배/정상 대조2세계, 각 양좌석에 c407/OFF/c408을 실행하는48native 개발. 선언된6worker, 일반 League 중지·수집 유지. 기존 c386 QA/c300 native와 c388 경제 판정기를 재사용한다. OFF 전체 행동/최종상태 동일·오류/관측변조0, own≥0·margin>0·승점≥0·양수2세계 이상이 경제 조건이다. 새 독립 성능 검증 전 절대적 급식/탈출/작업진행/화물 회귀도 검사한다. 같은 결함을 PASS로 숨겼다는 이유로 고쳤다고 판정하지 않는다.

개발 소스 `a46b86779e93f6bdc331817ad390474f8a12853c42ba3de902546441b7ad66c8`, 부모 `84ec23c4…`. `state/c408/source-freeze.json`과 `development-plan.json`에 실제 입력/해시·선행 근거를 저장했다. `state/c408/c408_execution_repairs_submission.tar.gz` 단일main.py readback PASS, 아직 등록·제출 대상 아님.

개발 실행기의 첫 호출은 Windows spawn에서 exec로 만든 `run`을 pickle하지 못해 **경기 실행 전 실패**했다. 후보/계약은 그대로 두고 기존 모듈의 import 가능한 `run`을 재사용하도록 어댑터만 수정했다. 최초 로그 `development-console.txt`와 재개 로그 `development-console-v1b.txt`를 모두 보존한다.

## 결과: c408 기각, c409 원인별 진단으로 분리

48/48 native 유효, 오류·관측변조 0, OFF 16조건 동일. 그러나 부모 대비 own −121.56, 마진 −179, 승점 −12.5pp, W→L 2로 개발 경제 기준 FAIL. 정식 screen/confirm·등록·제출하지 않는다.

기존 c407 대조를 재사용하고 c408만 13조건을 추가 재생한 정확 원장에서는 탈출 15→6, 선택 세계의 무효 명령은 PASS 정규화로 사라졌다. 이것은 모든 결함 해결이 아니다. 농부의 실제 PICKUP 수량은 그대로라 거위 탈출이 남았고, 폐기도 대부분 그대로였다. 씨앗·동물 구매는 같지만 일부 조건에 비료 구매·추가 고용·작물 수확량 변화가 생겼다. `state/c408/repair-field-readout.json`에 절대 탈출·수확·폐기를 보존했다.

다음 c409는 c407에서 별도로 시작한다. (1) 현재 실행 PICKUP에서 실제 남은 급식 경로에 필요한 부족분만 더 싣고, 그만큼만 시장에서 보충해 동료의 재고를 보존한다. (2) 부분 사료를 가진 6양 전담 일손의 정체 수정은 별도로 절제 검사한다. (3) o306은 창고가 비어 판매하지 못해 무효였고, c408의 OV 재호출도 같은 한계다. 자정 원장상 과잉 구매가 화물 공간을 차지하는 경우를 검사한다. 예시 2001388603의575턴은 기존 구매 포함 폐기17u, 구매 제외 시 폐기0이며 다음 아침 밀37/비료17을 보유한다. 다음날 실제 수요와 기존 판매량을 보호하는 구매 감축만 별도 진단한다. 개발 결과로 독립 성능 우세를 주장하지 않는다.
