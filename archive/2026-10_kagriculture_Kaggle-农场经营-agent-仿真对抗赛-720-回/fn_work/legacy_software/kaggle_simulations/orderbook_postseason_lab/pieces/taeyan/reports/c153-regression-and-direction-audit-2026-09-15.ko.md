# c153 성능 저하 주장과 개선 방향 감사

## 현재 판단

2026-09-15 확인한 API 스냅샷: c129 2820.3, c146 2788.3,
c152 2703.1, c153 2383.3. c153은 점수가 낮지만 현재 확보한 12패에서는
c129와 c153이 719턴 모두 같은 행동을 냈고, 실제 Kaggle 행동과도 일치했다.
따라서 이 표본에서 c153 추가 로직이 패배를 만들었다는 근거는 없다.
핵심 실패는 기존 약점을 해결하지 못한 후보를 개선 모델로 제출한 판단이다.
승격 기준선은 c129로 유지한다. 이번 감사에서는 제출하지 않았다.

API 반환 중 보상으로 판정 가능한 경기: c129 85승36패(121),
c146 76승38패(114), c152 52승29패(81), c153 59승12패(71).
상대, 시드, 좌석, 평가 시점이 같지 않다. 승률과 레이팅 차이만으로
인과적 퇴화를 확정하거나, 반대로 c153이 더 강하다고 주장할 수 없다.
반환 목록의 전체 역사 완전성도 보장하지 않는다.

## 확인된 개발/검증 문제

1. **통과하지 못한 개선 게이트를 제출 때 우회했다.**
   이전 1792경기는 두 정책 각각 896경기, 독립 시드는 64개다.
   변경 행동 0, 승점 차이 0, 긴급구매 0이고 `development_gate_passed=false`다.
   이는 좁은 코드가 비활성이라는 증거이며 일반 개선/활성 상태의 안전성 증거가 아니다.
   사용자의 제출 권한은 성능 근거를 대신하지 않는다.

2. **좁은 실패 복구를 주요 체급 개선 과제로 취급했다.**
   c153은 step144..431, 기존 비판매 주문, 밀 판매 없음, 긴급 동물과
   다음 픽업 경로, 정확히 1개 부족 등 조건이 겹쳐야 발동한다.
   이미 패한 두 기록에서 발견한 조건을 복구해도 대부분의 경기 경제는 그대로다.
   희소 복구는 보조 유지보수로 분류하고, 새로운 생산/노동 배분의 개선을
   확인하는 개발 과제와 성과를 분리해야 한다.

3. **상대 다양성과 평균 마진이 과대평가되기 쉬웠다.**
   요청한 공개 세 종은 결과가 거의 같고 관련 계통이다.
   nagata에는 128전승, 평균 마진 약 +109683이었다.
   이런 약한 상대의 큰 마진이 전체 평균을 지배해 접전 경쟁력을 가린다.
   공개 세 종 각각 76승52패는 유용하지만 현 1~3위 상대 승률이 아니다.

4. **고정 상대 마진을 자기 경제 개선으로 오해할 위험이 있다.**
   독립 재검증에서 108609267 마진 +5947 중 자기 현금은 +1569,
   상대 현금은 -4378이었다. 108724215는 마진 +2997이나 자기 현금 -305,
   상대 현금 -3302였다. 상대가 상태 변화에 적응하지 않는 진단에서 얻은
   상대 손실은 실제 반응형 경쟁에서 유지된다고 보장할 수 없다.

5. **기존 4경기 진단 실행기에 전역 상태 경합이 있었다.**
   `run_mechanism.py`는 ThreadPoolExecutor에서 replay_lab.evaluate를 직접 호출한다.
   evaluate는 엔진 모듈의 `_end_of_day`를 바꾸고 복구한다.
   서로 다른 경기의 함수와 stdout/stderr 캡처가 간섭할 수 있다.
   이번에는 경기당 별도 subprocess로 두 에피소드×두 모드×두 정책=8경기를
   실행했다. 모두 건강했고 두 모드에서 같은 개선 수치와 정확한 상점 경로를
   재현했다. 따라서 이전 '후보 때문에 fixed-shop 경로가 달라졌다'는 설명은
   철회한다. 1792경기 반응형 러너는 원래 경기별 subprocess라 이 결함과 구분된다.
   이전 파일은 수정하지 않고 감사 결과로 증거를 대체한다.

## 새 12패에서 확인한 범위

- 12/12 경기의 c129/c153 정책 차이 0턴, 실제 제출 행동 불일치 0턴.
- 6/12는 최종 마진 절댓값 1000 미만.
- 5/12는 step504 현금 우위 후 최종 패배. 현금은 미실현 자산 가치를 포함하지 않는다.
- 최악 108990377: step288 -281, step432 -2479, step504 -5165,
  최종 -7418. 초반 즉시 붕괴보다 중반 이후 누적 격차가 관찰된다.
- 108965111: step288 +18, step432 -572, 최종 -4707.

이것은 원인 위치를 좁히는 관찰이다. 작물 전환이나 판매 한 가지가 원인이라는
주장은 아직 하지 않는다. 다음에는 실제 수확/판매량, 투입, 현금 증감 장부로 분해한다.

## 권장 개선 방향

**우선순위 1: 마지막 수확까지 실행 가능한 작업 묶음의 순이익 평가.**
현재 자원에서 수확→운반→판매, 급식→추가 생산→회수,
추가 노동→처리 가능한 작업의 순증가 가치를 비교한다.
판매가격은 현재 호가 하나가 아니라 상대 공급을 포함한 보수적 가격 범위를 쓴다.
개별 행동을 탐욕적으로 바꾸지 말고 완료 가능한 묶음만 기존 계획과 교체한다.
접전/후반 패배를 대상으로 검증하되 개발에 쓰지 않은 이긴 경기에도 확인한다.

**우선순위 2: 중반 생산·재투자 선택 범위 확장.**
상점 공개와 생산주기 종료 시 기존 양/소/거위/작물 유지, 일부 교체,
추가 확장, 투자 유보를 비교한다. 남은 수확 횟수, 사료/종자/비료/노동/토지,
운반시간과 회수 시점을 합산한다. 상대나 시드 ID 조건을 쓰지 않는다.
처음부터 전면 planner로 교체하지 말고 기존 경로가 실행 가능한 선택 묶음
2~3개를 제안하는 계층으로 시작한다. 신규 코드량보다 실제 유효 기회 포착률을 본다.

**우선순위 3: 공통 실행 예약과 실패 후 복구.**
위 두 과제의 기반으로 현금·밀·창고·작업자 시간의 공유 장부를 둔다.
예약→실제 성공 확인→실패 시 해제/재계획을 연결한다.
특정 턴 한 번의 BUY 추가보다 여러 정책이 충돌하지 않는 구조를 목표로 한다.
기존 부모는 기준으로 고정하고 새로운 분기에서 한 메커니즘씩 검증한다.

## 더 효율적인 평가와 튜닝

- 개발 초기에 실제 행동/완료 작업이 바뀌는지 먼저 확인한다. 무변화 후보의
  천 단위 경기 확대를 중단하고 진입 조건·실행 기회를 분석한다.
- 강하고 서로 다른 반응형 계통을 우선 확보하고, 같은 계통 복제는 가중치를
  나누어 가진다. 약한 상대는 실행 회귀 확인용으로 따로 보고한다.
- 고정 리플레이는 원인 찾기와 메커니즘 검사 전용이다. 통과해도 승격하지 않는다.
- 발견/선택/최종 확인 조건을 사전 분리한다. 후보가 활성화된 조건만 골라
  최종 성적을 보고하지 않는다. 활성 분석과 전체 성적을 함께 보고한다.
- 주 지표는 계통 균형 paired 승점 차이. 자기 현금, 실현 매출, 꼬리 손실,
  좌석별 차이는 보조 지표다. 독립 단위는 시드 묶음이다.
- '단 한 번의 승→패도 금지'는 큰 개선까지 막을 수 있다. 실행 오류는 0을
  요구하되 전략적 교환은 사전 정한 하위군·꼬리 위험 한도와 전체 개선으로 판단한다.
  결과를 본 뒤 한도를 낮추지 않는다. 불확실하면 승격 보류한다.
- 로직이 여러 새 조건에서 활성화되고 가치 예측이 실현 순이익과 맞아야 튜닝한다.
  먼저 4~6개 경제성 파라미터를 랜덤/TPE로 약 12~24개 탐색한다.
  초기 탈락은 양 좌석과 모든 상대 계통을 한 묶음으로 본 후 적용한다.
  최종 후보 고정 후에는 미사용 시드·별도 상대 조건을 한 번만 사용한다.
