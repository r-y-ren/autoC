# c341 — 가용일정 기반 생산 대안과 실제 공유자원 진단

**처음으로 원본과 다른 생산/경로 조합을 얻었지만, 전체 엔진의 고용·공유자원 계약을 통과하지 못했다. 제출 후보가 아니다.** 독립 타일 생산량과 실제 농장의 생산량을 구분하며, 진단의 현금 증분을 전략 개선으로 인정하지 않는다.

## c340에서 바꾼 점

c340의41대체 일정은 매일 자유 방문을 가정했고533개 타일-일정 중509개가 개별 가용량부터 초과했다. 이번에는 각 타일에게 원본 구간을 독점시켜 얻는 낙관적 날짜별 용량을 생성 단계에 넣었다. 공유 구간 경쟁은 이후 기존 공동 경로 모델로 판단한다. 같은 사례·같은 고정 가격 시나리오·같은 투입 예산을 사용하며 가격이나 상대별 문턱을 조정하지 않았다.

기존 c338 공식 엔진 DP, c340 KEEP 시작 해/HiGHS 모델, c337 경로 비용을 재사용했다. 관측된 미래 구간을 쓰는 연구 완화이며 배포 정책은 아니다.

## 생성기 출력 범위의 추가 결함과 수리

타일별 가용일을 넣은72개 고유 생성 문제에서288개 선택 일정을 공식 재생했다. 첫 사전 비교는 메모리 tuple과 저장 JSON list를 직접 비교해 멈췄다. 전체 값을 JSON 정규화한 비교로 고친 뒤 동일성을 확인했다. 초기 파일·로그는 보존했다.

이 출력의 공동 선택에서는 KEEP만 찾았다. 균형 시나리오는 최적성이 확인됐지만 토마토/당근 시나리오는 제한 종료이므로 기각 근거가 아니다.

추가로 생성기가 작업 예산17–20의 최고 점수 일정만 내보내고 있음을 확인했다. 같은 DP 안에 계산된 저노동 대안이 누락되어, 일부 생산을 포기하고 다른 타일에 노동을 주는 조합을 만들기 어려웠다. 탐색 상태·가격·최대 작업수는 유지하고 **0–20 모든 노동 예산의 대안**을 내보냈다. 기존17–20 결과가 동일함을 사전 확인했다.

72문제에서1,512개 예산별 선택 일정을 유한 씨앗·비료 재고로 공식 직선 재생했다. 중복 제거 후 타일마다 KEEP 포함60–61개 대안이 남았다. 여전히 같은 생산량·작업수라도 서로 다른 모든 달력 모양을 보존하는 완전한 frontier는 아니다.

## 공동 선택과 경로 물리 확인

원본 KEEP이 모든 제약을 만족함을 다시 확인했다.38,410변수·2,360제약의 모델에서:

- 균형: KEEP10582, 최적 gap0.
- 토마토: 유효 incumbent8578, KEEP6502. 제한 종료, gap약0.723.
- 당근: 유효 incumbent7392, KEEP7182. 제한 종료, gap약0.844.

이는 고정 가격 시나리오 점수이며 경기 현금/기대 수익이 아니다. 시간 제한 해를 최적해라 부르지 않는다. 모델의 더 좋은 미발견 해가 있는지 미확정이다.

토마토 해는 어떤 타일의 생산을 줄이거나 비우고 다른 타일에 서비스를 배정했다. 경로를 실제 시각으로 풀어 공식 타일 재생한 결과 토마토46u·당근34u가 모델과 같았다. 당근 해도 당근62u·토마토11u가 같았다. 균형 KEEP의 딸기102u·당근8u·밀2u도 재현됐다. 시나리오별13타일, 총39개 재배정 결과에 불일치0. 하지만 이 검사에서는 각 타일에 씨앗과 비료가 미리 공급됐고, 일꾼 출생·공유 주머니·판매는 아직 없었다.

## 전체 공식 엔진 공유자원 진단

첫 비KEEP 해인 토마토 시나리오를 물리/자원 결과를 보기 전에 대상으로 고정했다. 원본 녹음에서 양측 시장 주문과 상대 행동을 유지하고, 우리 지역 작업을 생성 경로로 바꿨다. 원래 d11딸기 씨앗 구매를 새 유한 씨앗 묶음으로 바꾸었다. 이것은 사후 미래 계획과 동결 시장 주문을 사용하는 진단이며 반응형 전략 성능 비교가 아니다.

먼저 원본 제어를 시작부터 재생해 양측 전체 관측·최종 현금 일치를 확인했다. 초기 probe는 “BUY_SEED STRAWBERRY13 한 주문”을 가정했으나 실제는2/1씩10주문 합계13이었다. 그 변경이 적용되지 않은 실행은 종료 assert에서 실패했고 성능 자료에서 제외했다. 원로그 보존 후 실제 분할 구매를 대체하도록 수정했다. 새 씨앗은 첫 구매 시각에 한 묶음으로 사므로 원본 자금 타이밍과 다른 압력이 있다는 한계도 남겼다.

수정 probe 결과:

- 예상 지역 생산: 토마토46·당근34.
- 실제 지역 생산: 토마토18·당근25·밀3.
- 시비15시도 중6회 체결, 그중 주머니에 비료가 아예 없던 시도6회.
- 식재20시도 중4회 실패. 엉뚱한 작물·잡초가 남은 타일에 식재하는 사례가 있었다.
- 검사한 비자정 구간 끝 위치 불일치6개. 자정 자동 초기화 직전 위치까지 검사했다고 주장하지 않는다.

최종 현금이 우리71000→74338, 상대83177→91726으로 바뀌었지만, 시장 주문이 고정된 데다 실행 계약이 깨져 성능 수치로 사용하지 않는다. 일부 새 상품이 적절히 판매되지 않고 원본 매도가 계속되는 문제도 포함된다. 상점 경로가 바뀔 수 있어 고정 세계의 순수 효율 차이로도 읽지 않는다.

## 출생 위치 원인 계측

같은 수정 probe에 HIRE 직후 좌표 기록만 추가해 다시 실행했다. 전체 필드 사건·최종 현금·씨앗 대체·끝 위치 불일치 목록이 직전 probe와 동일했다.

263회 새 일손 출생 중18회가 원본 좌표와 달랐다. 첫 차이는 d11 h1(step265)의 actor6–10이다. 원래 움직이던 일꾼 경로를 바꾸면 상점 HIRE 시점의 창고 주변 점유가 달라져, 뒤에 고용되는 일손이 다른 위치에서 나온다. 이후 d23·d25·d26·d29에도 차이가 발생했다.

따라서 **구간 시작/끝 위치만 고정하면 중간 고용도 보존된다는 가정은 틀렸다.** c334의 새 일손 번호 충돌과는 다른, 기존 HIRE 출생 위치 의존성이다. 수정 방법은 고용 시점을 구간 경계로 넣어 점유를 보존하거나, 바뀐 출생 위치를 공동 모델과 미래 경로에 다시 전파하는 것이다. 위치 오류가 있는 상태에서 시비 실패 전체를 비료 부족 탓으로 돌리지 않는다.
