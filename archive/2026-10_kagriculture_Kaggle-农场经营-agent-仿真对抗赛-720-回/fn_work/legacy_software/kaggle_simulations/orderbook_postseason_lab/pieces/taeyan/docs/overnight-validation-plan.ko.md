# 수면·외출 중 5~6시간 검증 리그 계획

2026-09-13 사용자 요청으로 기록한 설계안. **전용 실행기 미구현·미실행 상태**다.
경기 구성은 최대 규모이며, 후보·상대의 적격성 및 실제 처리 속도에 따라 실행 전
확정한다. 기본 원칙은 [신에이전트 검증 기준](agent-validation-protocol.ko.md)을 따른다.
이 기록은 예약 실행, 자동 개발, 자동 제출을 설정하거나 승인한 것이 아니다.

## 목적과 후보

고정된 후보들의 선발과 새로운 조건에서의 확인에 집중한다. 실행 도중 코드를
수정하거나 합격 기준을 바꾸지 않는다. c117을 기준으로 c111·c115·c116 및 새 후보를
포함한 최대 6개를 준비하되, 사전 검사 미통과 후보는 제외한다. 목록은 아직 미확정이다.
기존 강자 전부를 매번 투입하기보다 서로 다른 장점을 가진 후보를 보존한다.

## 최대 경기 구성

| 단계 | 산식 | 경기 수 |
|---|---|---:|
| 기존 후보 직접 대결 | 6개 후보의 15개 조합 × 새 시드 48개 × 양쪽 좌석 | 1,440 |
| 다양한 상대 평가 | 후보 6개 × 상대 8개 × 같은 시드 48개 × 양쪽 좌석 | 4,608 |
| 약점 공격 평가 | 후보 6개 × 공격자 3개 × 시드 32개 × 양쪽 좌석 | 1,152 |
| 최종 확인: 공통 상대 | c117 및 선발 후보 최대 2개 × 별도 상대 8개 × 새 시드 48개 × 양쪽 좌석 | 2,304 |
| 최종 확인: 직접 대결 | 최종 3개 후보의 3개 조합 × 최종 확인 시드 48개 × 양쪽 좌석 | 288 |
| 상위 1~3위 기록 진단 | 각 12개 리플레이 × c117·대표 후보 × 진단 방식 2개 | 144 |
| **합계** | **반응형 9,792경기 + 기록 진단 144개** | **9,936** |

기록 진단은 상점 고정/상점 자연 생성 두 방식으로 분리하고, 모두 상대 행동은
기록 재생임을 명시한다. 원래 경기 재현 실행, 사전 검사 및 속도 측정 비용은 표의
9,936개 비교에 포함되지 않는다. 실제 반응형 상위권 승률로 환산하지 않는다.

상대 8개의 강도·행동 다양성을 먼저 확인한다. 기존 외부 패널처럼 대부분 전승하는
상대를 채워 경기 수만 늘리지 않는다. 같은 구현 계열의 파생형은 독립 계열로 세지
않는다. 최종 확인 상대는 개발 중 후보 선택에 사용하지 않은 별도 패널로 고정한다.
약점 공격용 조건과 최종 확인 조건의 중복을 막고, 과거 관측·예약 시드와도 대조한다.

## 시간 예산 근거

완료된 `state/agent_experiments/generalization_tournament_20260913/runs/`의
3,360개 `matches.jsonl` 기록을 읽어 계산한 값:

- 경기당 평균 `seconds`: 6.2786초, 중앙값 5.746초.
- 90백분위 8.258초, 95백분위 10.578초, 최대 19.729초.
- 10,000경기를 4개 작업으로 병렬 실행하는 단순 산술은 약 4.36시간이다.

이 값은 전체 실행기의 실측 처리량이 아니다. 프로세스 시작, 기록·집계, 리플레이
원본 재현, 상대 복잡도, 병렬 부하 비용이 추가된다. 5~6시간은 목표이며 완료 보장이
아니다. 실행 초반 대표적인 후보·상대 조합의 벽시계 처리량을 측정해 예상 시간을
갱신한다. 4개 작업을 기본으로 하고 병렬 수는 자원과 처리량 검증 후 결정한다.

시간을 채우려고 약한 상대와 반복 대전하거나 최종 확인 조건을 추가로 소비하지 않는다.
시간 부족을 이유로 최종 확인 표본 수나 통과 기준을 결과에 맞추어 줄이지 않는다.

## 무인 실행기 구현 요구사항

1. 시작 전에 소스·상대·시드·실행기·엔진 해시, 단계별 예산, 선발·탈락·판단 유보
   기준을 고정한다. 기존 실행과 중복 여부, 디스크 여유, 패키지·로더 검사를 확인한다.
2. 후보들을 번갈아 평가하고, 시드·좌석·공통 상대 묶음을 우선 완성한다. 시간 제한이
   특정 후보만 유리하게 남기지 않도록 배정 순서를 사전 고정한다.
3. 선발은 사전 정의한 승점 개선·유형별 퇴보 한도·안정성 기준으로 최대 2개를 고른다.
   선발 기준의 수치와 동률 처리 방식은 아직 미정이며 구현 전에 확정해야 한다.
   합격 후보가 없으면 최종 확인을 억지로 진행하지 않는다.
4. 5시간 30분부터 새 작업 배정을 멈추고 실행 중인 경기를 제한 시간 내 마무리한다.
   집계 여유를 남겨 6시간 내 종료를 목표로 한다. 단계 전환 때도 남은 예산을 확인하고,
   완주하기 어려운 최종 확인은 시작을 미루거나 미완료 상태로 명확히 남긴다.
5. 경기별 기록을 원자적으로 저장하고 같은 명령으로 재개할 수 있게 한다. 완료 경기는
   중복 실행하지 않는다. 오류·시간 초과 원본을 보존하고 실패를 지운 뒤 성공할 때까지
   재시도하지 않는다. 반복 실패 시 중단 조건과 인프라 재시도 규칙을 사전 정의한다.
6. 정책·엔진·실행기 해시 변경은 재개를 거부한다. 기존 부모와 제출 파일, 진행 중 실험을
   보존한다. 중단 이후 잠금 해제는 실제 프로세스 종료를 확인한 뒤 수행한다.
7. 실행 중에만 절전을 방지하고 종료 시 해제한다. 성공·실패·시간 제한 종료를 구분해
   데스크톱 알림과 소리를 낸다. 사용자 실행 명령 하나로 시작할 수 있도록 준비한다.
8. 시간 제한으로 일부만 끝났으면 `paused_budget` 또는 동등한 상태와 재개 명령을 남긴다.
   단순히 정상 종료 코드가 나왔다는 이유로 전체 검증을 완료·합격 처리하지 않는다.

## 다음 날 받을 보고서

- 계획·완료·무효·미실행 경기 수, 실제 실행 시간, 중단 이유와 재개 방법.
- 기준 c117 대비 후보별 직접 대결과 공통 상대 승점 차이.
- 상대 계열·좌석별 개선과 퇴보, 최악 조건과 초반 붕괴 원인.
- 새로운 최종 확인 조건에서 우위가 유지되는지, 불확실성과 독립 시드 수.
- 실행 오류·시간 초과·내부 예외·후보 기능 활성 빈도.
- 상위 1~3위 기록 진단을 별도 표로 제시하고 실제 Kaggle 대전과 구분.
- 승격 검토 후보, 추가 확인 후보, 보완 후보와 판단 이유.

후보 선발 결과가 자동 Kaggle 제출을 의미하지 않는다. 첫 실행의 범위는 고정된
후보의 검증과 보고서 생성이며, 다음 개발 방향은 결과를 읽은 후 결정한다.

## 구현 전 남은 일

새 시드·별도 상대 패널 고정, 시간 제한·배정·재개·실패 처리 실행기 구현과 사용자
사전 검사가 필요하다. 현재 실행 가능한 야간 전용 명령은 아직 없다.
