# 신에이전트 검증 리그 운영 기준

2026-09-13 사용자 합의. 이후 Kaggriculture 후보 개발·검증의 기본 운영 기준이다.
목표는 기존 강자를 이기는 능력, 다양한 상대에 대한 일반화, 실패 조건을 함께
확인하는 것이다. 이 문서는 운영 계약이며 모든 항목이 현재 실행기에 구현됐다는
뜻은 아니다. 실행 전 계획과 실행기의 지원 범위를 대조한다.

## 1. 네 가지 평가군

| 평가군 | 구성 | 용도와 해석 |
|---|---|---|
| 고정 기준군 | c117을 핵심으로 c111·c110 등 과거 강자, 서로 다른 장점의 후보 | 실행 가능한 원본으로 반응형 직접 대결. 기존 대비 개선을 측정한다. |
| 다양한 강자군 | 생산 품목·확장·노동·판매 방식이 다른 실행 가능한 정책 | 공통 상대 평가로 특정 계열에만 유리해지는지 확인한다. |
| 약점 공격군 | 조기 가격 하락, 동일 상품 집중 생산, 빠른 확장 등 가설별 공격자 | 실패 조건 발견용. 합성 공격자 성적이 일반 상대 성적을 압도하지 않도록 별도로 보고한다. |
| 상위권 관측군 | 평가 시작 시점 1~3위의 합법적으로 확보한 코드·공개 리플레이·실제 Kaggle 대전 | 상대 코드가 있으면 반응형 대결. 리플레이 진단과 실제 대전은 별도 증거로 보존한다. |

- 상대를 많이 복제하는 대신 강도와 행동의 다양성을 확보한다. 바이트가 동일한
  상대는 중복 제거하고, 같은 스케줄러의 파생형은 독립 구현 계열로 세지 않는다.
- 평균 성적은 낮더라도 현재 기준 모델의 패배 상대를 잘 이기는 후보를 보존한다.
  이런 후보는 비교 상대의 다양성과 다음 개선 방향에 유용하다.
- c117은 현재 핵심 비교 기준이자 제출 후보이지, 새로운 홀드아웃으로 일반화가
  확정된 최종 챔피언이라는 뜻은 아니다. 기준 변경은 증거와 날짜를 기록한다.

## 2. 개발 전 평가 계약 고정

후보 결과를 보기 전에 다음을 계획 파일에 기록한다.

- 가설, 불변 부모 및 후보 소스 SHA-256, 상대별 소스·계열·선정 이유.
- 상위 1~3위 조회 시각, 팀 ID, 평가에 대응하는 제출 ID, 코드 확보 여부.
  실험 도중 순위가 바뀌어도 상대를 교체하지 않는다. 다음 평가판에서 갱신한다.
- 엔진·실행기 버전과 해시, 실행 제한, 관측 정보 경계, 사용 가능한 자원.
- 개발/후보 선택/최종 확인 시드, 별도 확인 상대군, 좌석 구성과 경기 수.
- 직접 대결과 공통 상대 평가의 주 지표, 상대 유형별 가중치, 허용 퇴보 폭,
  통과·탈락·판단 유보 기준, 확대 검사와 중단 조건.
- 실행 오류·불완전 경기 처리, 재시도 조건, 예상 비용, 결과·로그 저장 위치.

서로 다른 승격 기준을 사후에 골라 유리한 결과만 채택하지 않는다. 앞서 제안한
직접 대결 승점률 70%와 신뢰구간 하한 50% 초과는 예시이며, 모든 상대에게 적용할
확정 기준이 아니다. 가까운 파생 모델 간 무승부와 표본 수를 고려해 실험 전에
구체적인 기준을 정한다. 결과 확인 후 기준을 낮추면 새 실험으로 기록한다.

## 3. 단계별 비용 제한

1. **빠른 탈락 검사:** 소규모 개발 조건에서 실행 오류, 극초반 붕괴, 명백한 퇴보를
   찾는다. 여기서 좋은 결과가 나왔다는 이유만으로 승격하지 않는다.
2. **공통 조건 비교:** 후보와 기준 모델을 같은 상대·시드·양쪽 좌석에서 비교하고,
   기존 강자와의 직접 대결도 실시한다. 상대 계열별 성적과 약점 공격 결과를 분리한다.
3. **최종 확인:** 후보를 고정한 후 남겨둔 새로운 시드와 별도 상대군을 사용한다.
   결과를 읽고 수정하면 해당 조건은 개발에 관측된 조건이다. 다음 최종 확인에는
   새로운 조건을 사용한다. 표본 부족·오류는 합격 대신 판단 유보로 남긴다.

약점 공격자를 만들고 보완한 후보는 다른 상대와 새로운 시드에서도 재검증한다.
그 공격자 하나를 이기는 것으로 보완 완료를 선언하지 않는다. 정책은 정상 관측만
사용하며 상대 이름·제출 ID·시드·미래 상점·비공개 재고를 의사결정 입력으로 쓰지 않는다.

## 4. 공통 보고 지표와 해석

- 공식 승패가 주 지표다. 승점률은 `(승 + 0.5 × 무승부) / 경기 수`로 표기한다.
  순수 승률과 혼용하지 않는다. 자기 현금과 최종 현금 차이는 원인 분석용 보조 지표다.
- 기존 강자별 직접 대결, 공통 상대별 기준 대비 승점 차이, 계열별 균형 성적,
  좌석별 성적, 하위 조건의 성적과 최악 손실을 함께 보고한다.
- 후보-기준의 승→패와 패→승, 초반 현금·생산 붕괴, 실행 오류·시간 초과를 확인한다.
  실패 경기를 조용히 제외하지 않고 원인과 처리 방침을 남긴다.
- 같은 시드의 양쪽 좌석·여러 상대 경기를 독립 표본처럼 부풀리지 않는다.
  불확실성은 시드 묶음 단위로 평가하고 독립 시드 수를 명시한다. 전승·전무승부 등
  퇴화된 표본에서 단순 부트스트랩의 0폭 구간을 확실성의 증거로 제시하지 않는다.
- 같은 시드라도 정책 행동에 따라 공식 엔진의 상점 경로가 달라질 수 있다.
  정상 반응형 평가는 이 동작을 유지한다. 상점 강제 고정 결과와 합산하지 않는다.
- 평균 현금 차이가 조금 줄었다는 이유만으로 자동 탈락시키지 않는다. 승점 개선,
  사전 정의한 퇴보 한도, 꼬리 손실을 함께 판단한다.

## 5. 상위권 리플레이와 실제 대전의 경계

상대 코드가 없으면 그 상대의 정확한 반응형 대전을 로컬에서 재현할 수 없다.
공개 행동 기록을 재생한 상대는 후보가 시장·농장 상태를 바꾸어도 새 결정을 못 한다.
따라서 리플레이를 이겼다는 이유로 승격하거나 실제 상위권 상대 승률을 주장하지 않는다.

- 원래 두 행동 기록을 재실행해 원래 보상과 상점 경로가 재현되는지 먼저 확인한다.
- 상점 고정/상점 자연 생성 진단을 따로 보고한다. 둘 다 상대 행동은 고정이다.
- 최신 경기 등 표본 선정 규칙을 결과 확인 전에 정하고 관측 이력을 기록한다.
- Kaggle에서 실제 맞붙은 경기는 양쪽 제출 ID·날짜·좌석·표본 수를 보존한다.
  서로 다른 상대와 시기의 전적이나 초기 평점을 단순 비교해 개선을 확정하지 않는다.

## 6. 현재 출발점과 다음 우선순위

완료된 `generalization_tournament_20260913`은 8개 발견용 시드의 3,360경기다.
c117은 후보 간 148승 0패 28무, 일반 외부 128승, 진단 외부 64승이었다.
c111 직접 대결은 16승, c115·c116에는 각각 2승 14무였다. 이는 기준 후보 선정
근거이며 새로운 조건에서의 우위 확정은 아니다.

대부분 후보가 일반 외부 128경기 전승이라 해당 상대군의 구분력이 낮다.
단순 경기 수 확대보다 c117에도 실패를 유발할 수 있는 강하고 다양한 반응형 상대
확보를 우선한다. 이때 합성 공격자 하나만 공략하는 방향으로 전체 목표를 바꾸지 않는다.

## 7. 실행·기록 원칙

최신 사용자 변경(2026-09-13): 아래 사용자 실행 방식은 현재 중단한다. Codex가
검증을 직접 실행하고 명령어를 사용자에게 주지 않는다. 총4~5 시뮬레이션 워커와
긴 확인 간격을 사용하며, 검증된 개선안의 제출까지 명시적으로 승인받았다.
승격·새 조건 확인·제출 해시 대조 기준은 유지한다.

- 현재 사용자 지시에 따라 로컬 테스트·시뮬레이션은 사용자에게 명령어를 제공한다.
  성공·실패 데스크톱 알림과 소리를 포함하고, 완료 보고 후 저장 결과를 분석한다.
- 사용자는 PowerShell 창 최대3개에서 동시 검증할 수 있다. 독립 검증이 있으면
  나눠 실행할 명령을 제안하되, 총 워커 부하와 출력·잠금·의존성 충돌을 확인한다.
  모든 작업에 각각 최대 워커를 배정하거나 의존 단계들을 동시에 실행하지 않는다.
- 기존 부모·제출 파일·진행 중 실험은 보존한다. 해시가 바뀌면 새 출력 디렉터리를
  쓰고, 중복 실행 방지·중단 후 재개·최종 완료 판별을 준비한다.
- 비교표, 경기별 원본, 실행 제한 위반, 관측된 시드 목록, 최종 결정 이유를 보존한다.
- 승격 판단과 제출 실행은 구분한다. 사용자가 중간 제출을 명시적으로 선택한 경우
  검증 한계를 기록하되, 미실행 홀드아웃을 통과했다고 바꾸어 쓰지 않는다.
- 이 문서를 기록했다고 기존 실행기에 자동 적용되는 것은 아니다. 다음 평가 계획을
  만들 때 각 항목의 구현·미지원 상태를 확인하고 필요한 실행기 변경을 별도로 수행한다.

실행기와 기록 진단의 기술 설명은 [simulation-league.md](simulation-league.md),
가장 최근 상태와 사용자 실행 명령은 [HANDOFF.md](../HANDOFF.md)를 참고한다.

수면·외출 중 장시간 실행의 구체적인 구성안은
[5~6시간 야간 검증 리그 계획](overnight-validation-plan.ko.md)에 기록한다.
해당 계획은 전용 실행기 구현 전 설계이며, 실행 예약이나 자동 제출 설정이 아니다.
