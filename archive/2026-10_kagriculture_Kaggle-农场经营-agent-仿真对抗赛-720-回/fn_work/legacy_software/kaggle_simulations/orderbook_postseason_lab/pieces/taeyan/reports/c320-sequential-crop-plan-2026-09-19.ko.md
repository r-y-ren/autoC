# c320 — 토마토 종료 후 당근 순차 재배

판정: **전체 정책 기각, c312 v9/4 기준선 유지.** 후속 재배 부품은 실재하는 작은 개선이지만, 선행 토마토 전환의 손실을 만회하지 못했다. 독립 confirm/final과 제출로 진행하지 않는다. 보호 blind 7240–7255 미사용.

## 기존 시도와 달라진 점

c313은 토마토 수명을 끝까지 수확했고, c317/c319는 KEEP·2칸·전체 작물 전환을 비교했다. 토마토 생산 종료 후 다른 작물을 심는 선택지는 없었다. c146/c305/c306은 기존 밀 재배를 당근으로 대체했으며, 이번에는 토마토 종료로 생기는 구간을 재사용했다. base19 재파종/LWE의 노동·타일 비용 실패도 선행으로 확인했다.

기존 c313 단일 타일 엔진 도구를 확장했다. 앞서 확인한 12경기·156레인의 52개 서로 다른 방문 일정에서 토마토64u를 보존하고 당근 최대33u를 추가할 수 있었다. 한 타일당 추가 당근 씨앗1개를 가정한 미래 방문 상한이다. 실제 구현한 현재 상태 규칙을 같은 방문 일정에 적용하면 당근18–22u였다. 이 계산은 자금·씨앗 도착·변경 후 실제 방문·운반·판매를 보장하지 않는다.

구현은 자기 토마토가 생산을 끝낸 뒤 기존 정지 작업을 정리·파종·급수·수확으로 바꾼다. 이동·토지·고용을 추가하지 않는다. 실제 자기 씨앗 수 증가로 추가 구매를 확인한 뒤 한 번 파종을 시도한다. 일반 부모 작물을 덮지 않는다. 실패 파종 재시도는 구현하지 않았다. c305/c306의 기존 재고 매도 간섭을 피하려고 추가 당근 SELL 명령은 넣지 않고 부모 판매에 맡겼다.

선행 전환은 c177의 기존 조건(토마토 수요 상점2개 이상·가격60 이상·현금2500 이상·8/10칸)을 그대로 사용했다. 이번 결과에 맞춘 새 임계값은 없다. c179 후속 투자 호환과 c313 수확 수정도 유지했다.

## 실제 원장 확인

동결 시드 순서에서 처음 실제 추가 씨앗 구매가 확인된 시드1745960649를 사용했다. 수익이나 승패로 고르지 않고 네 상대·양좌석·세 정책24개를 전부 재현했다. 각 native 경기 자신의 상점 경로를 고정해 양측 전체 행동·현금24/24 동일, 원장 잔차0, 해시 PASS를 확인했다. 공통 상점으로 바꾼 추가 성능 실험이 아니다.

이 한 세계8조건에서 후속 재배 증분은 당근 실제 수확·매도 +16u, 당근 매출 +766.5, 당근 씨앗 비용 +160, 토마토 수확·매출 변화0, 고용·땅·전체 밀 구매 비용 변화0이었다. 달걀 수확·매출 −2u/−111.5 등 간섭도 남아 own +487.25, 상대 −112.75, 마진 +600, 승점0이었다. 달걀 손실의 세부 원인은 별도 확정하지 않았다.

판독 오류도 보존했다. 첫 원장 실행은24작업을 제출했고1개 결과를 저장한 뒤, 메모리의 정수 day 키를 JSON 문자열 키로 읽는 `KeyError`가 발생했다. 원본 실행기·로그를 보존하고 별도 v2 판독에서 저장1개를 재사용, 누락23개를 다시 실행했다. 최종24개 검증 완료. 이를 후보 전략 실패나 독립24개 추가 세계로 세지 않는다.

## 결론과 다음 방향

후속 작물 재배라는 새로운 실행 가능한 선택지는 얻었지만 좋은 전체 생산 정책은 얻지 못했다. 같은 자료에서 전환 조건·면적·수확 규칙을 재튜닝하지 않는다. 독립 확인 예산은 쓰지 않는다.

다음 우선순위는 기존 작물 전환의 임계값 탐색보다 **생산 계획 자체를 자동 생성·평가할 행동 공간**이다. c309의 기존8경로 선택, c317의 세 작물 선택, 기존 optimizer의 제한된 노브와 구별해야 한다. 기존 실행 계획을 대조로 보존하면서 타일의 연속 재배·방문 일정·씨앗/고용/운반 비용을 함께 표현할 수 있는지 먼저 확인한다. 이 방향이 더 강하다는 증거는 아직 없다.
