# c309 — 실행 경로 묶음의 학습 기반 선택

2026-09-19, Codex. 작업 원장: HANDOFF.md. 목표는 최종 승점 개선이며, 이 보고서는 상위권 달성 증거를 미리 주장하지 않는다.

## 재시도 근거와 행동 공간

가장 가까운 시도는 H05/o209의 동물 구매 슬롯별 선택, c171의 V42 생산 경로 도입 및 상점별 고정 매핑, base19 Macro Oracle이다. o209의 희소 표·일부 음수 결과는 해당 슬롯/부모/표본의 결과이며, 당시 요청 라벨의 시간 정렬과 실행 결과 캐시·통계에도 재사용 전 보완 사항이 있었다. c171은 경로 변경이 승률과 손실 꼬리에 서로 다른 영향을 줄 수 있음을 보였다. Macro Oracle의 작은 노브 분기는 전체 계획 공간의 상한이 아니다.

이번에는 이미 실행되는 V49의 전체 생산 경로를 선택한다. 소스 해시 `7d5777978465a2dd18b85fbef9d354d3cc9e008c279630e7655e5a517058b960`. 내부41경로 중40개는 d6 이전144명령이 완전히 같고, route1만 예외다. 선택 대상은 KEEP와100/101/109/110/114/123/12이다. 결과를 보기 전에 d6–d12 요청 포트폴리오의 차이로 고정했다. 구매·배치·작물·노동·판매의 묶음을 보존하고 원래 d6 분기점만 바꾼다. d27 정리 경로와 나머지 공개 정책의 반응층을 유지한다.

정적 명령 접두 일치는 충분한 실행 가능성 증명이 아니다. 실제 분기 관측과 행동 접두 해시도 경기별 모든 선택지에서 동일해야 한다. 다른 계획의 실제 현금 부족/실패 주문/손실은 평가 결과에 포함한다. 현재 시장과 맞지 않는 계획도 제거하지 않고 결과로 판정한다.

## 기존 도구 재사용과 수정 범위

- `macro_compile.py`의 강제 행동→롤아웃→조건부 선택 틀은 재사용한다. 그 파일의 오래된 상대 목록·파일 존재만의 캐시·행 단위 bootstrap·결과 코드 미확인은 그대로 쓰지 않는다.
- 경기 실행·격리·캐시·해시·양측 오류 검증은 기존 `validation_v2.py`와 `championship_league.py`를 그대로 쓴다. 엔진/동결 러너를 수정하지 않는다.
- 새 코드 `state/c309/build_plan_bank.py`는 기존 소스를 묶고 d6 경로 선택·관측 telemetry를 붙인다. 새 시뮬레이터나 크롤러를 만들지 않았다.
- `state/c309/learn_plan_choice.py`는 canonical 결과에서 학습 데이터와 시드 제외 예측을 만든다. sklearn의 기존 RandomForest를 쓰며 새 RL 엔진은 구현하지 않는다.

## 실행 QA

첫 생성본은 기존 `agent` 이름을 재정의하면서 namespace 삽입 순서가 바뀌지 않아, 마지막 callable을 선택하는 로더가 `_c309_router`를 실행했다. step0 TypeError로 canonical QA가 중단했다. 이 결과는 전략 실패로 세지 않는다. 실패 소스·설정·캠페인 `c309_plan_choice_qa`는 보존했다.

v2는 최종 `agent` 정의 직전에 기존 키를 삭제해 진입점을 마지막으로 등록한다. 다른 전략 수정은 없다. KEEP와 V49 원본을7000/7001, V49/o239 양좌석8조건에서 비교(총16게임): 양측 전체 행동 해시·보상·상점8/8 동일, 분기 호출1회. `state/c309/v2/qa_identity.json`.

## 결과 전에 고정한 학습/판정

학습용 native 대전:8개 새 시드 × 실행 상대4소스(V49/o239/K0006/router v5) × 양좌석 × 정책8개 =512게임. 기본12워커. 네 소스가 서로 독립적인 네 계보라고 주장하지 않는다. 시드는 기존 validation 설정과 보호7240–7255의 중복을 피했으며 모든 과거 원시 산출물까지 전수 중복 검사한 것은 아니다.

정책 입력은 d6 결정 직전의 상점 수·현재 가격/시장 재고·양측 공개 농장 상태·자기 창고/씨앗이다. seed/episode/팀명/제출ID/미래상점/결과는 입력하지 않는다. 이전 행동의 요청을 잘못된 미래 label로 쓰지 않고, 각 계획을 실제 실행한 최종 승점/마진을 target으로 쓴다. 경기별 관측, 라벨, 실행물 신원을 보존한다.

LeaveOneGroupOut으로 해당 시드의 모든 상대·좌석을 함께 제외한8fold를 만든다. RandomForestRegressor64개, max_depth4, min_samples_leaf4, max_features1.0, random_state309, n_jobs12를 고정한다. 승점 차와 마진 차는 별도의 모델로 학습해 현금 스케일이 승점 학습을 압도하지 않게 한다. 예상 승점 차가 양수인 계획 중 승점 우선·마진 보조로 선택하고, 양수가 없으면 KEEP다. 결과 후 파라미터를 조정하지 않는다.

대조는 KEEP, 각 fold의 학습 부분에서만 고른 고정 최선 계획, 모든 결과를 본 사후 oracle이다. oracle은 행동 공간 진단일 뿐 실행 정책 성능이 아니다. 신뢰구간은 시드 평균을 재표집한 탐색용95% 구간으로 보고한다. 8개 시드의 내부 교차검증을 독립 확인/승격으로 부르지 않는다.

사전 진행 조건은 OOF 학습 선택의 승점 차와 마진 차가 모두 양수인 것. 그때만 별도 고정 정책을 만들어 독립 native 대전에 진입한다. 그렇지 않으면 같은 데이터에서 튜닝을 반복하지 않고 증거 부족으로 기록한다. confirm/final은 이번 학습 캠페인에서 자동 실행하지 않는다. 더 나아갈 때는 학습된 정책 파일·상대·새 시드·기준을 별도 동결한다.
