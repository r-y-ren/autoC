# flow203 — the E3 FAIL-branch arm, staged 2026-09-11T14:47Z, NOT launched

`flow203` exists so that the moment the E3 one-step sweep at candidate B's centre returns **FAIL**
(consensus §48: every σ×P cell κ ≤ 0.015 and net gain ≤ 0; "mixed" counts as FAIL for the knobs),
the campaign has a field change to start instead of another knob. If E3 **PASSES**, flow203 is void:
§48's PASS branch continues the ES from B at the winning σ/P, which is flow196's recipe with one
number changed.

Everything else — σ 0.02, lr 0.003, pop 512, Adam, `--weight-decay 1e-4`, `--margin-scale 3000`,

**Primary (the objective).** The rung weights become a function of B's own measured per-rung outcome:
lost ×2, barely-won (< +1,500 coins) ×1.5, won ×1.0, 15 % per-rung mass cap. W_lost is the one field
on which this estimator has been shown to resolve a gradient at a centre where the current field is
flat (κ 0.024-0.037 vs 0.003-0.005 at flow172_g1000, `2026-09-11-lost-board-objective.md` §3) — which
is exactly what an E3 FAIL declares about B. It is mild by design: the ×4 version (38 % → 79 % of the
mass on lost boards) lost held-out on both seeds (−956 / −786 coins, −6.7 / −10.0 pts) and that doc's
closing instruction is "keep it mild (≤ ×2) and judge it by the held-out line only".

**Secondary (the field).** flow203 keeps flow199's ten LOSS10 tapes at w4 rather than flow196's
narrower field, because a loss-weighted objective cannot address boards absent from the field and
LOSS10 is the only class where B's losses are measured in the real engine (the 2175-2381 band clone
that beats B 19/20 at any seed, `2026-09-11-loss10-anatomy.md`). flow199 has been staged since 10:05Z
and never launched, so flow203 **replaces** it in the queue rather than competing for a GPU.

## The weight file is a measurement, and it gates the arm

The W_lost vector is read off B's centre play, so it cannot be written in advance. `flow203_precheck.sh`
runs the existing rig (`~/popcurve/B/lostw.py`, pointed at `~/launch_flow199.sh` = B's seat and the 157
rungs, with `--lost-mult 2.0 --barely-mult 1.5 --won-mult 1.0 --cap 0.15` and **fresh** rollout/grad
directories, since `~/popcurve/B/rollouts` holds flow172_g1000's centre-specific rollouts) and does two
jobs in one ~20-minute GPU pass: it writes `~/stage_hr/flow203_wlost.txt` right after the centre play,
then re-runs the lost-board one-step test **at B**.

**Stop rule, fixed in advance (flow192's own staging conditions, which it failed at g1000):** launch
flow203 only if, on the held-out block (LIVE-C 43-72, both seats), net `+d` gain > 0 on obj **and**
margin **and** ≥ 12/16 randoms are beaten, on both eps seeds. A negative pre-check at B closes the
W_lost field at both centres — then the FAIL branch has no objective change left and the queue falls
back to flow202 (fresh top-tier rungs), not to another knob.

The launcher enforces this operationally: it exits 2 unless `~/stage_hr/flow203_wlost.txt` exists,
carries exactly 157 `--rung-weight` tokens, and names every rung in
`~/stage_hr/flow203_rungs.txt`. Both failure paths were smoke-tested locally (a good file passes, a
156-token file exits 2).
