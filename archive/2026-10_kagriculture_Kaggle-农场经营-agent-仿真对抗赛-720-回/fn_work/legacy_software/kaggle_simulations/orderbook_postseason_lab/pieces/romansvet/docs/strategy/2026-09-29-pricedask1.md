# PRICEDASK1 — the crop count priced like the seeds: the next tile does not pay (NONE)

2026-09-29 19:08-21:00Z, branch `pricedask1_0929` (worktree `kagg3_wt_pricedask1`, base 8d670dad = vrp20_pfsoff), dir `S/pricedask1`.
The user asked at 19:02Z: "why we do not use same arithmetic?" PFS sets the daily crop count as a learned fraction
(`n_dev = _qfloor(dev_frac * n_free)`). The seeds are priced in coins, but the count never asks whether the next tile pays.
This stream built that question into the planner and judged it closed-loop.

**Answer:** yes, it can be asked with the same arithmetic, and the answer is "no".
- At PFS's own d10-27 crew (11-14 hands), the next hand's Fibonacci wage is 9-38 coins per unit-turn.
- At that price a tile's lifetime tending costs about 800 coins. The best crop earns about 140 coins.
- The rule adds 0.05-0.24 plantings per game. It is inert on every read of the named grid.
- Pricing labour only when turns run short (the 0x diagnostic) adds 25 plantings per game.
  - Those plantings take the tiles the planner's own 2-4-day wheat relay would replant.
  - That arm loses on V56: m40 -1,324 (t -3.56), v21 -1,560 (t -2.77).

## 1. The switch (`PRICED_ASK_ON`, default OFF = byte-identical)

Placement and timing:
- The rule runs in `_plan_and_stats` after pass A and the crew argmax, for days `PRICED_ASK_D0..D1` = 10..27.
- It walks the free crop-capable tiles that the head's own plantings leave.
  - The order is pass A's `slot_rank` past the builds and the funded head plantings. That is the existing near-first `compact` order.
- It adds one planting per tile while the next tile's value is > 0, capped at `PRICED_ASK_CAP` per dawn.
- Pass B then derives the extended day through the unchanged pipeline: seed grant, placement, admission, route_vrp.

Unchanged: the animal ask, the head's own crop split and the tile order.

The value of a tile:

    value(tile k, crop c) = rev - seed - labour - capacity
    rev      = _stream_rev: VAL.new_plant_units(c, day) units sold j blocks down the SALES-WINDOW curve
               (PJ.inv_at_day + our own _pipeline_units; j = today's funded plantings of c + the extension's).
               This is the seed grant's arithmetic without grow_mult. It is opponent-free: this tree has no RIVALSUPPLY2.
    seed     = spec.CROP_SEED_COST[c]                       (10 / 20 / 50 / 100 for wheat / carrot / tomato / strawberry)
    labour   = TURNS[c] x (1 + 2 x DIST_SHED[k]) unit-turns x coin-per-turn
               TURNS = WATER+FERTILIZE turns per planting (2026-09-19-turncost.md):
                       wheat 4.64, carrot 3.63, tomato 9.56, strawberry 11.35, melon 8.73
               (melon is excluded: it is the brain's saturated market, absorb/DRAIN_CLIP)
    coin-per-turn (PRICED_ASK_CPT = None -> derived each dawn) = HIRE_COST[h*] / (route_turns(h*) - EST_LEAD)
               = the next hand's fib wage / its productive turns, x PRICED_ASK_CPT_MULT (the grid knob)
    capacity = projected spare turns.
               today:  yesterday's routed usable idle (PASS at h>=3, recorded by runtime.pa_idle after route_vrp.apply).
               day t:  today's idle - (1 + EST_MOVES) x (modelled crop ops on t - today's).
                       The model is TILELEASE1's calendar walk over every standing tile, today's plantings, and replants at the ask ratio.
               The tile needs (1 + EST_MOVES) x its ops: PLANT + WATER (+ DIG) today, then its water/harvest calendar.
               Each short day charges one more hand's fib wage and credits that hand's 16-17 turns.
               A hand charged for today is really hired (h* + bump, affordable only).
               The idle-covered part of today's need is credited to pass B's admission, as in TILELEASE1's admission-credit mode.

**What the arithmetic says.**
- At PFS's own crew the marginal unit-turn is expensive (fib wage 144-610 per day for the next hand).
- An extra tile's tending costs 5-10x its revenue.
- The turns the winners use are idle turns of hands already paid for.
  - Pricing those at zero (D0) exposes the real constraint: the **tile**, not the ask.
  - PFS leaves a median of 3 free tiles past its own ask. Any extension has to take a tile from the base's relay.

**The one thing to do next.** The lever the winners pull is **turnover per tile-day** (IDLE2: wheat +7.3k, carrot +3.2k of harvest value, 234 vs 152 plantings).
- Price every planting against the tile-days it blocks.
- The charge is the base relay's measured revenue per tile-day on that tile: about 35 coins/tile-day for 4 wheat units at 35 over a 4-day cycle.
- Judge it as a crop-choice rule on the base's own tiles, not as an extension of the count.
