## The rule (docs/strategy/2026-09-09-kaggle-calibration.md s4)

Paired vs the LIVE theta, on the 53 boards left after excluding the two non-byte-exact tapes
`107088554` / `107095149` (still played, still in the headline win/flip/drop counts):

1. d-margin > 0,
2. seat-grouped |t| >= 2 (both seats of a board averaged into ONE observation first —
   a row-level t is inflated ~1.4x, `2026-09-09-lottery-audit.md` s4.1),
3. at least 28 boards positive.

Unlike LOSS12/LOSS20 this set is **two-sided**: the base wins 19 of the 55 held-out boards
(34.5 % of the 110 games), so a candidate can drop games as well as flip them, and both are
reported.

Output (one greppable verdict line, then detail):

```

```

`LIVE55: no csv <path>` when the LIVE62 leg has not run for that name; `LIVE55: no base` when the
base csv is missing. Headline `d-margin Z` is over all 110 games; the rule's margin is `mean M`.

## Judge wiring

`S/judge/judge.sh` (backup `judge.sh.bak_live55`) prints the LIVE55 block after the LEG20 /
LOSS12 lines, guarded by `[ -s $S/lossflip/${name}_live62.csv ]` (else `LIVE55: no csv`), and the
drawn legs now run when

```
(LEG20 d-margin > 0 AND H_dm >= 0)  OR  LIVE55 RULE PASS
```

so a live-passing candidate still gets the drawn legs — as the **veto**, never as the promotion
evidence (calibration doc s4a: the drawn legs' one historical promotion, flow102_g280, cost 265
rating points). Every prior output line and file name is unchanged; the new gate status is a
separate `gate2:` line. Because judge.sh does not itself play the LIVE62 leg, run
`S/live62/run.sh <name> <wt>` (or its chain) before judge.sh, or LIVE55 reads "no csv".
