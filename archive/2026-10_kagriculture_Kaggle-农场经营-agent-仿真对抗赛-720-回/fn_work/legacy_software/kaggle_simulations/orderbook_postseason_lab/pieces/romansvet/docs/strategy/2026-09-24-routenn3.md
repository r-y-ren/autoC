## 1. Design
* Every unit (farmer + hires) each hour d10-28, **h1-23** (h0 stays the plan: h0 occupancy decides where the h1 hires
  spawn, engine `_spawn_hand`). A unit is in PLAN mode (replays its planned ops) or QUEUE mode (executes its plan
  STOPS = non-move ops, by Manhattan navigation, each stop at its planned hour, never earlier; late stops on arrival;
  invalid-when-due stops dropped).
* Decision points: PLAN unit at every leg start / waiting turn; QUEUE unit whenever it has no target (~2,700 decisions/game,
  ~400 of them h1-2). Pointer rows (K1 = 32): row 0 = KEEP (continue plan / next queued stop), up to 20 planner stops of
  ANY unit (steal = another unit's stop, own = re-order), + unplanned legal jobs (route_nn candidates, no seed buys).
  Taking a stop moves chooser + owner to QUEUE. Hire count = planner (no hire head).
* Network = ROUTENN1 pointer (F_T 30, F_H 10, 21k params), init keep bias 8.5 → **greedy init == OFF byte-exact**
  (V56 boards 100/101: 115,947 / 77,110 both arms), sampled init ≈ 12-14 changes/game.
* Queue-executor fidelity (every unit forced into QUEUE, no changes) — needed so a deviation is not charged for the
  executor: first version −4.5..−6k/board; fixed (planned-hour timing, engine move clipping, PLACE rows from the
  overflow guards, planned-spawn tracking for hires) → boards 100-103: +791 / −51 / −918 / −122 (mean −75).

## 5. Why ~0: per-hour accounting (`account.py`, `account_init_s.txt`, `account_rn3_c_20s.txt`)
Each change's coin = its day's (ON−OFF) coin day reward split over that day's changes; per game, V56 dev100:

| hour bucket / kind | init sampled: changes/g, coin/change | u20 sampled: changes/g, coin/change |
|---|---|---|
| h1-2 steal (another unit's planned stop) | 1.5, −90 | 1.3, −152 |
| h1-2 extra (unplanned water/care) | 0.8, −788 | 0.8, −314 |
| h3-20 steal | 6.2, −260 | 5.8, −252 |
| h3-20 extra | 3.7, −311 | 3.0, −302 |
| h3-20 own re-order | 1.3, +113 | 1.1, −72 |
| h21-23 (all) | 0.3, ±noise | 0.3, −190..−431 |
OLS Δpurse on per-board counts: steal −144..−180/change, extra −32..−357, own re-order −67..+43.
What the changes are: steals = HARVEST / COLLECT_FERT / CARE / WATER of another hand's route (the planner already
schedules those tasks inside the day; moving one only swaps who does it and delays both routes: the owner and the
chooser leave their planned timing → late harvests miss the planner's sale rows, the market book shifts and the V56
rival gains +1.3..+2.5k/game); extras = watering / fertilising / caring tiles the planner deliberately left (no coin, or
negative through labour taken from planned stops); h1-2 moves have almost nothing to earn — the h0-2 hands are waiting for
the seed / wheat / animal pickups landed by the h0-h1 market rows, and a hand that walks away arrives late for them.
**No class of re-routing earns coin**: the planner's per-day task list is already a near-optimal assignment for the
tasks it chose; the only positive cell (own re-order of FEED/CARE/FERT, +300..+550 on n ≤ 13) is noise-sized.
Together with ROUTENN1/2 (idle units) and CREW24/CREWRELAY1: crew ROUTING is closed from both ends — idle units have no
coin, busy units' tasks are already placed. The remaining lever is WHAT work exists (tasks the planner does not create:
plantings / animals / sale timing), i.e. the plan-level decision, not the dispatcher.
