## 2. Port: C kernels via ctypes (`src/kagg3/agent/route_vrp_c.c` -> `route_vrp_c.so`)
- Why not numba: it is not in our venv, and the Kaggle image's numba is broken against its NumPy 2.4
  (`docs/FORUM_RESEARCH.md` #735332: `ImportError: Numba needs NumPy 2.0 or less`); its first compile also costs seconds
  on the 1 s clock. numpy: the loops are sequential walks over 5-25 stops with data-dependent branches (RRSPEED1 §1), no
  vector shape. So (c), but as a plain C library loaded by `ctypes`, not a CPython extension: built with `-nostdlib`
  (no libc, `readelf -d`: 0 NEEDED), one 18 KB binary for any CPython on linux x86-64; `-ffp-contract=off`, no fast-math,
  so every float op (route_key = elapsed + 0.01·moves, insertion deltas, the 1e-9 margins) is the same IEEE double op in
  the same order as the Python path. `S/routerjit1/build.sh` rebuilds it byte-identically (md5 checked).
- Kernels: `rv_eval` (route_eval + _sim + _best_acc), `rv_best_insert` (candidate list, top-K by (det, uid, pos),
  exact evals, full-scan fallback), `rv_insert_seq` (the sequential best-insert loops of ruin_recreate, mode2_ii and
  construct in ONE call, with the unit route costs for `total()`), `rv_two_opt` (improve's first-improvement 2-opt).
  The numpy rng stream, the ruin set, sort keys with `rng.random()` and all acceptance logic stay in Python, so the
  RR random stream is untouched.
- Glue (`route_vrp.py`): `Solver._jctx` packs the stops into an int32 table (rebuilt when fill/sliver append/pop stops);
  anything not representable (non-int fields, > 64 items/units, routes >= 250) falls back to the Python code for that
  call. `JIT_ON` (module) and `plan.ROUTE_VRP_JIT_ON` (switch-string kill switch) select the path; the library load is
  checked by a self-test at import (0.2 ms: dlopen + one eval; no compile, nothing on d0). If the package directory
  refuses dlopen it retries from a temp copy; if that fails too the Python path runs AND `DEEP_NEEDS_JIT` makes
  `_rr_knobs` return the shipped (30, 8, off) search, so a missing library can never put the deep search on the Python
  clock.
