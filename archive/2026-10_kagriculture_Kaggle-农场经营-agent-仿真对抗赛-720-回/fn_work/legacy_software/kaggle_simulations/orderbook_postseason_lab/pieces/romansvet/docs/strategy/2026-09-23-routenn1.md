## 1. MDP (reduced version, section 5 of the brief) — what the policy owns
The day plan (`build_day`: ask, market rows, land, animals, `_derive` admission, `_routes` chains) stays the planner's. The policy owns the crew:
* **HIRE** (dawn, d10-28): delta ∈ {−2..+2} on the hire argmax (after head_940's d_hire), re-clipped to the affordable prefix by
  `_residual_hire` BEFORE `n_hire` sizes the bill/routes, so plan and crew never desync. One decision per dawn.
* **DISPATCH** (every turn d10-28): a unit whose remaining plan suffix is all PASS is FREE. For each free unit the policy points at one of
  ≤ 31 engine-legal candidates built from the observation, or PASS: WATER (any unwatered plant, optional water included),
  HARVEST (plant/animal with yield, shed room checked), FEED (wheat in bag), CARE, COLLECT_FERTILIZER, FERTILIZE (fert in bag),
  PLANT c (spare seed; ≤ 3 nearest vacant tiles per crop), BUY_PLANT c (DSMLOGIC1: one seed bought THIS turn in the crew's own 1-unit
  BUY_SEED row, only when the plan has no purchase left today, cash ≥ 1,500 floor). The chosen task is a job: Manhattan steps then the
  command; the unit is then free again, so chaining on the current tile (harvest→plant→water, feed→care→collect) is the distance-0 row.
  Tiles still owned by any cached route are excluded (never steal planned work); planned units are never touched.
* NOT owned yet (left): h0-2 waiting units (plan suffix not PASS: the h1 seed-row pickup) and the chain order of routed units — i.e. the
  full `_routes` replacement. The h0-2 idle (207/game) needs the plan's BUY row moved or the pickup re-routed, which desyncs cached chains.

## 2. Network (`route_nn.py`, numpy at run time, the same `forward` under JAX in the trainer) — 26,631 params
glob (16: day, hour, purses, margin, hands, planted/vacant/unwatered/ripe tiles, shed, seeds, free units, animals) → tanh 64 = g;
hand (8: hour, turns left, bag wheat/fert/total, farmer flag, x, y) ⊕ g → tanh 64 = h; task row (26: type one-hot 9, distance, (d+1)/turns
left, crop one-hot, price, yield frac, age frac, dry streak, fert active, bonus window, d29, at-tile, fed) → tanh 64 = t_k;
pointer logit_k = v·relu(W[t_k, h, t_k⊙h]) + PASS bias (init +3); hire head relu(W[g, onehot planner count]) → 5 (init delta 0);
value = own MLP on glob. Init policy ≈ OFF (PASS / delta 0 most likely, sampled). **Inference** (`timing.txt`, 13 free units, full farm,
host load 22): 7.2 ms median / 10.8 ms max per turn; hire head 0.09 ms → far inside the 1 s act limit.

## 3. Reward (USER 09-23: dense per-day route quality, NO win/margin term; wins are gate-only) — `route_nn.observe`, our farm only
Per day, from consecutive observations: + harvested units × that turn's price (crop and animal product); + 0.5 × full-yield value at
planting (tile credit), − that credit if the tile dies dry or rots away unharvested (pre-existing tiles 0.5 × value on a dry death);
+ 0.25 × value for a WATER on a tile one dry day from death; − ripe yield decaying unharvested (0.5 × price per unit); − the day's
Fibonacci hire bill; − 0.5 × value of yield left on the field at d29 h23. No op counts. Day d's reward goes to the last decision taken on or
before d; γ = 1, GAE λ 0.95 on V(glob); return = sum of day rewards (coins / 1,000). Not covered: shed-overflow destruction
(OVERFLOW_GUARD_V3 owns it), h23 harvests (seen only after the eod drop).
