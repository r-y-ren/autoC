### Trainer change (train3x.py vs train3h.py)
- Unit loss: `lt = CE(token)`, `lq = CE(qty) * QTOK[tok]` are multiplied row-wise by `w = WUT[day, teacher token]` before the unchanged normalisation (`lt.mean() + lq.sum() / #qty rows`).
- Market loss: the per-(step, key) CE `[512, 21]` is multiplied by `w = WMA[day, key] * (WMN[day, key] if teacher target > 0 else 1)` before the unchanged `.mean() * 3`. `nz: true` (default, used by every market rule here) weights only cells where the teacher ordered, i.e. it is a recall weight, like the label-keyed unit weights.
- Weights are looked up on the host in `batch()` (2,048 + 512 x 21 floats per step, negligible) and passed into the jitted step. Overlapping rules multiply. With all weights 1 the loss is bit-identical to train3h.py (verified below).
- Host RAM: MT int8, PV int16, PR int8 (cast per batch; lossless) as in train3w.py. Minibatch sampling: identical rng calls to train3h.py when BC_WEIGHTS is unset, so a train3x run and a train3h run with the same init/data/steps/W210 draw the same minibatches. **r5a4 is therefore the exact control for the first weighted rung** (warm r5a3, same 4,143 train eps, 30k, W210=3).
