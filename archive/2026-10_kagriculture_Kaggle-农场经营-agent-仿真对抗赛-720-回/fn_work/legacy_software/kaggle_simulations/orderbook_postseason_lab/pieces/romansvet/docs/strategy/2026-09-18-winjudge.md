# WINJUDGE — the POOLED278 gate for a WINRATE checkpoint (2026-09-18)

Branch `winjudge` off master `e505d59` (= the live package, sub 56329775, ESR + gene
`WIDE_PICK_ON`, layout **7,659**). No `src/` change: this box is a judge, not an arm.

## Usage

    [WORKERS=4] [BASE=wp_on] [ASSERT=<label>] [SW_EXTRA=,NAME=VAL] \
        bash S/winjudge/judge.sh <label> <theta.npy>

`<theta.npy>` may be 7,659 or **any shorter prefix layout** — the shipped 6,789
`submission/theta.npy` included. `S/winjudge/pad_theta.py` writes the padded copy next to
the results and **REFUSES** a longer one (a longer theta is a different layout, not an
older one). A zero gene column is the switch's *shipped default* (`plan._sw`), so the
padded shipped theta is the shipped package, `WIDE_PICK_ON` and all. This is the fix for
`S/judgekit/judge.sh` refusing a 6,789 theta while expecting 7,428.

Legs: **BAND250** (250 held-out band-clone tapes, rung 2900, CARROTFLAT3 recipe) +
**TOPLEG2 + TOPLEG3** (60 leaderboard top-10 tapes), of which the 28 at tape retention
≥ 0.85 are **ENGINE28** — the same opponents, seeds, ids order and town registries as
WIDEJUDGE's banked rows, so the pairing is CRN. [ESJUDGE10: a 22-game gate cannot resolve
what the pool measures at se ≈ 100 — every checkpoint is judged on all 278 boards.]

Switch string = the ESR string the whole ledger is paired on. Every **gene**-switch name
in it is set to its shipped default, which by `plan._sw`'s precedence is *not* an override,
so the candidate's **gene block rules** — how a WINRATE checkpoint is meant to be flown.
`SW_EXTRA` appends (`,WIDE_PICK_ON=False` flies the pre-WIDE_PICK package).

Outputs: `S/lossflip/<label>_{band250,topleg2,topleg3}.csv` (repo convention, JUDGEKIT can
read them) and `S/winjudge/<label>/{band250.csv,engine28.csv,summary.txt,theta7659.npy}`.
`report.py` prints per-leg and POOLED Δmargin / se / t, Δours (t), Δtheirs (t), boards
better/worse, **board WIN RATE base→cand** (win = margin > 0 on the board), the **paired
win-flip counts** `+up/-down` and their **exact two-sided sign-test p** — the ladder is
Bradley-Terry over board wins, so coins that land on boards we already win buy nothing.

## Runtime

Two full judges run concurrently, `WORKERS=4` each on 12 cores: BAND250 **32 min**,
TOPLEG2 **3.5 min**, TOPLEG3 **4 min** — **~40 min per label**, ~27 min for BAND250 alone
when nothing else runs. Smoke (4 ids per leg via `IDS_BAND250` / `IDS_TOPLEG2` /
`IDS_TOPLEG3`) is 85 s end to end and also reproduces `wp_on` to the coin.
