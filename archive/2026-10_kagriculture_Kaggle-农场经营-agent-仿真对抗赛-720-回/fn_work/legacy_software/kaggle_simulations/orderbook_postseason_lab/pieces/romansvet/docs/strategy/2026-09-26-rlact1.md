## Action space (S/actionrl/head.py layout "act" = WIDE 20 slots + 2; 22 slots, 134 logits)
- slot 20 `relay_n` ∈ {0..6}: wheat relay plantings today on free OWNED tiles (Q4 too once bought), through the
  MIX_RELAY count/seed/placement path under `plan.RL_ACT_ON`. Capped by the free tiles the day's funded ask leaves and by
  the seed the purse left after the grant. Plantings enter the mandatory tier at full units × quote. Hands are sized from
  the relay's own ops (ceil(ops/12), ≤ 3) on top of h_star, and the day is re-derived at the bigger bill. Admission order
  (only when a relay task exists): mandatory work + ALL herd-tile tasks, then the relay, then the planner's crop tail.
  Days ≥ 1 while wheat still matures by pay_day.
- slot 21 `q4_buy` ∈ {0,1}: buy the fourth quadrant today if `money ≥ land_gap` (nquad == 3 only). Its tiles become the
  planner's (and the relay's) free tiles.
- A zero action equals the OFF plan byte for byte. MIX_RELAY_WATER/FERT masks stay MIX-only (they cannot tell relay tiles
  apart), so RL relay wheat is watered and fertilised by the planner's own rules. All other switches are unchanged.

## Features (+4 after the 64 + 19 rival columns, `plan._residual_features` under RL_ACT_ON; order-free)
crew slack = our PASS unit-turns yesterday / 100; relay tiles free = max(empty owned − today's ask, 0) / 40; wheat
quote / 100; rival wheat units sold yesterday / 50. The two history columns come from `plan.RL_ACT_OBS`, which the
rollout sets per seat (like Q4_VRP_RELEASE). `ppo_fast.play` counts PASS ops of live units from the executed host rows
and takes the rival's wheat from the `sold_ni` ledger (KAGG3_SIM_SALES=1).
SHIP CAVEAT: the file agent leaves RL_ACT_OBS at (0, 0). Before any package, `agent/runtime` must fill it: own PASS
count, and rival wheat sold = Δmkt_inv[wheat] + town consumption − our sales.

## Trainer (S/rlfast1/ppo_fast.py, `--run run3*` or `--act`; run2 behaviour unchanged)
Same checklist as RLFAST2: ±1 win + 0.3 tanh(margin/6000) with a running std; K=8 CRN groups, 40 groups = 320
games/update (≥ 256). Opponents: 40 % CURRENT checkpoint mirrored, 20 % PFSP league, 30 % V56+V57, 10 % head_940
anchors. Fixed-reference gates every 10 updates; rollback only on collapse. Warm start = head_940 → `widen.widen`
(wide + 19 rival rows) → `widen.widen_act`: 4 zero w1 rows, zero w3 columns, no-op bias `--act-zb` 3.0 on both new
slots, so the greedy action is 0 on the new slots and unchanged on the old ones (test). Sampled at T=1 this gives relay > 0
on ~23 % of dawns and q4_buy on ~5 %. The teacher KL(head_940‖head) covers the 20 old slots only. Checkpoints go to
run3/heads/head_ra1_u{N}.npz (the save asserts ≠ head_940/theta7659, and md5ok() runs every gate). Action use is logged to run3/act.tsv.
