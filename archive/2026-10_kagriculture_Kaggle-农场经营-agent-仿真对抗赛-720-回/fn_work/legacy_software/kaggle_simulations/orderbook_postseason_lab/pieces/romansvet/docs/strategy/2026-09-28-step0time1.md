# STEP0TIME1 — V56 preload off the first turn (2026-09-28)

**Verdict.** Lazy V56 = the existing knob `KERNEL2_PRELOAD=False`. It is already implemented on melonhybrid4 (runtime.py `_kernel2`), so no new code was needed. With it off, step 0 execs nothing V56 and PFS plays only its real h0. On a fired seat the kernel is exec'd once at step 1. On V seats and ZERO-excluded seats it is never loaded. Results are coin-exact on all 3 seats.

The fresh-process step-0 call drops from 365 to 218 ms, which equals live vrp12 (225 ms). The fired step 1 rises from 4 to 239 ms, below the 600 ms bar, so the background-thread alternative is not needed.

In-game step 0 on this loaded box is dominated by PFS h0 and by load, not by V56. Live vrp12 itself took 1.30 s on the MELON seat.

- **Import.** Every package pays the import (~0.36-0.44 s), and it is not charged to step 0. kaggle_environments builds the file agent in `Agent.__init__`, and `duration` times only `self.agent(*args)`.
- **PFS h0.** Profiled on lazy (res/h0prof_lazy.txt), the step-0 call spends 0.26 s of 0.315 s in `build_day`. Its largest parts are `_derive`, `_routes` and route_vrp `solve_plan` at 0.05 s. The residual-head lazy load costs 0.02 s.
- **V56 preload.** It adds about 150 ms (≈ `kernel2_load`), which the lazy switch removes from step 0.
- **In-game gap (unexplained).** In-game step 0 on the MELON seat took 1.3-1.7 s for all 3 arms, against 0.22 s in a fresh process. This was not investigated. Hypotheses: pinned-town obs, box load, or a gen-2 GC over the engine's tape-laden heap. The gap is common to live vrp12, so it is not a KERNEL2 cost.

## Step 1 on a fired seat
- Lazy step 1 = kernel exec + inherit turn = 239 ms under load, below the ~600 ms bar.
- Alternative, not implemented: preload the kernel in a background thread at step 0 after the h0 plan is returned. This is only worth building if fired step 1 is seen above ~600 ms live. Under CPython the GIL makes the thread steal from the step-0/1 turns anyway, and the compile is mostly GIL-held.

## Proofs
- MELON seat, lazy (real h0 rival cash 2438): 108,827/73,010 = S/melonhybrid4 A4 row. The default reproduces it too.
- V seat, lazy: 151,182/135,790 = pfv1.
- ZERO 488 seat, lazy: 108,943/102,663 = pfv1.
- Why coin-exact holds by construction: the V56 source imports stdlib only, uses a private `random.Random`, and mutates no shared module. It is exec'd into a fresh namespace per game, so exec time does not change its first call.
