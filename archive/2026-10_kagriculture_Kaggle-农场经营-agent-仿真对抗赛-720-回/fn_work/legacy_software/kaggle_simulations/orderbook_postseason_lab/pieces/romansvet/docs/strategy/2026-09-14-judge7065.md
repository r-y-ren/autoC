    for item in sys.argv[1].split(","):
        name, eq, val = item.partition("=")
        mod = P                                   # kagg3.core.plan

            mod, name = B, name[6:]               # kagg3.core.brain

…**before** `runpy.run_path("scripts/eval_vs_baselines.py")`, i.e. before the seat imports the sim.

    OPEN_PUMP_ON=True,TAIL_FILL_ON=True,BANK_BEFORE_LOT_ON=True,HIRE_ROW_ON=True,brain.MELON_GENE_ON=True,brain.CROP_DAY_ON=True

branch is not entered.) Padding it would also work and is byte-equal — but it is an extra artifact
to md5, so don't.

`judge_candidate.sh` preflights (tree is 7,065; theta width ∈ {6789, 7020, 7065}), runs TOPB2 →
LIVEC-H30 → LIVEC-H30B → LIVE62 → LOSS10 → NEXT30 → NEXTHIGH → TOPB3R9 with the six-item switch
string from the judge-7065 tree, lists the csvs written
(`S/lossflip/{name}_topb2.csv`, `_livech.csv`, `_livech2.csv`, `_live62.csv`, `_loss10.csv`,
`nextband_{name}.csv`, `nexthigh_{name}.csv`, `topb3r9_{name}.csv` — the families' own historical
names, unchanged), then prints, in order:

1. **TOPB3R9 retention** (`S/topb3/retention.py`) — a candidate that hires differently can desync a
   tape B kept; a board under 0.85 **under the candidate** is not readable.
2. **The §115 table** (`S/judge7065/pooled_band.py`) — pooled band = LIVEC-H30 + LIVEC-H30B +
   NEXT30 as ONE 90-board leg, base = candidate B, statistic = `S/bank/paired.stats` with the two
   seats averaged into one observation. Prints `PROMOTE` only on pooled Δ ≥ **+450** and board-t ≥
   **+2.00** and net flips ≥ 0 and no band leg worse than −400 and no veto; TOPB2 (Δ ≤ −1,400 & t ≤
   −2, or net ≤ −4) and LIVE62 (Δ ≤ −700 & t ≤ −2, or net ≤ −8) are the vetoes; LOSS10 / NEXTHIGH /
   TOPB3R9 print as informational. Nothing is re-implemented — it only pools the three band legs'
   rows before calling the judge's own `stats()`, which no existing tool does.
3. **`S/autojudge/audit_candidate.py`** — the canonical per-family coverage/void audit, unchanged.

**Dry-run receipt** (`--only TOPB3R9,LOSS10` on the B pad7065 theta, label `B7065dry`): both csvs

## 6. Caveats

* **`audit_candidate.py` has 7 families, not 8.** TOPB3R9 is registered in
  `S/unitorder/judge_family_inventory_20260913.json` (`family_count: 8`) but the two one-line
  additions in `2026-09-14-topb3r9-leg.md` §5 to `audit_candidate.py` and `S/autojudge/watch.sh`
  are **not applied** — those files are the lead's. `judge_candidate.sh` and `pooled_band.py`
  therefore run and score TOPB3R9 themselves; `audit_candidate.py` simply will not list it.
* **The watcher is not wired to this tree.** `S/autojudge/watch.sh` still passes its own worktree
  and 4-item switch string, so an automatic judge of a flow215 record would run the 6,789 tree and
  fail (or silently drop `cd`). Judge flow214/flow215 candidates with `judge_candidate.sh` by hand
  until the lead re-points the watcher.
* Leaving the two genes ON for a **6,789** theta is harmless and proved identical (§3/§4), so one
  switch string can be used for B and for both arms — no per-arm branching.
* `S/judge7065/decode_receipt.py` mutates `brain.MELON_GENE_ON` / `CROP_DAY_ON` at module level and
  restores both to False before exiting; it is a standalone script, never imported by a leg.
