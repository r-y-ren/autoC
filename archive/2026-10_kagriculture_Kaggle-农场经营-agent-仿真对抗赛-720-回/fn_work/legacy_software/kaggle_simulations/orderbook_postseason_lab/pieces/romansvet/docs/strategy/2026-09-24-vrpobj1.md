## 2. Fix (src/kagg3/agent/route_vrp.py)
- `route_key(elapsed, moves) = elapsed + MOVE_W x moves`, MOVE_W = 0.01: THE route objective. Used by route_eval's
  pickup placement (was finish + moves), `Solver.rcost`, `Solver.cost`, hence best_insert / improve / 2-opt /
  ruin-recreate acceptance and the checkpoint key. A route makes <= 24 moves, so 0.01 x moves < 1 h: the scalar is
  lexicographic (elapsed, then moves) per route (and for crew sums while the move delta < 100). finish vs elapsed differ by
  the route's constant start hour, so the order is the same.
- `sol_key(dropped, route_cost) = (-sum fib(dropped hands), route_cost)`: explicit lexicographic solution objective,
  crew bill first (the day's hires are fixed, so the bill kept = total - fib of the dropped hands). Lexicographic, not a
  weighted scalar: a hand costs fib(n) coins/day while route cost is hours; no exchange rate is defined and the
  shipped mode ii never trades a hire for hours (ROUTEOPT1). Stored on every checkpoint (`_ckpt`), and `apply()` now tries
  checkpoints on a timeout in sol_key order (ties: latest first) instead of latest first.
- Variant rejected: MOVE_W = 1/1024 (exact floats, lexicographic for any crew sum). It re-breaks float-noise ties
  (`c < best[0]` in best_insert has no epsilon; 0.01 sums carry 1e-16 noise), changing the plan on 364/600 dawns (hires
  -59/+63, moves +291, makespan +275 unit-h) and every dev board: net flips -1, dmargin +7 t 0.07 = noise. Kept 0.01.
