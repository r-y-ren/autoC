# The `_MAP` pin in the engine-side tape seat: instrumented, fixed, and it closes the sim/engine gap

Settles the open item at the end of `docs/strategy/2026-09-14-sim-hire-sticky.md` §6 ("UNVERIFIED by direct
instrumentation of the engine's `_MAP`: deduced ... A short probe on 108741964 would settle it") and the
"108741964 DSM 0.75 -> 0.40, unexplained" line in `docs/strategy/2026-09-14-tape-hire-fix.md` §4.
Built and measured 2026-09-14 09:35-10:00Z.

**VERDICT: CONFIRMED, with one correction to the mechanism. Instrumented over all 36 TOPB3 games (25,884 agent
steps): exactly the three DSM boards the sim disagreed with -- 108741964, 108784054, 108813021, both seats, 6 of
36 games -- carry a `_MAP` pin, and every other board carries none. Each of the six is 1 pin, on day 1, held for
23 turns (23 turn x pinned-slot PASSes), and 37 acting source orders per game executed by the WRONG live hand.
The correction: `starved` turns -- a pin coexisting with an unassigned source hand -- is 0 of 25,884. The source
roster growing past the pinned hand never leaves a source hand unclaimed; the growth is absorbed by a NEWER live
slot, so the damage is a one-place SHIFT of the whole assignment (source order k executed by live hand k+1), not
a dropped order. Fixed behind `--hire-sticky-remap` / `TAPE_MAP_FIX=1`, default OFF and 36/36 games
coin-identical with it off (and 60/60 on NEXTHIGH). With it on, 108741964 returns 0.40 -> 0.75 and the whole engine leg becomes
IDENTICAL to the sim's hire-sticky ledger on 18/18 boards (it was 15/18): retention to 2 d.p. and B's margin to
the coin on every board. It does NOT make more boards readable -- 10 -> 9 at >= 0.85, because two of the three
"gains" hire-sticky showed on DSM were this artefact -- and Majkel1337 never pins at all, so B vs the rank-1 file
is still n=1.**

## 1. What the instrument shows

`TAPE_MAP_DEBUG=<dir>` (off unless set; pure observation, changes no action) makes the emitted package write one
jsonl row per step: `step, day, hour, live, src, src_next, pinned, owed, owed_acting, extra, claimed, map`.
`S/topb3/tapemap/mapstats.py` folds those into per-day counts. The whole leg, hire-sticky ON, repair OFF
(`S/topb3/tapemap/dbg_all_off/`, `mapstats_all_off.txt`):

| boards | games | pins | PASS turn x slot | starved turns | misaddressed acting orders |
|---|---|---:|---:|---:|---:|
| 108741964, 108784054, 108813021 (DSM) | 6 | 1 each | 23 each | **0** | 37 each |
| the other 15 boards | 30 | 0 | 0 | 0 | 0 |

The mechanism, read off 108741964 seat 1 day 1 (`S/topb3/tapemap/dbg_off/`):

```
d h  live src src_next owed extra   map
1 0     0    0        2    0     0  []
1 1     3    2        2    0     0  [0, 1, -1]      <== 3 of the tape's recorded HIREs land; the SOURCE had 2
1 2     3    2        3    0     0  [0, 1, -1]
1 3     4    3        3    0     0  [0, 1, -1, 2]   <== source hand 2 goes to the NEW live slot 3, not to slot 2
1 7     5    4        4    0     0  [0, 1, -1, 2, 3]
...                                                    held to hour 23; wiped at the day boundary
```

* The pin is created because the live seat **out-hires its source**: the recordings over-submit HIREs and let the
  fib cost ladder (`kaggriculture.py:702`) stop them, so a seat that is richer at that instant lands more of the
  same row. `_settle` had no source hand for the surplus slot and wrote `-1`.
* It is never repaired because `_settle` only ever **appends**: when the source roster grows, the new source index
  is taken by the slot that grew with it. `owed` stays empty (hence `starved` 0), the `-1` stays where it is, and
  every later source order is one live hand to the right of where the frozen tape would have put it.
* Cost per game: one hand idles for 23 turns **and** 37 acting orders (MOVE/HARVEST/... at specific tiles) are
  executed by a hand standing somewhere else. The frozen tape idles a hand too -- the LAST one -- so the crew size
  is the same; what changes is which worker does which job.
* So `2026-09-14-tape-hire-fix.md` §2's "`_MAP` provably reduces to the identity on every path the engine can
  produce" is **wrong**, as §6 of the sim doc deduced; but the counter-example is the day the seat out-hires the
  source, not the day the source's roster overtakes a pinned hand (which never happened in 25,884 steps).

## 2. The repair

`scripts/tape_opponent.py --hire-sticky-remap` bakes `_MAP_FIX_DEFAULT = True`; `TAPE_MAP_FIX=0/1` wins at run
time (no `KAGG3_` prefix -- `eval_vs_baselines._vendored_imports` clears that namespace for file agents). Default
**OFF**, and inert unless hire-sticky is on. In `_settle`, before the day's growth is distributed, a live slot
still holding `-1` claims the lowest unassigned source hand, lowest slot first. Two consequences:

1. the pin migrates to the NEWEST live hand -- which is the hand the frozen tape idles too -- so `_MAP` collapses
   back to the identity-plus-PASS-tail that `_align` already used. Instrumented: with the repair on the pin count
   and the 23 PASS turns are unchanged (the surplus hand still has no source hand) but **misaddressed acting
   orders go 37 -> 0** on all six games (`mapstats_all_fix.txt`);
2. a claimed hand is NOT queued as `owed`, so the deferred-hire re-issue never buys a hand the seat already has.

The re-issue itself (the measurable half of hire-sticky) is untouched.

## 6. What is still unreadable, and why

* **Majkel1337, 5 of 6 boards (0.28-0.45).** Not a `_MAP` problem: those boards record **zero** pins over both
  seats. The residual is the cash spiral named in the hire-fix doc §4 -- the re-issue can only buy a hand the seat
  can afford, and on 108795516 the seat is on 0 coins from day 7. A purse-side repair is UNVERIFIED and the one
  precedent (the 2026-09-11 `--sticky` arm carrying refused BUYs) made tapes weaker.
* **DSM 108751325 (0.39)** and **108741964 / 108784054 / 108813021 (0.75-0.78)**: same cash spiral, now without
  the artefact that was flattering two of them.
* TOPB3 is still not a promotion gate and B vs the rank-1 file is still n=1.

## 8. Next

The repair is a prerequisite, not a lever: it buys sim/engine agreement (18/18) and removes a false +0.09 on two
DSM boards. **The next experiment is the purse side** -- the five boards under 0.5 are all "the tape cannot afford
its own recorded row", and the instrument to answer it already exists: log `money` alongside `owed` and count the
turns where an owed hire is dropped for cash rather than for roster parity. If a cash repair is what makes
Majkel1337 readable, TOPB3 becomes a 6-board reading of B against the rank-1 file; if it is not, TOPB3 should be
cut to the 9 readable boards and quoted as such.
