## 2. Portability of `kagg3/agent/route_vrp_c.so`
- `file`: ELF 64-bit LSB shared object, x86-64, SYSV, not stripped. `readelf -d`: 6 entries (GNU_HASH, STRTAB, SYMTAB,
  STRSZ, SYMENT, NULL), **0 NEEDED**, no RPATH. `readelf -V`: no version information. `readelf -r`: no relocations.
  `nm -D`: 4 defined symbols (rv_eval, rv_best_insert, rv_insert_seq, rv_two_opt), **0 undefined**. GNU_STACK is RW
  (the stack is not executable).
- Build: gcc 11.4.0 (Ubuntu 22.04) `-O2 -shared -fPIC -nostdlib -fno-stack-protector -fno-builtin
  -fno-tree-loop-distribute-patterns -fno-semantic-interposition -ffp-contract=off -Wall`, default `-march=x86-64`
  (baseline SSE2). objdump shows 0 ymm/zmm instructions; `endbr64` is a NOP on CPUs without CET. A rebuild from the .c in
  a clean directory reproduces the packaged .so byte for byte (md5 f7b5941b). The packaged route_vrp.py, .so and .c
  equal the routerjit1 tree.
- Not our venv: `/usr/bin/python3` 3.10.12 under `env -i`, with numpy 2.2.6 from /usr/local/lib/python3.10/dist-packages
  and sys.path = extracted package only (`S/shipjit1/port.py`). `jit_live` True, `_rr_knobs(20)` = (150, 10, True). The
  10 fixture days (tests/data, converted to plain dicts) with deep knobs at SAFETY_S 1e9 give **10/10 identical** JIT vs
  Python, 8.3x CPU. The venv (3.11.15) also gives 10/10.
- Tarball: `kagg3/agent/route_vrp_c.so` is 18,136 bytes, mode 0644, uid 0. dlopen needs only read permission plus an
  exec-capable mount.
- Fallbacks, tested with system python3:
  - Package dir on a `noexec` tmpfs: `jit_live` True through the temp-dir copy (/tmp/rvjit*/route_vrp_c.so).
  - Package dir and TMPDIR both `noexec`: `jit_live` False, knobs (30, 8, False).
  - .so missing: False, (30, 8, False).
  - .so not an ELF, or a foreign library (libz) without the symbols: False, (30, 8, False).
  - Exception: a **truncated** ELF (first 4,000 bytes) crashes the process in dlopen (SIGBUS, rc 135). Python cannot
    catch this. It can only happen if the archive is corrupt, and a gzip CRC failure would stop the extraction first.
- Real engine, one game each way (extracted main.py vs reacting V56, LIVE250 board 0, live wall clock, load 18):
  - With the .so: **79,744 / 74,625**. This equals the ROUTERJIT1 smoke and the sim deep arm. The run used the
    package's own modules (route_vrp from ext/, jit True, knobs (150, 10, True), EMPTY_ROUTE_UNHIRE_ON True).
  - .so removed: **79,379 / 74,635**. This equals vrp7's smoke exactly. jit False, knobs (30, 8, False).
- Kaggle image evidence: public agent flexonafft "Adaptive Farm Intelligence" (kernel 132704576, public score 2,156)
  loads `agent.so` from its submission directory with `ctypes.CDLL`. Its g++ fallback also writes into that directory.
  So dlopen from the agent directory works on the Kaggle runtime.
- **Unverified:** we have no shell on the Kaggle image. Its glibc version does not matter, because the .so has no libc
  and no symbol versions. Its CPU architecture is not checked here; it is assumed to be x86-64 like all Kaggle CPU hosts.
  If the load failed, the package would play vrp7's router exactly, as the smoke game above shows.
