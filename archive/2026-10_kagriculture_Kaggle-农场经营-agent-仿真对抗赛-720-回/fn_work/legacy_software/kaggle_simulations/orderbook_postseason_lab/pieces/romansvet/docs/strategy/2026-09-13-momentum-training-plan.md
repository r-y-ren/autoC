# Momentum-only training integration plan

Status: **prospective; no training, transfer, or evaluation has run**. The frozen source boundary is `S/unitorder/momentum_stage_manifest_20260913.json` (SHA-256 `497a3e33f24a7d0b3172e30f8a2a663db6539e9f214c60359ddb030cd14625d4`).

The smallest independent experiment is two cold ES lineages using the staged trainer directly. Both load original B (`flow193_g100_hr.npy`, 6,789 float32 parameters), let the staged `policy.pad` append 66 zeroes, and set `train_only=mh,ms`. In the staged layout, `mh` is `[6789,6853)` and `ms` is `[6853,6855)`. The named mask and `live_mask` must agree exactly on those 66 coordinates. The trainer applies that mask to population noise, updates, and weight decay, so the old 6,789-coordinate prefix has a byte-exact preservation contract.

Everything else remains the Flow215 W00 training objective: the ordered 120 action tapes plus four scripted archetypes, population 4,096, sigma 0.01, SGD learning rate 0.00018, weight decay 4e-7, margin tape score with absolute-coin weight 0.6, ten generations, and the frozen stage's planner switches. Seed 311 is assigned to GPU 0 and seed 312 to GPU 1. They are separate lineages and outputs; their results are never pooled. Only each run's final centre (`theta.npy`, equal to the final state theta) is eligible for later review. Native “best” files and intermediate checkpoints are audit artifacts, not selection candidates.

`S/unitorder/momentum_train_prepare.py` is deliberately a preparation tool, not a launcher. It verifies the frozen 43-file source map, B bytes, ordered tape bytes, parameter layout, pad behavior, effective mask, switches, and unchanged objective fields, then writes seed-specific configs and a proposal receipt. This avoids dependencies on the seed-309/310 helpers, whose 6,789-parameter and 1,191-live-coordinate proofs do not apply here.

The standalone runner, protocol, qualification auditor, and saved training auditor are now staged for review. They have not run on a GPU. The protocol exposes separate `qualify` and `train` modes: both seed qualifications and their cross-seed audit must pass independent review before either train mode is invoked. The following fidelity gates still require execution evidence:

1. Construct the actual archived CLI trainer from each emitted config. Before and after installing B, capture theta, optimizer moments, optimizer counters, pool rung 0, RNG words/noise, config, and evaluator inputs. Require the installed theta prefix to equal B byte-for-byte, its tail to be 66 zero float32 values, moments/counters to be zero, and rung 0 to equal the installed centre.
2. Require perturbation and update masks to contain exactly indices 6789 through 6854. At generation 1 and generation 10, require theta, momentum, and variance outside those indices to remain byte-identical to initialization. A violation refuses the run.
3. Prove seeds 311 and 312 produce different initialization/evolution RNG evidence while source, B, objective, and ordered tapes remain identical. Seed identity alone is insufficient.
4. Bind helper, config, frozen source map, B, all 120 tapes, runtime/JAX/CUDA environment, device UUID, and raw progress before launch and rehash them at publication. Each process gets `timeout -k 10 10800`, an NVML 22,000 MiB ceiling on a 24 GB RTX 3090, flushed logs, atomic receipts, and process-group cleanup on error, timeout, or memory excess.
5. Require exactly ten completed generation rows and ten optimizer updates. Preserve native artifacts, logs, GPU telemetry, exit status, and cleanup evidence. Do not resume, transfer, promote, select a checkpoint, or start a replacement seed after seeing progress.

The two configs are not launch-ready until those runner/protocol gates and a zero-update actual-CLI initializer proof pass independently. The experiment measures whether the new history path can improve the existing training objective; it does not inherit the offline ridge result as a game-gain claim.

Staged implementation files are `S/unitorder/momentum_train.py`, `momentum_train_protocol.py`, `audit_momentum_qualifications.py`, `audit_momentum_train.py`, and `test_momentum_train.py`. The prospective 177-input launch manifest is `S/unitorder/momentum_train_manifest_20260913.json`. It is an input inventory for review; the eventual remote launch wrapper must pin its reviewed SHA rather than accepting an arbitrary replacement manifest.
