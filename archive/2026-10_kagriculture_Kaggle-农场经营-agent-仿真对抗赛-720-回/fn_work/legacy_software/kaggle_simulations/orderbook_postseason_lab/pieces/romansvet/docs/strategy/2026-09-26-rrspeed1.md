## 2. Exact speed-up (byte-identical) — measured 1.00x, reverted
Patch `S/rrspeed1/exact_speedup.patch` (not merged): flat per-stop tables, int tile-id distance table, candidates as
ints `det<<16|u<<8|pos` (same order as the tuples), cached per-route slot lists, and a prefix-resumed insertion evaluation
(cached prefix states per route and pickup variant; only j + suffix simulated). Exactness: 207,911 insertion evaluations
asserted equal to route_eval; recorded dawns base 10/10 and deep 10/10 byte-identical; 600 recorded dawns deep 600/600,
base 599/600 (dawn 269, d13: the difference is in the REPAIR_MS 100 ms wall-bounded repair, load-dependent in master too
— not re-verified).
| measure (600 dawns, remote, same load, concurrent) | master code | patch | speed-up |
|---|---|---|---|
| CPU s, base (30/8/off) | 75.8 | 75.8 | 1.00x |
| CPU s, deep (150/10/ON) | 256.4 | 256.1 | 1.00x |
| cProfile s, 30 deep dawns | 112.9 | 78.2 | 1.44x (profiler artefact: it charges per call, the patch removes 47.8 M abs() calls) |
Pure-Python micro-optimisation buys nothing un-profiled; the deep cell costs 3.4x the shipped CPU (p99 1.23 s vs 0.41 s at
SAFETY_S 1e9), so it needs >= 2x at the tail and there is no exact algorithmic cut (the RR rng stream depends on every
accept/reject, and a sound lower bound for pruning insertions does not exist once pickups move). Speed-only: NOT MET.

## Verdict — NEEDS_FIX (no package)
- Speed-only (the asked fix): 1.00x CPU with a byte-identical exact rewrite (600/600 deep dawns identical); the deep cell
  costs 3.4x shipped CPU and times out on 17-19 % of dawns even on an unloaded (CPU) clock. Not fixable by pure-Python speed.
- Clock-bounded `ROUTE_VRP_RR_WALL_S = 0.15` (LOAD-DEPENDENT, wall-clock branching on every dawn, against GOAL.md's
  "no wall-clock branching" contract beyond the safety deadline): timing bar met on the remote replay (p99 0.504 s, 0
  timeouts at load 9-10; p99 0.502 s, 0 timeouts on the CPU clock), but the only live-clock tapes read is net +1 with
  Δours -25 (t -0.3) at load ~33, i.e. no measurable gain, and only 234/600 dawns reach the full deep search.
- Switch stays OFF (None, byte-identical: all route_vrp tests pass). A fair re-read needs a quiet host (load <= 6) for
  the paired tapes leg; with the gain at best +1 flip / 50 boards, it is not worth a slot.
