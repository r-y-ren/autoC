# LIVEWATCH22 (LW22PREP): live watcher for the KERNEL2 v3 package vrp15_k2fire

2026-09-28 08:30Z. Built before the upload. Read-only: Kaggle ListEpisodes plus public replays. No upload, no src change.
Tooling: `S/livewatch22/` is a copy of the livewatch21 scripts plus `lw22.py`. It also reads `S/livewatch21/gz` as an extra read-only replay cache.

## Commands

After the upload, with the new submission id:

    python3 S/livewatch22/lw22.py <new_sub_id>                  # all listed games; paired read vs vrp12_pfs 56612145 over the same window
    python3 S/livewatch22/lw22.py <new_sub_id> --last 100 --nofetch   # re-read the cached list, newest 100 games only

Options: `--ref <sub>` sets the paired sub (default 56612145), `--workers N` sets the parse pool (default 2), and `--nofetch` reuses `api/eps_<sub>.json`.
Outputs: `S/livewatch22/lw22_<sub>.tsv` (one row per game, both subs) and `lw22_<sub>.txt` (the summary).

## What it reads per game (from the replay)
- `cash_h1` is the rival's money in our step-1 obs. The live replay exposes it directly (`steps[1][seat].observation.farms[1-seat].money`), and it is
  exactly the value `runtime._kernel2` latches on, so no re-simulation is needed. `listed` = cash in {26, 29, 2338, 2438}.
- `v56obs` marks an OBSERVED fire: our h1 market (replay `steps[2][seat].action`) has BUY_ANIMAL COW 2 + BUY_ANIMAL SHEEP 2 + HIRE, which is the
  V56 inherit row. `v56full` also requires SELL WHEAT 48 + BUY_SEED WHEAT 1 + all hands PASS, the exact row of the two
  offline v3 fired replays (S/v3branch1/gz/v3: 2438 highfrequencyf, 2338 yannikschiffne). Those replays also show 12 MELON tiles at d1 h0.
  PFS h1 never hires: on 133/133 live vrp12 games it is `SELL WHEAT 48, BUY_SEED WHEAT 11, CARROT 8, GOOSE 1, COW 4, SHEEP 1`.
- `h0pfs`: our h0 = farmer NORTH, market [BUY_PRODUCT WHEAT 53, 4x HIRE]. This must hold on every game.
- `pfsid` (unfired identity): h0pfs, the h1 market starts with SELL WHEAT 48, and there is no V56 signature. Full byte-identity needs a board replay (proven offline 781/781).
- Also recorded: rival d2 family (V/MELON/ZERO/OTHER), rival and our melon plantings d0-9, our MELON tiles at d1 h0, statuses, overage, all-PASS turns, result and margin.

## Summary blocks
GATE (listed vs observed fire share, per value W-L, fired-game detail), PFS IDENTITY, RESULTS for the sub and for vrp12_pfs over the same window
(fired/unfired W-L, family x listed, rating band x listed, health), EXPECTATION (GATETABLE2 faithful net flips per fired seat:
26 +3/6, 29 +2/8, 2338 +1/22, 2438 +5/30; band-276 rates in brackets), BAND-SEAT PAIRING, and VERDICT.
BAND-SEAT PAIRING lists every listed live game whose rival sub, or failing that the same team, has a BAND-276 tape, with v3 vs base judge rows
(S/v3branch1/res/runs/v3/band_on.csv vs S/bandbank2/res/pfs_band2.csv). `(=this ep)` marks a tape cut from that same live game.

**Integrity bar (decision brief §4).** All of these must hold:
- 0 errors or timeouts;
- h0 misses 0;
- fires off-list 0 and missed fires 0 (listed == v56obs on every game);
- the fire share should be close to the vrp12 would-fire share over the same window.

Only an integrity failure justifies undoing the upload.
