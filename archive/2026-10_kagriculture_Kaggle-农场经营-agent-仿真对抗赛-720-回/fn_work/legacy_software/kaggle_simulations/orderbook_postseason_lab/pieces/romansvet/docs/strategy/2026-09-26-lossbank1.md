## 4. Standing loop: `S/lossbank1/pull_losses.sh` (not scheduled)
- **Config.** `S/lossbank1/subs.txt` has one line per sub: `<sub> <family> <min_ep>`. It currently lists 56580780 (vrp8_jit, all losses) and 56572961 (vrp7, only losses after ep 113752862).
- **Running it.** Run by hand from the repo root: `bash S/lossbank1/pull_losses.sh`. With `SYNC=1` it also pushes the bank and feeds to the stages. Each run does:
  1. `S/livewatch17/api.py eps` fetches the episode list;
  2. `S/livewatch17/fetch.py` fetches the new loss replays;
  3. `mk_tapes.py` banks them (verified; idempotent via boards.json/banked.tsv);
  4. `mk_legs.py` regenerates `esw_legs.json`, `xr.json` and bed.txt.
- **Getting new items into the trainers.** They pick up new items only at a restart:
  - ESWORK1: `run_remote.sh addlegs` (only the new boards are computed), then `es`.
  - RLACT1: `--xr` is re-read at launch.
  - NVTHETA1: boards.json is re-read at launch.
