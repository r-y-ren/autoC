- **The clone package fits.** It is 14.25 MB against the 100 MB limit (the current package is 1.16 MB).

- **The hand-back at d18 happens under the clone body on 20/20 seats.**

## 1. Design and switch (`src/kagg3/core/plan.py`, `src/kagg3/agent/runtime.py`)
- **`KERNEL2_BODY = "v56"`** (default) or `"clone"`. The latch is unchanged (FIRE_CASH, step 1), and so are the dawn market-inventory record and `KERNEL2_HANDBACK_DAY` (18).
- **With `clone`, the fired seat's body is the clone from step 1.**
  - The clone is a policy on the observed farm. It plays the real step-1 observation of the farm PFS's real h0 built, which is the same take-over point as V56 INHERIT, but without the INHERIT rewrite (that rewrite exists only to show V56 its own h0).
  - It plays until the dawn of day 18, then PFS takes the farm (`k2_mode="back"`, `k2_back_day=18`, VRP ledgers reset, as for V56).
  - The clone's own d29 sell-off (END=1) never runs, because the hand-back at d18 comes first.
- **`KERNEL2_CLONE_CFG = "GUARD=1|WATER1=1|CARE=2|CAP=90|END=1|M3=1"`.** These are the clone's BCB_* switches without the prefix; the default is BCBODY3's best rung, r4c+care2+end. The field is `|`-separated, so it passes through the `LE.SWITCHES` / apply_switches comma parser.
- **Loader: `runtime.clonebody_load()`.**
  - `agent/clonebody/body.py` is loaded by path as a fresh module per game. Its ledgers (`_LED`, `_PREV`, …) are module globals, as the V56 kernel's are.
  - `params.npz` is read once per process as float32 and injected; the CFG is injected too. The load is numpy only: no JAX and no sys.path edit.
  - The callable is tagged `_bcw_clone`. A PRELOADed V56 callable is replaced at the first clone turn.
- **Safety:** an exception inside the clone hands the farm to PFS at once (`k2_clone_err` = the step). PFS then plays the rest of the game.
- **The V56 source lines are untouched.** The clone branch is inserted before `if self.k2_fn is None: self.k2_fn = kernel2_load()`, so test_kernel2_v3_package's wiring asserts hold.
- **`agent/clonebody/`** is `S/bcbody1/agent/main.py` (md5 bdf649b0, snapshot in `S/bcwire1/src_snap/`) ported by `S/bcwire1/port_body.py`. It is verbatim except for:
  - `os.environ` is replaced by `_ENV`;
  - the weights come from `_BCW_PARAMS`;
  - feats/model/model3 are loaded by path (model3 loads its sibling model.py);
  - the shadow V56 path points at the packaged `agent/v56kernel.py` (the same md5 e2f39bf2 as v56tune1's v56kernel_orig);
  - `agent()` re-raises instead of writing a log.

  The port is asserted: a drifted main.py fails the port instead of shipping half-ported. Re-running the port on the snapshot gives byte-identical files. All BCBODY4 switches (SALE, CRUSH, INV, HAND, ...) are carried, so a new config needs only `KERNEL2_CLONE_CFG`.
- **Packaging (`scripts/package_submission.py`):**
  - `CLONEBODY_INCLUDE` (8 files) plus the params are shipped **only when the tree's `KERNEL2_BODY` default is "clone"** (parsed, never imported). `--clone-params <npz>` overrides the default `src/kagg3/agent/clonebody/params.npz`.
  - A v56 build keeps the 31 members. Only `plan.py` and `runtime.py` differ from dist/vrp17_k2hb, and they carry only the switch code.

**The float16 check fails, so float32 ships** (`S/bcwire1/f16check.py`, `logs/f16check.txt`). The same 300-step observation sequence was run through float32 and float16-stored params:
- max |dlogit| on identical inputs: unit token 0.063, qty 0.051, market 0.113;
- min float32 top-2 unit margin: 0.0008;
- the first action flip is at step 82 (d3 h10), and 2 of 300 steps differ.

Float16 is therefore not action-exact. The package ships compressed float32 (13 MB, well inside the limit).

## 5. Re-package recipe (one command; `S/bcwire1/repack.sh`)
```
# given a new clone params file (float32 model3 npz from train3.py, e.g. remote out5x/params_best.npz copied locally):
bash S/bcwire1/repack.sh <params.npz> <tag>            # [f16] as a 3rd arg stores float16 (NOT action-exact, see §3)
#   env CLONE_CFG="GUARD=1|WATER1=1|CARE=2|CAP=90|END=1|M3=1|SALE=3"   the clone's BCB_* switches, if the new rung needs others
#   env PORT=1   first re-port S/bcbody1/agent/main.py (+ feats/model/model3/json) into the tree (port_body.py) if BCBODY changed the agent code
#   env W=6      smoke workers (local CPU cap)
```
Steps, all logged under `S/bcwire1/logs/` (about 15-20 min on a loaded box):
1. **Params into the tree:** the params go to `kagg3_wt_bcwire1/src/kagg3/agent/clonebody/params.npz` as compressed float32.
2. **Named tests:** `tests.sh <tag>` runs test_bcwire1 plus the PACKHB1 list (expect 1 fail: package_defaults vs dist/vrp17_k2hb, §2).
3. **Package build:** `build_pkg.sh <tag>` builds the clone-default package on a copy, writing `S/bcwire1/pkg/<tag>.tar.gz` (never dist/). With CLONE_CFG it also sets the plan default of the copy.
4. **20-seat smoke:** `smoke.sh … <tag> 6 clone` runs the 20-seat MELON clone arm. The v56 arm does not depend on the params, so `logs/smoke_v56.csv` is reused. The pair_faith summary goes to `logs/<tag>_pair.txt`.
5. **Package game:** `pkgfire.py pkg/<tag>` plays the package as a file agent on the 2438 seat. It checks exact against the step-4 row, `k2_mode` back / 18, and ms per step (`logs/pkgfire.csv`).

**To ship a passing clone** (the user's call), follow PACKHB1 §7-8 on top of `bcwire1`:
1. Set `KERNEL2_BODY = "clone"` (plus CFG) in plan.py AND add `KERNEL2_BODY=clone` (plus `KERNEL2_CLONE_CFG=…`) to the LE.SWITCHES gene block (the gene-block-equals-plan test).
2. Bare-build to dist/.
3. Re-point test_package_defaults, then pin.
