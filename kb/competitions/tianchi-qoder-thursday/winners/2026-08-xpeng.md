### 小鹏 AI 出行服务编排 Agent（一等奖，帖 1070745，作者名未渲染，归属为推定）

**归属依据与边界**（先读证据，再读作品）：官方一等奖点评与本帖的吻合度——逐字级 4 组：① 点评主题场景"疲劳但想赶路"↔ 帖旗舰输入"我有点困，想回家，不要提速"；② "既说明为什么要干预，也给出可接受的替代方案"↔ 帖核心设计"部分放行"（疲劳驾驶：禁止加速，允许查询服务区和规划安全路线）；③ "给出分级响应而非一刀切断"↔ 帖"危险操作只被单独否决，安全替代方案继续执行"；④ 专家建议"定义'用户拒绝休息'后的分级干预"↔ 帖旗舰场景即用户拒绝停车休息、坚持开回家。强对应 4 组：五级链路"车辆信号→风险判断→服务计划→禁止动作→决策留痕"五要素 ↔ 帖输出管线（车辆状态接入→Qwen 风险分析→动态服务计划→允许/禁止操作→实际工具轨迹可追溯）逐级对应；"单屏集成风险指数、车辆状态、用户原话、系统解释、执行步骤与禁止动作"六要素 ↔ 帖 UI 右侧分析区七项逐项对应；"高速行车、紧急停车、儿童安全"↔ 帖场景组（快速路开窗/隧道停车/亲子出行）。残余不确定性：点评"深色车机风格"无法从帖文/仓库文字核验（UI 颜色未描述）；帖页作者名未渲染，不能排除同题材他帖为一等奖作品的极小概率。

**解题/创作骨架**：
1. 问题定义：针对车载 Agent 五痛点（表面指令≠真实需求/安全边界不透明/多轮上下文漂移/故障无提示/过程不可追溯），做"可检查、可追溯"的编排内核——帖内明言"不能只回复'请注意安全'"；
2. 感知与意图层：车辆状态/GPS/道路环境接入 + Qwen 意图分析（显式目标/隐含目标/风险等级/缺失信息/证据分层输出）；
3. 编排层：动态工具 DAG（工具存在性/参数来源/权限/依赖四重校验），只读工具直接执行；
4. 安全层：写入类操作走 Preview/Confirm 两阶段确认 + Qwen Safety 独立审查 + 二次 Safety Veto；策略为"部分放行"——危险操作单独否决、安全替代方案继续执行；
5. 交付层：React 双栏前端（左对话/路线卡片/行内确认，右分析区七要素）+ FastAPI + PostgreSQL/pgvector + MinIO 五服务 Docker Compose；Whisper 语音入口；13 场景 × 改写变体共 39 用例回归 + strict-suite 报告 + run/session/trip/order 四级数据隔离测试中台。

**亮点**（按该赛评审维度归类；证据=官方点评图转录 + 帖 1070745 全文 + 仓库 README）：
- 服务编排（点评"五级链路逐级递进，每个工具调用均有明确触发条件"）：动态 DAG + 四重校验 + 失败降级路径，且每条结论可回答"哪个工具在什么数据上得出"（帖 §六）；
- 安全边界（点评"分级响应而非一刀切断，兼顾刚性底线与体验弹性"）：**部分放行**是本期最被官方肯定的设计范式——布尔式全拦截升级为"veto 列表 + 替代方案继续执行"（帖 §三，四条规则逐条给出"禁止什么+允许什么"）；
- 场景理解（点评"意图判断有层次、有依据"）：显式/隐含目标双层分析 + 风险证据输出，直接命中"读懂人心"赛题主张；
- 交互与呈现（点评"信息密度高且层次分明"）：主回复与服务方案、安全边界、工具轨迹分层展示，七要素分析区使评审可逐项核对；
- 工程质量：两阶段写确认 + Safety Veto + 39 用例回归 + 数据四级隔离 + 测试环境分离（development/test/docker），在"1 小时 Agent"定位的系列赛中属重度工程投入（README：13 场景套件/strict 报告/预检清理 API）。

**不足与可改进点**（核对维度：官方点评专家建议/帖内自述覆盖面/技术栈契合）：
- 官方专家建议（= 评委认定的改进方向，逐条转录于 raw 快照）：① "定义'用户拒绝休息'后的分级干预与责任边界，避免安全建议变成单次提醒"——帖内旗舰场景只覆盖用户"接受双路线规划"路径，**用户彻底拒绝替代方案时的升级策略未定义**；② "把服务区不可用、导航失败、传感信号冲突等故障注入做成可回放测试，并用成功率、误报率和接管率证明闭环有效"——帖内测试中台已支持 payload 注入与回归报告，但**无故障注入用例、无量化指标**（点评暗示的下一级竞争力 = 可回放故障测试 + 指标化验收）；
- 技术栈契合：自建 PostgreSQL/MinIO/Whisper 栈，未采用赛题推荐的阿里云全栈（百炼千问已用，函数计算+OSS 托管未用）——"阿里云技术栈利用"维度有让分空间；
- 体验摩擦：公网体验页依赖用户自备 API Key（X-Model-Api-Key，fail-closed 降级 Mock），评委零配置体验打折；
- 归属证据面：UI"深色车机风格"未在文字材料中自证（见归属边界），若后续核验不符需重审归属。

**可迁移性**：
- **部分放行范式**（危险操作单独否决 + 安全替代方案继续）：可复用于一切"安全约束 vs 用户意图冲突"类 Agent（出行/家居/健康/金融风控），复用成本低——把布尔拦截改为 veto 列表 + 替代计划生成本期已被官方点评背书，是**本系列当前最高性价比设计**；
- Preview/Confirm 两阶段写操作 + 二次 Safety Veto：写操作类 Agent 的通用安全骨架，API 形态可直接照搬（帖内 v2 turns/preview → confirm），成本中；
- 右侧"分析区域"七要素信息架构（事实/目标/计划/计划轨迹/实际轨迹/模型调用记录/风险与允许禁止操作）：可解释 Agent 的标准 UI 范式，纯前端成本低；
- "显式目标+隐含目标+缺失信息+证据"四层意图输出格式：低成本，任何意图理解场景可用；
- 四级数据隔离 + preflight/cleanup + 场景改写回归：多场景 Agent 测试中台模板，复用成本中（需后端配套）。
