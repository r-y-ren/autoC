## 一、评审偏好（从章程/评委讲评/获奖名单可观察到的取向）

**核心机制：B 榜分数 + 复现审查双闸制——分数决定入围排序，复现决定资格保留，结果正确必须可复现才作数。**（信源等级：官网，[通知PDF]+[附件1]+[附件2] 三原件交叉）

- 闸门一（分数排序）：线上赛按 result.csv 在线评测得分排名；B 阶段取各奖项名额上限的 120% 入围 Docker 提交，收集范围扩大至初测前 490 支队伍，最终获奖从该 490 支中产生、不再顺延（[平台API] 4-29/8-10 通知，2026-08-27 实抓）。
- 闸门二（复现审查）：Docker 镜像经组委会复现验证，**复现运行结果须与提交的 result.csv 完全一致**（[通知PDF] 交付要求）；配套强约束：参赛作品主要贡献须为机器学习方法、组委会"审核并剔除没有机器学习算法贡献的队伍"；2026-07-18 规则提醒——result.csv 必须由模型训练与预测产生，硬编码固定股票代码/权重属违规，复现阶段将代码审查（[平台API]，meta.ai_policy，2026-08-27 实抓）。
- 双闸的实证闭环（2026-08-28 机读）：490 支收集范围队伍中 186 支验证通过 / **216 支验证不通过（44.1%）** / 88 支未上传 Docker（[附件1]）；rank 4（0.3453，与 B 榜榜首同分段的在职队）因 Dockerfile `ENV BDC_WEIGHT_MODE=equal` 强制等权输出等缺陷被刷、rank 5（0.3218）因只读挂载写回崩溃 + 复现不一致被刷（[附件1] 逐队备注原文）；**全国奖 30 队经逐队比对 = "验证通过 × 在校生"按 B 榜排序的前 30 支，集合完全相等**（[附件1]×[附件2] 交叉，本文件派生统计）——奖项归属由"分数排名 ∩ 复现通过"机械决定，公示名单就是双闸的执行结果。
- 官方验证的严谨度偏好（可从备注原文观察）：验证方为排除环境误伤设置了仲裁机制——首轮挂载官方数据（只读）+ 第二轮不挂载数据，另对可疑案例加跑可写副本轮（rwcopy）、不限时扩展轮（最长观察到 51 小时）、修正宿主权限重跑、预扫描删除镜像内预置 result 类文件；官方备注中至少 11 队的判负过程显式记录了这类仲裁尝试（[附件1]，2026-08-28 机读）。取向总结：**宁可加轮仲裁不误杀，但对"真跑而不一致"零容忍**（多队备注明确"真实完成训练"仍判不通过，见第四节 C6）。
- 决赛层：受邀队伍现场演示与答辩（[通知PDF]），名次未产生（决赛阶段至 2026-08-31，[平台API]）——决赛评审偏好暂无数据，不推测。
- **五星级 A 类的定位含义**：本赛 2018 年起入选全国普通高校大学生竞赛榜单内竞赛项目（国内高校 A 类赛事），2026 年更被评为"计算机类最高的五星级赛事"（[通知PDF]+[平台API]+清华 bdc 官网三源文字一致，2026-08-27 实抓，见 meta.md）。可观察到的配套事实：3393 支队伍、5457 人报名的规模（[平台API]）；决赛 6 队覆盖塔里木大学、湖北大学、华东师范大学、国防科技大学、苏州大学、浙江理工大学，全国奖 30 队覆盖 28 校、无霸校（[附件2]，winners/2026.md 校别分布）——头部含国防科大/华东师大等强校但整体高度分散，奖项纵深（11 级奖级：决赛 1-6 名 + 全国一/二/三等奖 + 赛区三级 + 月月星）使中游队伍也有赛区级出口。

## 三、往届差异化点（什么样的作品拿到了最高奖）

本节为名单层数据侧写（非方案层，方案未公开），核心证据 = 决赛入围 6 队的构成分析（[附件1]×[附件2] 双原件互证，2026-08-28 机读）：

- **晋级规则**：B 阶段通过代码审核的队伍中，在校生单独排名前 3 直接晋级，其余按 B 榜成绩前 3 晋级（[通知PDF]+[平台API]）。
- **实际构成**：B 榜前三名塔里木大学-毛延亮的团队、生长-生之、cjmao 三队并列第一（得分 0.345264219952075，小数点后 12 位完全相同，[附件1] 原值）且均验证通过——恰好占据"在校生前 3 直接晋级"名额；rank 4（在职，0.345263874687855）、rank 5（0.3218）验证不通过，rank 7/8/12 未上传 Docker，于是"其余按 B 榜成绩前 3"由验证通过队伍中的 rank 6 Forever（0.2842）、rank 9 gogogo（0.2323）、rank 10 誓死效忠恒生科技（0.2283）替补入围。
- **证据链结论**：决赛 6 队 = 验证通过队伍中 B 榜最靠前的 6 支——"B 榜分数决定入围（排序资格）、复现验证决定保留（资格生效）"的双闸在晋级环节同样生效；分数买不到复现豁免，复现通过也救不回分数不足（rank 13/14/15 验证通过但止步全国一等奖线外）。
- **分辨率观察**：B 榜顶端饱和——前三名得分完全相同、rank 4 仅在第 7 位小数有差异（[附件1] 原值），意味着榜首段线上评测无区分度，**真正的差异化被制度性推迟到复现质量与决赛答辩两个环节**。此为机制层观察，不涉及任何方案内容。
- 已知缺口（不作猜测）：全国一等奖公示 6 队 vs 规程 5 队，无备注解释（winners/2026.md 缺口声明 4）；决赛名次 8-31 后产生。

## 四、反面观察（常见失分模式，若有依据）

**总口径（[附件1] 逐队备注机读，2026-08-28）：490 支收集范围队伍中 216 支（44.1%）验证不通过，另有 88 支（18.0%）未上传 Docker——即被要求提交 Docker 的队伍中仅 186/402（46.3%）通过复现闸门。** 216 条备注为组委会逐队手写（无模板复用），以下归类为本文件派生统计（关键词多标签分类，一队可落入多类，67 队复合 ≥2 类），非官方分类口径：

| 失败类别（自分类） | 队数（占 216） | 典型形态（备注原文摘录） |
|---|---|---|
| C3 数据接口硬编码/私有布局假设 | 124（57%） | 82 队硬编码 `train.csv`/`test.csv` 等私有文件名，与官方单文件 `stock_data.csv` 接口不符致 FileNotFoundError；3 队假设"每股一个 CSV"目录结构；4 队强依赖私有环境变量/入参（`BDC_DATA_PATH`/`BDC_AS_OF`/`target_date`），官方无参调用即退出；另有假设镜像自带数据集但文件未打进镜像 |
| C6 复现结果不一致（真跑但不复现） | 99（46%） | 容器真实完成训练与预测却与榜单不符：选股重合 0/5～4/5、复现分显著偏离；7 队属"临界数值抖动"（分差 0.004～0.024、4/5 重合）仍按 picks_match 判不通过；12 队自带数据陈旧（止于 2026-03-06 等，距决赛周约 5 个月）致选股漂移；3 队复现选股含非沪深 300 名单股票判成绩无效 |
| C2 运行环境缺陷 | 43（20%） | 15 队缺依赖库/解释器（libgomp、talib、statsmodels、tensorboardX、CUDA 运行库、.venv 打包无 python 解释器）；18 队缺标准入口脚本（无 test.sh，"No prediction entry point"）；7 队 Windows CRLF/BOM 致 shell 脚本空跑；另有 ENTRYPOINT 配置错误（sleep/bash 截获验证命令）、镜像架构不符、FROM scratch 无运行时、非 root 用户输出目录不可写 |
| C1 提交物非合法 Docker 镜像 | 20（9%） | docker load 即失败、容器从未启动：11 队实为源码/构建目录打包缺 manifest.json；其余为 ZIP 压缩包、百度网盘链接文本、1.2GB 全零字节、0 字节空文件、层校验不符、重复路径条目等损坏或非标归档 |
| C5 行为违规/预置产物 | 10（5%） | rank 4 队 Dockerfile 以 `ENV BDC_WEIGHT_MODE=equal` 强制等权输出（复现 0.1415 vs 榜单 0.3453）；1 队 config 写死 `fixed_stock_ids` 五股名单、模型评分算而不用（官方定性"写死股票名单的硬编码违规"）；多队镜像预置 result/expected_result 文件（其一与候选文件逐字节相同）；1 队预置模型直接推理精确命中预置提交——官方裁定"预置模型直接推理命中不算有效提交，必须真训练复现" |
| C7 资源超限 | 10（5%） | 8 小时限时内未完成（50 epoch 深度模型估算需 78 小时、强制 CPU 训练全量数据、按宿主核数起线程在 10 核配额下严重超订）；1 队子进程疑内存超限被 SIGKILL |
| C4 只读挂载写回崩溃 | 7（3%） | 把官方只读数据挂载目录当可写工作目录：拆分出的 train/test 写回、训练特征缓存写入均触发 `OSError: Read-only file system` 中断 |

- 跨类事实：92 队两轮均未产出 result.csv（完全无法交付）；82 队备注显示"真实训练/真跑"发生过仍被判负——**"真跑"是必要条件而非充分条件，闸门卡的是结果一致性本身**（[附件1]，2026-08-28 机读）。
- **44% 不通过率对"完整可实用"标准的印证**：失败几乎全部归因选手侧（官方备注显式排除验证环境因素：同机其他队伍镜像可正常加载、仲裁轮复跑后仍失败才判负）——近半数队伍能把模型调出线上分数，却交付不出一个在陌生环境按标准接口跑通且结果一致的 Docker。这证明"能跑出分数的代码"与"可交付的可复现作品"是两个独立能力维度，且后者是普遍短板；该赛把后者做成了与前者等权的硬闸。
- 排序细节：88 支未上传 Docker 的队伍含 B 榜 rank 7/8/12（0.2454/0.2415/0.2217）——分数足以进全国一等奖讨论区却因未提交而自动出局（"不再顺延"规则），反向印证提交纪律本身是第一道筛子。

## 五、赛点检查表（评审标准 → 可执行检查项；快循环验收清单的派生源）

以下条目全部派生自本届官方规则原文与 [附件1] 失败样本（派生依据逐条标注），适用于数据竞赛型（代码型）交付物；文书型战役不适用 Docker 条目，但"复现/一致性/无硬编码"三原则通用。

- [ ] **Docker 复现自测**：干净环境 `docker load` + 按官方标准接口无参调用 init/train/test 全链路跑通并产出 result.csv，与提交结果逐项比对一致（派生：[通知PDF]"复现运行结果须与提交的 result.csv 完全一致" + C1/C2 类 63 队失败形态；官方限时参照 8 小时/10 核配额）
- [ ] **数据接口零硬编码**：严格按官方数据规格读取（文件名、单文件 vs 目录、挂载点路径），无私有文件名/目录布局/环境变量假设（派生：C3 类 124 队——占比最高的失败类别；官方单文件 stock_data.csv 接口）
- [ ] **只读输入/可写输出分离**：全部中间产物写入可写工作目录，不向数据挂载目录回写任何文件（派生：C4 类 7 队 Read-only file system 崩溃）
- [ ] **无预置结果/锚点**：镜像不含 result/expected_result 类预置文件；删除预置模型后全流程可重训复现（派生：C5 类 + 官方预扫描删除机制 + "预置模型直接推理命中不算有效提交"裁定）
- [ ] **输出行为纯净**：审查 Dockerfile ENV 与输出逻辑，不存在强制等权/篡改权重等绕过模型的行为路径（派生：rank 4 队 `ENV BDC_WEIGHT_MODE=equal` 案例——B 榜同分段被刷的直接原因）
- [ ] **无股票名单硬编码**：选股与权重完全由模型预测产生，config/代码中不存在固定代码名单（派生：[平台API] 2026-07-18 规则提醒 + `fixed_stock_ids` 违规案例）
- [ ] **依赖完备**：requirements/系统库（libgomp、talib、CUDA 等）在干净镜像内全部可 import；不打包构建机 .venv；提供全部标准入口脚本且 LF 换行、无 BOM（派生：C2 类 43 队的四个子形态）
- [ ] **资源预算**：训练时长/内存/线程数在官方配额内完成，深度模型 epoch 数与硬件匹配估算（派生：C7 类 10 队，含 78 小时估算案例）
- [ ] **一致性自测**：固定种子完整重跑 ≥2 次，选股与权重逐项全等——不接受"4/5 重合、分差 0.004"的临界通过（派生：C6 类临界抖动 7 队均被判负，picks_match 全等口径）
- [ ] **数据新鲜度对齐**：自带/缓存数据的截止日与赛程决策周对齐，防止选股漂移（派生：12 队自带数据止于 2026-03-06 等陈旧案例）
- [ ] **结果合规**：输出股票均在官方标的名单内、表头/数量/权重约束满足（派生：3 队选出非沪深 300 股票判成绩无效 + [通知PDF] result.csv 规格）
