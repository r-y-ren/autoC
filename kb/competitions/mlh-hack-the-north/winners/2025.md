## 二、深构条目（每篇一节，四节必备）

### DUM-E — NLP 驱动机械臂（Hack the North 2025，画廊 Winner 徽章项目；Jason Liu / Daniel Ganjali / Chinmay Jindal / Eric Tao Xie）

**解题/创作骨架**（依据：devpost 项目页原件，2026-08-28 抓）：
1. 命题：钢铁侠 DUM-E 式桌面助手机械臂——语音指令 → 物理动作。
2. 感知层：摄像头 + OpenCV 分割 + 单应性变换，把工作区映射成俯视图（鸟瞰坐标）。
3. 决策层：Whisper Large V3 语音转文字 + 多模态 LLM（Groq 上的 Llama Maverick 109B）读俯视图与转录文本，决定机械臂动作（指向/挥手/抓取）。
4. 执行层：Flask 服务器（Raspberry Pi）→ Arduino Uno PWM 舵机控制 + 逆运动学（5 自由度：1 yaw/3 pitch/1 roll + 爪）。
5. 闭环：机械臂当前位姿/爪状态回传 LLM，支持连续指令。

**亮点**（对应该赛 expo 评审取向：Technology/Design/Completion/Learning，MLH 四等权标准）：
- Technology：多模态 LLM 直接消费俯视图坐标做空间决策——"多模态模型在空间推理方面的强大能力令人印象深刻"（作者经验原文）；Groq 快推理控制延迟。
- Completion：36 小时内端到端跑通（STT→LLM→CV→嵌入式硬件全栈），"What it works" 演示完整度高。
- Learning：作者明示学到的多模态空间推理经验，正对 MLH "did the team stretch themselves" 评分点。
- 硬件叙事：9A 电流、舵机归零、逆运动学微调等真实工程细节——现场 expo 的强展示素材。

**不足与可改进点**（核对维度：技术披露完整性/演示边界；依据项目页自述，未看现场演示视频）：
- 空间感知无深度信息（单目+单应性近似），抓取高度估计不可靠——作者已把深度相机列入 What's next。
- 多步任务与上下文理解未实现（作者自认 next step）；LLM 决策的失败模式（误抓/误判）无量化。
- 集成延迟问题作者列为挑战但未给出实测数字。

**可迁移性**：
- "多模态 LLM 读俯视图坐标 + 机械臂 IK"是可复用的具身智能演示模板（成本：中-高，需硬件件套；对纯软件赛道可降级为"LLM+屏幕坐标"的 UI 操作 agent）。
- 36 小时交付节奏的工程切层法（感知/决策/执行/回环四层解耦）可迁移到我方黑客松时间盒管理。
