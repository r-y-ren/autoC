# Amazon Nova AI Hackathon 模式库（patterns）

> 追溯约定：本文只重组库内实抓结论，事实明细见 `winners/2026.md`（各条目带来源 URL + 抓取日期 2026-08-27）与 `meta.md`（sources 同日实抓）。文中 **W1–W7** = winners/2026.md 深构条目 1–7（BackstageCommercials / Oracus AI / Sai / Project Memoria / Title AI / flare / SpatialMath AI），**M** = meta.md。
> 样本性质：**单届（2026）· 7 席获奖全集 · W3 为快照级降级条目**。7 席是当届获奖者全集而非抽样，但"由获奖集归纳致胜模式"天然存在幸存者偏差（977 提交的落选盘未分析），各节置信单独标注。
> 本文件属正文层（lint 跳过 schema，仅结构检查）；代码型（黑客松）作品首份 patterns，措辞按黑客松语境。

## 一、评审偏好（从章程/评委讲评/获奖名单可观察到的取向）

**官方标准直录**（信源等级：官网，首页实抓 2026-08-27，M）：

- Technical Implementation **60%**（质量/效果/**Nova 集成度**/系统架构）
- Enterprise or Community Impact **20%**
- Creativity & Innovation **20%**
- 另载 social impact 有加分（M 概况）；5 赛道制 + Student App 独立资格奖（M）。

**间接归纳**（性质声明：无评委讲评/评分明细实抓，以下由 60-20-20 权重 × 7 席获奖作品共性反推；作品侧证据为官网级项目页实抓，归纳环节置信**中低**）：

1. **"Nova 集成度"被获奖者当显性得分位经营**：W5 用满 Nova 全家桶（Reel/2 Lite/Act/2 Sonic/Bedrock KB/微调，"覆盖面第一，正中 60% 技术权重里的 Nova 集成度"——W5 亮点原文）；W1 串联三种 Nova 能力且"各自承担非同质角色"（W1 亮点）。
2. **成本工程是技术叙事的高频弹药**：4-bit 量化 + 单帧生成摊薄（W1）、token 降约 85%（W4）、约 1/7 成本的小模型路由（W5）、延迟 6→2 分钟（W2）——四席均把"省了多少"写成技术亮点。
3. **Impact 用落地信号而非愿景表达**：400+ 用户 + $29/月付费档（W2）、$0.0027/用户/天成本核算（W4）、GitHub 开源 + uptime 监控（W6）、$3.6T 行业切口叙事（W5）、55M 患者基数（W4）。
4. **完成度 = 端到端单旅程跑通**：现场对话→上台准确回忆的全流程 demo（W4）、场景理解→购物代理直达商品页（W1）、告警创建-验证-回滚闭环演示（W6）、单周末端到端可用（W7）。
5. **创新维度偏好"反常规模型用法"**：视频生成模型造浏览器自动化训练数据（W5）、把 Nova Act SDK 从"用工具"改造成"造工具"（W6）、场景原生隐形广告（W1）。
6. **表达策略亦影响可信度**：W6 在 Challenges 如实写工程失败（SDK 断代/WebSockets 不可用/放弃 MCP），"失败的诚实披露反而强化技术可信度"（W6 亮点原文）。

## 三、往届差异化点（什么样的作品拿到了最高奖）

**声明**：2026 为库内可考唯一一届，**无往届可比**；且 977 席总盘仅实抓画廊首 24 席（winners-first 排序，获奖者列首——M sources），落选 970 席未分析。本节是**获奖侧证据归纳，不是获奖 vs 落选的对照研究**，置信**低**；"977 分母"仅说明竞争烈度（7/977 ≈ 0.7% 获奖率，按公告级别合计）。

- **Technical（60%）：把指定模型的用法做成展示位**——头部作品在"Nova 集成度"上堆深度：W5 全家桶覆盖 + 反常规用法（视频生成造训练数据）；W1 三种 Nova 角色非同质分工 + 三层成本工程；校验闭环 ×3 席（见二节）。
- **Impact（20%）：落地信号三型**——付费/用户数（W2）、开源与监控（W6）、$/用户/天成本口径（W4）；叙事锚点选可量化基数（55M 患者 W4、$3.6T 行业 W5）。
- **Creativity（20%）：反常规用法即创新分**——合成数据（W5）、SDK 语义改造（W6）、广告即场景（W1）。
- **头部两名 vs 赛道奖的分层观察**（7 席内规律，非因果结论）：Overall 前二（W1/W2）均为**完整商业叙事 + 端到端系统**（隐形广告变现、焦点小组替代且已有付费档）；Best of 赛道奖更偏**单点技术亮点**（W5 反常规数据管线、W6 SDK 改造闭环、W4 降本技术点、W7 单次结构化生成）。
- **团队规模无门槛信号**：单人（W2、W4）、2 人（W6）、4 人学生队（W7）均获奖（W1/W5 成员名单未获取，见 winners 数据缺口）。

## 四、反面观察（常见失分模式，若有依据）

**来源声明**：无评委讲评/落选案例实抓；本节为获奖作品深构"不足"节的归纳——即"登顶作品共有的短板"，**不是落选原因分析**。以下每条在 6 个可评估席位（W3 不可评估）中的分布：

1. **评测缺失是通病（6/6）**：关键数字全部自述、无对照/无测量过程——W1 无任何效果评测；W2 核心效度未验证、"20× 便宜"为粗估；W4 的 85% 与 $0.0027/天无测量口径、检索准确率未测；W5 的 2.7x/1.5x 与"1/7 成本"无可复现口径；W6 无检测准确率/RCA 正确率/接通率评测；W7 无学习效果对照。→ 评测不是本赛获奖门槛，但意味着**补最简评测即可在 60% 技术权重上形成对获奖者的反超位**。
2. **合规讨论缺位（3/6 显性）**：广告标识/品牌授权只字未提（W1）；患者及第三方录音的知情同意与隐私未处理（W4）；担责文书的法律责任与语音摘要可靠性未讨论（W5）。→ 同上，非门槛但是空白差异化位。
3. **营销口径/挂名风险（3/6）**："any US county" 实际覆盖未披露（W5）；Nova Reel 与交互 3D 场景的整合机制不明、存在挂名嫌疑（W7）；预计算画像库对临时查询支持弱但未声明边界（W2）。
4. **工程降级自认（2/6）**：录音 SDK dev 模式 + Guardrails 降级为 prompt 护栏（W4）；电话 PSTN 链路未展示、日志流退化为轮询、依赖断代 SDK（W6）。
5. **反面观察的正向用法**：W6 证明"如实写失败"比写套话更能取信评委——短板披露本身不扣信任分。

## 六、对本框架的启示（喂给 K-02 / 验收报告）

- **与团队画像的契合**（画像 = web 全栈 + ML，任务包给定）：
  - 全栈上线是已验证的获奖形态：W2 以 Next.js+FastAPI+Vercel+付费档拿 Overall 第二——web 全栈能力在本型赛直接对口 Impact+完成度双维度；
  - ML 画像在 60% 技术权重上有充足展示位：嵌入检索 ×3、量化部署（W1）、CV 分割合成（W1 YOLOv8-Seg）、模型微调（W5 OCR）、合成数据（W5）均为获奖实证；
  - 小队可行：单人作品占 Overall 前二/赛道奖各一席（W2、W4）——画像规模适配。
- **作品工程要点（黑客松 track）**：
  - demo 优先：按"一条旅程端到端跑通"裁剪范围（W6 单告警闭环、W7 单周末端到端均获奖）——蓝图阶段即做减法；
  - "最简评测"是空白差异化位：对获奖者通病（四-1）的反超点，且直接服务 60% 技术权重——验收清单应含 C3；
  - 成本工程模式库（C4/C5/C6 各项）+ $/用户/天 表达（D2）应内建到黑客松 track 的蓝图模板。
- **AI 政策栈应对（强制主办方模型型赛）**：
  - 心法：把强制模型当**得分项**而非约束——W5"每层点名一个 Nova 能力"的展示法是直接模板（W5 可迁移性原文）；
  - 强制范围有边界：rules 明示可自由混用服务/框架/工具（LangChain、MCP、A2A 等），获奖者均混用非主办方组件（W1 的 FLUX Kontext/YOLOv8，W2 的 ChromaDB）——核心链路用指定模型、外围自由选型；
  - 官方预留通道：Nova 公开权重可选自部署（M ai_policy）——API 受限场景的合规路径；
  - 框架工程建议（**策略推演，非实抓结论**）：我方作品工程的 LLM 调用层保留 provider 适配，赛时把主办方模型接入核心链路、外围组件按需选型。
- **边界与待刷新**：
  - 本赛已结束（M status: ended），本文件结论供同型赛（厂商模型推广型 Devpost 黑客松）推演，跨主办方外推置信低；
  - W3（Sai）项目页补抓后应刷新二、四节的计数；Bonus/Feedback 奖名单（160 席）官方未公布，无法纳入；
  - 若后续届次出现，"往届差异化点"节需重写为真正的跨届对照。
