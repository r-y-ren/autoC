## 二、深构条目

### 1. DOG——嫁接学习方案（一等奖/冠军，单人队，花志祥·京东尚科）

**解题骨架**（来源：冠军 GitHub README[3] + 新智元评委视角报道[1]）：
1. 问题定义：预测第 8 天（复赛含上午数据）的转化概率，发现初赛各天转化率相似、复赛前 7 天与第 8 天差异巨大（大促日）→ 问题重定义为分布漂移下的预测。
2. Graft Learning（嫁接学习）：以第 1~7 天数据为"砧木"（rootstock）训练模型，其预测输出视为"营养"（nutrition）作为特征，供给"接穗"（scion）模型（用第 8 天上午数据训练）——用历史分布模型的知识弥补目标日样本不足。
3. 融合嫁接特征与常规特征，训练最终模型预测第 8 天下午。
4. Sample Embedding：基于 predict_category_property 与 item_property_list 构造样本嵌入——取 top100 属性做 0/1 指示向量，用户嵌入=其点击样本嵌入均值，商品嵌入=点击该商品的用户嵌入均值，共 6×100 维特征，刻画"用户-商品属性匹配度"。
5. 交付一页式最终代码（评委确认"全部代码只有一页"[1]）。

**亮点**：
- 直击赛题核心矛盾（分布漂移/特殊日预测），方法命名化、思路极简——评委原话："没有暴力地去融合很多特征，而是针对数据特性做了很简洁的特征设计"，工程上"有比较好的实用性"（评审标准=复赛成绩+答辩表现，[1]）。
- 嫁接方向有实验边界意识：复赛内跨时间段嫁接有效、跨赛段（初赛→复赛）嫁接"因类目亲缘关系太远"无效——给出失败实验与归因（[3]）。
- Sample Embedding 用"用户群画像均值"代替个体长历史，适配低频场景（多数用户 8 天点击 ≤5 次，亚军文[4]的数据分析互证）。

**不足与可改进点**（核对维度：方法边界/工程/业务可落地性）：
- 时差特征存在数据穿越（用到"距下次点击时间"），冠军本人在答辩中承认属数据穿越（[1]）——业务上不可得，实用性和可复现性受损。
- 方案细节公开度依赖一页 README：未公开线下验证策略、单模型分数、消融实验（[3] 无此内容），可复现颗粒度低于亚/季军。
- 迁移学习仅在"同分布时间段"内有效，方法对跨场景（如线上→线下、类目漂移）的稳健性未验证（[3] 仅给出本赛结论）。

**可迁移性**：
- "历史模型输出作为目标时段模型特征"的 graft 套路，可迁移到任何时间漂移类赛题（促销/节假日/突发流量），成本低（两阶段训练即可）。
- Sample Embedding 均值式嵌入适合冷启动/低频用户场景，30 行代码量级可复刻。
- "简洁性本身就是答辩加分项"——对快循环作品的启示：评委讲评明示简洁方案受青睐（[1]）。

### 2. 蓝鲸烧香队——特征群海量工程方案（二等奖/亚军，周耀/李智/郭鹏博）

**解题骨架**（来源：雷锋网亚军全方案长文[4]，队员笔名 BRYAN/桑楡/李困困；GitHub YouChouNoBB/ijcai-18-top2-single-mole-solution）：
1. 数据分析定位问题：前 7 天转化率 ~1%，6 日走低，7 日上午 >4% 且样本量远超日均 → 特定促销日预测问题。
2. 主模型用 7 号上午样本训练、31-5/6/7 号数据提特征；两种弥补时间信息缺失的手段：前 7 天模型对 7 号的预测概率作新特征；前 7 天+上午全量模型加权融合。
3. 预处理：id 众值/数值均值填充；item_property_list 取频次 top1~10 property 作 id 特征；predict_category_property 顺序取 top1~10 类别；item_category_list 取第二层类目。
4. 特征工程：基础/转化率（加平滑）/排名/比例/类/竞争/业务七大特征群，并行提取，按特征群分批线下验证。
5. 三人各训一个高分模型（样本与特征均有差异），差异性融合；LightGBM 为主（数据量小、迭代快）。

**亮点**：
- 稳健的双线下验证纪律："7 日上午最后两小时"+"7 日上午随机 15%"两套线下均提升才提交线上——把线上提交机会当稀缺资源管理（[4]）。
- 特征群分批测试法（原始特征+待测特征群），在复赛大数据量下快速迭代（[4] 工程优化节）。
- 工程四板斧可操作性强：id 重编码+树深 -1 替代 onehot；数据分块落盘再并行（规避 Python 多进程内存拷贝）；训练/测试合并提特征后按 day/hour 切分；特征群分批验证（[4]）。
- 数据洞察驱动决策：logloss 指标 → 不做负采样以保持分布（[4]）；点击一次用户占比大 → query 为核心表征（[4]）。

**不足与可改进点**（核对维度：过拟合控制/业务可落地性/方案自身承认的局限）：
- 当天上午统计特征群过拟合：线下突出、线上平平，作者归因"上午/下午分布差异即使交叉提取仍无法克服"（[4]）——特征群筛选对时间切分敏感，说明其线下验证对"当日上午特征"这一类别不具完全代表性。
- 使用了"距下一次点击时间"等未来信息特征，作者自认业务中根本不可得（[4] 比赛与业务差距节）。
- 融合方案复杂度与业务收益不匹配：作者自述实际业务几乎不会用 stack 类融合，简单加权更常见（[4]）。
- 目标自我承认未达成（"目标一致而明确（虽然最终并未达成）"——志在夺冠获亚军，[4] 团队亮点节）。

**可迁移性**：
- 双线下验证+特征群分批测试可直接复用为本框架快循环的"离线评估闸门"设计，成本=维护两套切分脚本。
- "历史时段模型输出作特征"与冠军 graft 思路同构——两条独立获奖路线互证该模式为本赛制胜点。
- 工程四板斧适用于所有中等规模表格数据赛（人日级成本）。
- "比赛技巧 vs 业务可用"的自省清单（实时特征/未来信息/融合复杂度/负采样+截距修正）可作为我方 AI 辅助方案"业务真实性"答辩预案。

### 3. 躺分队——异常流量特征工程方案（三等奖/季军，全学生队）

**解题骨架**（来源：腾讯云转载方案自述[2] + GitHub README[5]）：
1. 问题定位：平稳流量 CVR 已有成熟工业方案，本赛核心=异常流量（大促日）中找稳定可靠的预估方式。
2. 探索性分析：8/31-9/7 训练、9/7 下午预测；8/31-9/5 转化率稳定、6 日下降、7 日猛增 → 推测 7 日为大促节日。
3. 构造 4 个差异训练集（all-to-7 全量统计提第 7 天特征 / sample 全量抽样 / only7 仅第 7 天 / all 全量），每组内做高维特征选择后特征分组。
4. 特征工程三步走：基础特征分列→去低方差列→去高缺失列；特征选择复用其糖尿病赛开源框架（github.com/luoda888/tianchi-diabetes-top12），贪心+模拟退化构造多组特征，Std/Mean 训测分布一致性筛选。
5. 组内 n 特征组×m 模型加权融合，组间再加权得最终；用前六天上下午每小时均值变化趋势线下预测线上均值 0.036287135，对最终结果做 Logit 逆变换校准。

**亮点**：
- 离线验证直接取"异常流量当天上午最后 1/2 小时"——验证集设计紧贴测试分布，与冠军/亚军的做法三方互证（[5]）。
- 复用自有历史赛开源代码（糖尿病 top12 的特征选择框架）——学生队资源的最大化策略（[2]）。
- Logit 逆变换校准线上均值：用历史趋势外推目标日整体转化水平再回写预测，显式处理 logloss 对整体校准的敏感性（[2]）。
- 前三名中唯一全学生队，方案文档（PPT+PDF+算法思路.txt）全部开源（[5] 仓库清单）。

**不足与可改进点**（核对维度：方法泛化性/创新度自评/工程）：
- 方案自述"Promotion Period 的特性和时间序列特征刻画存在欠缺"（[5] Introduction 末句）——对促销动态的建模深度不足，仅靠训练集划分近似。
- 融合体系两层加权（组内×组间）超参多、解释性弱，未见消融证据说明各组件贡献（[2][5] 均未给出）。
- 均值外推校准依赖"第 8 天与前 6 天趋势同构"的假设，若大促强度突变则校准失效——未见敏感性讨论（[2]）。

**可迁移性**：
- "多训练集划分+组内组间两级融合"是表格赛通用涨分模板，成本=1 周内可搭建。
- 仓库含答辩 PPT/PDF 原件——可直接学习"决赛答辩材料"的叙事结构（快循环 Document 角色参照物，[5]）。
- 学生队路线证明：特征选择框架复用+验证集设计可在资源受限下进 Top3。
