## 四、反面观察（常见失分模式，若有依据）

- **一手红线（赛事页原文）**：必须构建在 AssemblyAI 平台之上（Voice Agent API 或 Realtime STT API 二选一）——不用其栈直接丧失资格；提交须原创且 MIT 合规（"Submissions must be original and MIT-compliant"）；队伍 1~6 人。
- **一手风险条款（官方免责节原文要点）**：规则、奖金与条款可单方变更或取消；奖金依赖第三方赞助方资格与可用性；发放最长 90 天——策略上不应把奖金当确定性收益建模。
- 提交包缺项风险：九件套（标题/短描述/长描述/标签/封面图/视频/幻灯片/公开仓库/应用 URL）任一缺失即提交不完整（清单制，反推）。
- 平台兑现记录：往期"获奖公布"可证、奖金实际发放不可直证（meta 待办 2）——按"平台一手（新平台，往届兑现待核）"等级计。

## 六、对本框架的启示（喂给 K-02 / 验收报告）

- 方向契合：免费、全程线上、月度周期——低成本练兵场；强制栈 + MIT 开源与 GOAI（决赛 09-22/23 同窗）的开源要求兼容，Voice Agent 作品可评估"一鱼多吃"双投（meta 已注）。
- 工程要点：语音代理的验收难点在延迟与打断——turn-taking/VAD、sub-second 转写是 API 特性描述而非评审标准（注意区分），但 demo 失败多发生于现场语音环节，验收清单应含"嘈杂环境/打断恢复"人工测试项。
- 合规栈：AI 工具无限制（赛事本身即 AI 应用赛）；MIT 合规义务落在仓库许可与原创性两处，与快循环开源产出对齐。
- 风险建模：规则可单方变更/奖金 90 天发放——蓝图收益模型不得以本赛奖金为主假设。
