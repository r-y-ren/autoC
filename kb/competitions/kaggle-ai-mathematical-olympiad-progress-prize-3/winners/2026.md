## 二、深构条目

> 本赛评审标准实质为：私榜解题数 + 合规（单卡 H100、5 小时 wall-clock、无外部 API、开源权重模型、获胜方案公开共享）。以下"亮点"按此归类。除注明外，深构材料均为 2026-08-28 实抓。

### 1. Exalted Joseph（1st Place，公榜 #1）

**技术方案骨架**（写题式主线——注意：其 Kaggle writeup 正文为 SPA 未能渲染，本节为"确认事实 + 同族方案生态侧写"，细节置信度分层标注）：

1. **确认层**（writeup meta 直抓 + 官方公告）：方案为 "GPT-OSS-120B Based Inference"——基于 gpt-oss-120b 的纯推理方案，无微调（官方公告：多数队伍围绕该模型做 harness 与提示策略）。
2. **同族生态层**（#2/#5 队自述 + arXiv 报告交叉，均实抓）：全部五队共享同一基线谱系——Parthenos(nihilisticneuralnet) 的 "44-50-let-me-over-cook" 公共 notebook 与 Andreas Bisiadis 的 "aimo-3-gpt-oss-120b-with-tools"。TAMU-TACO 结果表注明 #1 的选定 notebook 即 "let-me-over-cook" 系。该谱系的标配：vLLM 本地服务 gpt-oss-120b（FP8 权重+KV cache）、N=8 并行尝试（T=1.0）、每尝试挂持久 Jupyter 内核做 TIR（sympy/numpy/mpmath）、熵加权多数投票、4/8 早停、18000s 时间预算等分+安全边际。
3. **#1 专属线索层**（第三方 HF 排行榜 Space + 搜索片段，**二手未核**）：memory optimization、prefix caching、KV cache fp8 量化、entropy-weighted self-consistency、verification-assisted techniques。

**亮点**（对应评审标准：解题精度/工程约束/公开共享）：
- 私榜 46/110 全场最高，且在"分数密集"的榜单上以 1 题优势胜出（TAMU 结果表）——在 σ≈1.7 分的采样噪声下（arXiv 报告对同族基线 13 次运行的实测：μ=39.7/50 公榜、min 37/max 44），顶部的 1 题差距本质是"买彩票"式的提交预算管理（arXiv §8：P(single≥44)≈2.3%，13 剩余提交内 max≥44 概率≈28%）。
- 合规内做到"能塞下的最大模型"：gpt-oss-120b 116.8B 总参/5.1B 激活（MoE）单卡 H100 80GB 可服务（同族配置实抓：gpu-memory-utilization 0.96、kv_cache_dtype fp8_e4m3、ctx 65536）。
- 方案公开共享（合规要求）：提交已发布 HuggingFace（官方公告），writeup 同步公开。

**不足与可改进点**（核对维度：writeup 可得性/方案独有性/统计显著性——前两项为本条目材料层缺口，非方案本身）：
- **材料缺口**：writeup 正文 SPA 阻断（静态快照仅 6KB 壳，`winners/2026-kaggle-writeup-1st-place.html`），"prefix caching/verification-assisted" 等专属细节仅第三方与搜索片段口径，**未能直抓原件核验**。
- **独有性存疑**：与 #2/#3/#5 同基线谱系，1 题领先在同族基线的运行方差（σ≈1.7）以内，arXiv 报告的结论——"模型能力差距碾压一切推理期优化，最优策略是反复提交未修改基线"——反过来说明 #1 的胜利中运气成分无法排除。
- **身份映射未确认**：arXiv 2603.27844（Natapong Nitarach）与 Exalted Joseph 的关系未见官方声明，本文仅将其作同族工程/消融的代理材料（该报告最佳公榜 44/50，2026-01-12）。

**可迁移性**：
- "最大开源模型 + 极简自洽基线 + 提交预算当彩票刷"的整赛策略（arXiv §11 原话："use the largest model that fits, keep temperature high, and spend your submission budget on lottery tickets"），适用于一切固定硬件/时限的推理型赛。
- 同族工程模板（vLLM FP8 服务、N=8 并行、Jupyter 内核 TIR、熵加权投票、时间预算等分）有完整开源实现（varianceofx repo + arXiv 附录 A–F 配置/复现指南），复用成本低（Kaggle notebook 级）。

### 2. varianceofx（2nd Place，公榜 #2）

**技术方案骨架**（材料等级：一手——官方 HF 仓库 README 全文 + writeup 标题 meta；注意该仓库为**赛后改编版**，README 明列与原提交差异）：

1. 模型/服务：GPT-OSS 120b 经 vLLM 本地服务（kv-cache fp8_e4m3、max-num-seqs 256、ctx 65536、并发 8），单卡 H100 80GB、约 4.5h 端到端跑完（原提交 notebook：`varianceofx/let-me-improve-this-cooking?scriptVersionId=306081269`）。
2. 工具推理：每尝试挂**有状态 Jupyter 内核沙箱**（sympy/numpy/mpmath），代码执行结果回灌对话多轮推理。
3. 提示工程：系统提示显式施加 [0,99999] 整数答案约束 + Parse→Explore→Plan→Execute→Verify 结构化协议 + \boxed{} 前置校验清单（整数/范围核对后才提交）。
4. 答案抽取：**流式滚动窗口扫描 \boxed{}**——生成被时限截断也能恢复部分答案（改编版新增对大整数逗号的处理：12,345→12345）。
5. 聚合与停止：8 路并行多数投票 + 熵加权（低熵=高权重）；**动态早停**——4 票一致即停，或尾随答案在数学上不可能反超时停（=writeup 标题所称 "Fastest-Answer Prioritization"）。
6. 时间管理：锁定硬上限 MAX_TIME=18000 / MAX_PROBLEM_TIME=900 / MAX_ATTEMPT_TIME=300 / MIN_CONSENSUS=4 / MAX_CONCURRENCY=8（改编版发现 Kaggle 运行时资源竞争会挂起/崩溃，硬上限恢复稳健性）。

**亮点**：
- 答案抽取鲁棒性（流式 \boxed{} 扫描 + 截断恢复 + 逗号处理）直接对准"5 小时硬杀"约束——把时限从风险变成可管理变量（README 实抓）。
- 早停的数学化表述（"尾随答案不可能反超即停"）比朴素 4/8 一致更省时，省下的时间回流难题（README + writeup 标题 "Fastest-Answer Prioritization" 双证）。
- 工程诚实度高：README 显式区分"原提交 vs 赛后改编"，原提交含小模型 fallback 逻辑、熵打分较粗糙，均如实标注（一手）。

**不足与可改进点**（核对维度：可复现性/方案独立性/消融证据）：
- 公开仓库≠精确参赛提交：fallback 删除、尾窗熵打分、更聪明早停均为赛后改进，复现 45/110 需回读原 notebook 版本（scriptVersionId=306081269 未抓取正文）。
- 方案独立性弱：自述基于 Parthenos 与 Andreas Bisiadis 两个公共 notebook（同族谱系），差异化集中在工程层而非算法层。
- 无消融数据：README 未给出各组件（熵加权 vs 纯多数、早停阈值）的分数贡献。

**可迁移性**：
- 锁参数硬上限模板（全局/单题/单尝试三级超时 + 最小共识 + 并发上限）可直接复用到任何时间盒评测 harness，成本低（纯配置）。
- 流式答案抽取模式适用于一切"生成长度可能撞时限"的 LLM 评测场景。

### 3. SKobayak（3rd Place，公榜 #3）

**技术方案骨架**（材料等级：一手最强——writeup 正文全文渲染实抓 `winners/2026-kaggle-writeup-3rd-place-SKobayak.md` + HF Colab 仓库）：

1. 基线：ZaynYu 公共 baseline notebook——gpt-oss-120b 原样使用（无微调）、Python 代码执行工具、8 并行求解器多数投票、保留基线动态早停。
2. 离线验证体系：采集 **1120 条全文回答**（10 道官方 reference 题 ×32 次 = 320；参赛者分享的 50 道外部难题 ×16 次 = 800），全文/上下文/对错入统一表 `llm_history.csv`。
3. 错误分析：用比 gpt-oss-120b 更强的 LLM 交叉核对失败原因并归类，**同时喂给强模型 gpt-oss-120b 自己的正确回答范例**——防止强模型给出"gpt-oss-120b 跟不上的过于高级的建议"。
4. 问题结构假设：5 道几乎不可解 / 10 道时对时错 / 35 道必对——因此**只看公榜分数会过拟合那 10 道不稳定题**，改进目标定为全分支全难度的稳定性。
5. 提示设计（三点对策，均有错误分析依据）：用 Python 做验证；显式提取并核对题目约束（针对"漏看约束"错误模式）；合理收窄搜索空间（针对"循环太大跑不完"错误模式）。
6. 全部提示词（system/tool/preference 三段）原文公开于 writeup。

**亮点**：
- 方法论上最完整的**错误驱动提示工程闭环**：全文语料→强模型归类→可行域内对策→外部题集验证（writeup §1.2–2.1）。
- 反过拟合框架明确（问题三分假设 + 拒绝以公榜为唯一指标 + 外部 50 题独立集），对一切"公榜驱动"型 Kaggle 赛通用（writeup §2.1.2）。
- 负结果如实公开：日文推理、两步自纠、complexity-based consistency、8→16 扩池（提前完成的答案精度反而降）全部记录（writeup §2.2）。
- 完全开源共享：writeup 全文 + 附件演示文稿 + HF Colab 版代码（除模型路径/输入流外与提交一致，HF README 自述）。

**不足与可改进点**（核对维度：量化证据/工程深度/假设强度）：
- writeup 无消融表：各提示改动的分数贡献未量化（仅有"什么没奏效"列表）。
- "5/10/35" 问题三分是启发式假设，未经验证。
- 纯提示层方案：无服务层/聚合层工程（对比 #2 的流式抽取与 #5 的时间分配），天花板受基线钳制。
- 单人参赛、自述"以学习为目的"（writeup 开篇），无团队分工与算力管理记录。

**可迁移性**：
- "1120 条全文回答 + 强模型错误归类 + 可行域约束"的离线分析循环，是提示工程类赛的标准作业流程，成本低（一次采集多次复用）。
- 三段式提示模板（system 约束层 / tool 使用规范层 / preference 求解协议层）可直接套用于任何"整数答案+代码工具"型数学评测。

### 4. TAMU-TACO（5th Place 名次，领 4th Place 奖金口径）

**技术方案骨架**（材料等级：一手最强——官方 HF Space README + writeup.md 全文实抓）：

1. 服务层：vLLM 本地服务 gpt-oss-120b（FP8 KV cache、ctx 65536、单 H100 80GB、5 小时 wall-clock）。
2. 代理循环：默认 8 并行求解器池；每求解器可调持久 Jupyter 内核执行 Python（sympy/mpmath/numpy），print 输出回灌下一步推理；**4 求解器一致即早停**，剩余时间回流难题。
3. 聚合：8 路多数投票，按**每次尝试平均熵的倒数**加权（低不确定性答案权重更高）；无多数时选最低熵答案。
4. 时间管理：18000s 全局预算按剩余题等分；单题软上限 900s、单尝试硬上限 300s；540s 安全边际留给模型加载与基础设施开销。
5. 场外工程：用赛外 "AutoResearchAgent" 在 **64×H100** 上离线分诊提示（**大部分收益未迁移到比赛环境**——原文明示）；高价值 reference 题生成 "golden traces" 验证早停与熵加权行为；GPT-5 high 仅用于离线题集难度过滤/分诊（**从不在计时提交内**，提交完全自包含）。

**亮点**：
- 私榜 43.5/110（4138 队中第 5 名次），与其并列的 DrDobok 未入获奖名单——合规稳健性本身成为名次的一部分（公告 "stricter rules" 口径 + writeup 结果表）。
- 结果透明度全场最高：writeup.md 直接给出五队私榜分数表（本文名单节的分数源）。
- 负结果清单与 arXiv 报告交叉验证（提示多样性无增益、提示压缩反而伤、工具菜单模型不用、attempt 级反思浪费 token）——两个独立来源得出同族结论，模式可信度高。
- 离线-在线分离纪律：强外部模型只用于场外分诊，计时提交零外部依赖（规则合规的示范做法）。

**不足与可改进点**（核对维度：离线在线迁移/名次边际/可复现性）：
- 自认"64×H100 离线分诊的大部分收益未迁移"——离线提示增益在真实约束下蒸发，该团队未解决迁移问题（writeup §3 原文）。
- 43.5 与 #4 同分，名次由次级指标决定，方案边际优势不明。
- 场外 GPT-5 过滤虽然合规，但复现者无法获得同一题集分诊，可复现性打折。
- HF Space 为浏览器演示版，非精确参赛 notebook（README 自述为"easy to try"改编）。
