# GitLab AI Hackathon 2026 — 获奖作品解构

## 一、名单数据

- 计数方法：官方公告帖 41783（Devpost 一手）与 GitLab 官方博客双源文本直读，两源 22 项完全一致；无校别/地区列，不统计分布。
- 22 席分布：Grand 1 / 赞助商 GP 2 / 专项 3 / 赞助商 RU 2 / Green 1 / Sustainable 4 / HM 6（HM 规则载 5 席实发 6）。
- 规模：~6,900+ 注册（页面计数 6,958），600+ agents and flows 提交（博客口径）→ 主奖级获奖率量级 ~9/600 ≈ 1.5%（仅量级参考）。
- 署名观察：Zelong Wang 以单人项目横扫 Time-Traveler / RedAgent / Launch Control 三专项 + GraphDev 赞助商大奖（博客原文："Once again, well done Zelong Wang"）——单人多次提交多项目在本赛制可行且被官方点名表彰。

## 二、深构条目（每篇一节，四节必备）

### LORE — Living Organizational Record Engine（Grand Prize，$15,000）

**解题/创作骨架**（依据：官方博客 + 项目页原件）：
1. 切入点：MR 评审决策随合并消失 → 从 MR（而非会议）直接捕获组织记忆。
2. 架构：GitLab Duo 上的多 agent 路由制——triage router 将请求分派 8 个专职 agent（Pre-Mortem / Follow-Up / MR Review / Reply Handler / Decision Extractor / Health Auditor / Onboarding / Commit Keeper）+ 2 个独立 agent（LORE Ask / LORE Migrate）。
3. 检索：RAG + 知识图谱，带防环逻辑（circular loop prevention）与语义等价的记忆冲突检测。
4. 工程：python CLI（lore-cli，4 命令）+ 43 个自动化测试 + CI/CD；Anthropic Claude 驱动全部 agent。
5. 呈现：可视化 dashboard（Mermaid.js 决策图、碳影响表、安全清单）+ 40 页设计报告。

**亮点**（对应评审四项等权标准）：
- Technological Implementation：router→8 专职 agent 的分工架构 + 防环/冲突检测逻辑（博客原文 "logic to prevent circular loops in the knowledge graph"）；43 测试 + CI 流水线的工程完备度。
- Design：评委 April Guo "Polished design, well-structured documentation, and clear agent architecture"；"complex system with several moving parts, yet still feels cohesive"。
- Potential Impact：把 "80% 从不被讨论的决策"（作者经验原文）变成可检索资产；PII 自动扫描、合规可导出记录。
- Quality of the Idea：会议→代码本身的知识捕获转向（"capture them from the code itself"）。

**不足与可改进点**（核对维度：工程稳健性/评审披露/平台约束；证据限于官方描述与项目页，未运行代码、未看演示视频）：
- 评委评语已点出复杂度风险："several moving parts"——8+2 agent 的维护成本与 router 误路由率官方材料未给出量化。
- 平台适配打补丁痕迹：Duo agent 不能写 wiki 需 lore sync CLI 桥接；64 KiB catalog 上限靠压缩清单（87→31 KiB）绕行——说明架构对平台配额敏感，迁移性受限。
- 碳追踪方法论自述为 "carbon honest methodology"，但无第三方核算口径；PII 扫描的准确率/召回未披露。

**可迁移性**：
- "router + 专职 agent 分工 + 防环"是多 agent 竞品作品的通用骨架，可直接复用于我方 agent 类赛题（成本：中，需自建 router 与测试）。
- "43 自动化测试 + 长篇设计文档"是被评委明确表扬的信号——快循环交付 agent 类作品时应配套测试与文档层（成本低，收益高）。
- 从 MR/代码而非对话捕获知识的 RAG 切角，可迁移到任何"组织记忆/知识库"类赛道。

### Gitdefender（Most Impactful on GitLab & Google — Grand Prize，$10,000）

**解题/创作骨架**（依据：官方博客）：
1. 定位：Sentry 式的"安全 agent 监控台"，跑在 GitLab Duo Agent Platform。
2. 流程：每次 commit 触发自定义 pipeline → 运行安全 agent 扫描。
3. 技术栈：Gemini 2.5 Pro on Vertex AI（Google Cloud 全家桶：Vertex AI + Cloud Run 部署）。
4. 增强：组合 Snyk 与 CodeQL agent（静态分析 + LLM 推理双轨）。

**亮点**：
- Technological Implementation：commit 触发→扫描→修复建议的自动化闭环，"production-grade security framework"（评委 Stefania Paneva）。
- 赞助商契合：完整使用 Google Cloud 栈（Vertex AI + Cloud Run），精准吃下 $10,000 Google 赛道。
- Design：评委 "well-thought architecture… combine static analysis and LLM-driven reasoning"——传统 SAST 工具与 LLM 的混合推理。

**不足与可改进点**（核对维度：技术披露完整性；仅有博客级描述，无项目页/视频）：
- 修复建议的误报率、漏洞库覆盖、对非 Python 语言的支持均未披露。
- 深构素材单薄：项目详情页未抓取成功（/submissions 路由 500），架构细节只有博客一段——列为待补。

**可迁移性**：
- "每次 commit 触发安全扫描 + LLM 归因"模式可平移到任何 CI 集成类赛题（成本：低-中，Snyk/CodeQL 有免费层）。
- 赞助商赛道策略样本：吃透单一云厂商栈（Vertex AI+Cloud Run）拿厂商奖金，与主奖池不冲突（限奖条款允许 1 Grand + 1 Category）。

### GraphDev（Most Impactful on GitLab & Anthropic — Grand Prize，$10,000，Zelong Wang）

**解题/创作骨架**（依据：官方博客）：
1. 把 GitLab 项目转成"活的、可查询的知识图谱"，暴露隐藏依赖。
2. 随时间可视化系统演化（system evolution over time）。
3. 技术栈：Claude Sonnet 4.5 + Claude Agent SDK + Neo4j 图数据库。

**亮点**：
- Technological Implementation：代码库→知识图谱的映射管线 + 图查询交互。
- Design：评委 Dabeer Siddiqui "world-class, beautifully designed product… hard to believe this was put together in a hackathon"——demo 体验是 Anthropic 赛道夺奖的直接证据。
- 赞助商契合：Claude Agent SDK 原生集成拿 Anthropic 赛道。

**不足与可改进点**（核对维度：技术披露/规模边界；仅博客描述）：
- 大型 monorepo 的图谱构建成本/增量更新策略未披露；Neo4j 部署运维门槛未提及。
- 无团队级成员信息（博客仅署名 Zelong Wang），协作分工不可考。

**可迁移性**：
- "仓库→知识图谱→自然语言查询"是可复用的演示形态（成本：中，Neo4j + LLM 抽取管线）。
- 评委对 "beautifully designed product + joy to interact with demo" 的强调 → 演示打磨的边际收益极高。

### Time-Traveler（Most Technically Impressive，$5,000，Zelong Wang）

**解题/创作骨架**（依据：官方博客）：源代码镜像进 PostgreSQL → 代码 diff 转 SQL 指令 → 运行时架构"时间镜像"（任意时点回看应用结构）→ 模块级回滚（代码库的"重置按钮"）+ 深度语义 trace。

**亮点**：技术原创性获评委 Alberto Evans "runtime mirrors are a brilliant and innovative concept"；"presentation is world-class"。

**不足与可改进点**（核对维度：技术披露；仅博客描述）：镜像存储的膨胀率、多语言支持、"模块级回滚"与真实脏状态的一致性保证均未披露。

**可迁移性**："diff→SQL 指令"的版本化思路可迁移到任何需要状态回放/审计的赛题；单项目成本低（单人完成）。

### RedAgent（Most Impactful，$5,000，Zelong Wang）

**解题/创作骨架**（依据：官方博客）：自然语言 prompt → 生成 deployment-ready 的 Kubernetes 集群；不止代码生成，是完整自动化系统。

**亮点**：评委 Alex Hauser："truly embodies the hackathon theme of action-oriented agents… fast, well-structured, and thoroughly documented"——主题契合（action，不是 chat）被点名。

**不足与可改进点**（核对维度：技术披露；仅博客描述）：生成集群的安全基线（RBAC/网络策略）与幂等性未披露。

**可迁移性**：NL→IaC→部署的闭环演示形态可复用（成本：中，k8s 环境搭建）。

### Launch Control（Easiest to Use，$5,000，Zelong Wang）

**解题/创作骨架**（依据：官方博客）：与软件目录聊天 + 自动化工作流；连接 Jira agent、GitHub agent、监控 agent；提供 Linear 风格工程视图。

**亮点**：评委 Darrell Prank："easy to use and quite visually appealing"；Linear 风格看板直接对应 Easiest to Use 奖项的评审取向。

**不足与可改进点**（核对维度：技术披露；仅博客描述）：多 agent 编排的一致性（Jira/GitHub/监控三方数据冲突）未披露。

**可迁移性**："聊天×既有工具目录 + 熟悉的看板 UI"是低认知成本的获奖模板（成本：低-中）。
