# CastClaw：给预测工作流装上"检查-取证-停止"纪律的 agent harness

> 来源：https://arxiv.org/abs/2608.30976 （arXiv export API 实抓，抓取日期 2026-09-20。以下分析基于本次抓取的摘要原文；未发现代码发布）

## 是什么

面向工业时序预测的人机协同自治系统（摘要口径）：真实预测不是一次性模型调用，而要定任务、连数据与模型、纳入领域知识、评估合理性、沟通不确定性。CastClaw 用"预测导向 harness 工程"把数据、专用预测模型、分析工具、用户输入与**版本化执行记录**接进一个运行时：用户以自然语言指定目标、视界、约束与假设；agent 从一个给定或自行生成的预测出发，检查时间模式与用户约束，证据不足时检索上下文、跑分析或换模型、或向用户提问；随后在**显式停止条件**下保留、修订或升级结果；输出最终预测 + 记录输入/证据/动作/修订的执行报告。五数据集电力价场景中，CastClaw 在 16 个基线中报告最低点估计 MSE 与 MAE；Nord Pool 案例演示可检视工作流；另在华北省级电力负荷数据（2026 年 1-6 月）离线验证。

## 解决什么问题

专用预测模型管线固定、缺领域交互；通用 LLM agent 缺预测专用的检查、约束与停止规则——"跑了就信"或"无限重试"。CastClaw 给 agent 补上预测域的纪律层：什么算证据充分、什么时候停、过程如何留痕。

## 相比前方法优势

- **预测专用检查项**（时间模式/用户约束核查）内生于循环，而非事后人工审；
- **显式停止条件**取代开放式重试——可控的迭代成本，与赛期时间预算天然契合；
- **版本化执行记录/执行报告**：过程可审计、可复述——这正是数模论文方法论章节与 Kaggle 方案说明最值钱的形态；
- 实证不止一个案例：五数据集对比 + 北欧电力市场案例 + 省级负荷离线验证三层。

## 局限

- **无代码发布**（arXiv 页无 Comments 无链接，2026-09-20 实抓），复用即自建整套 harness，工程量在千行级；
- 实证集中在电力价/负荷域，跨域泛化未证；
- human-in-the-loop 依赖"有人在环"，比赛高压时段交互本身是成本；
- 本卡止于摘要层，16 基线名单与指标细节未读正文不得引用。

## 如何用于比赛（比赛映射展开）

- **适用赛种**：数模-数据分析与决策（含建模流程展示的题）；数模-预测与评估（论文写作结构借鉴）。
- **打法**：
  (a) **轻量版 harness**：不必复刻全套——用其骨架搭"任务书→核查→补证→停止→报告"五步的赛内自动化建模流（LLM API + 几个检查函数即可起步），把"我们如何选模型、何时停"变成论文里的流程图而非一句空话；
  (b) **模板化借鉴（零代码）**：执行报告的四元组（输入/证据/动作/修订）直接作为论文附录《建模过程记录》的表格模板；显式停止条件写成"若连续 n 轮验证误差未降则冻结模型"类可检验规则；
  (c) **答辩话术**：引其"16 基线最低误差"说明 agentic 预测管线的上限，再讲我们的轻量实现取舍。
- **成本**：reuse_cost=高（复刻系统）/ 低（仅借报告与停止条件结构，见两条映射分别标注）。
