# ReasonCast：选择性语义推理的智能体需求预测

> 来源：https://arxiv.org/abs/2608.15291 （arXiv v1 提交于 2026-08-15，cs.AI；抓取日期 2026-08-28）

## 是什么

arXiv 2608.15291（Yang 等，cs.AI）提出的需求预测框架 ReasonCast：

- **选择性触发**：由一个 agent 判断是否需要文本推理——依据事件上下文、无文本基线预测及其不确定性；
- **结构化事件语义**：不用自由文本，而以结构化字段表达事件知识（事件相关性、需求方向、时间形态、幅度、峰值强度），经加性与乘性两条路径与时序基础模型交互；
- **三阶段课程训练**：Schema SFT → 语义字段 RL → 以冻结预测器评估的预测效用 RL。

## 解决什么问题

需求预测需要同时利用历史销量的数值动态与前瞻信息（促销、节假日、价格变动、平台干预）；现有文本增强方法把上下文编码成通用表示并与时序特征无差别融合，不区分该文本对当前预测是否相关（摘要归纳）。

## 相比前方法优势

- **选择性**：稳定期不做语义干预——论文实测无差别语义干预使稳定销量期 WMAPE 恶化 1.68 个百分点；
- **结构化优于自由文本**：字段化事件语义（方向/形态/幅度/峰值）可解释、可控，与预测主干的交互有加性+乘性两条显式通路；
- 增益有梯度且落在痛点上：节日敏感品类 WMAPE -3.29pp、大促敏感品类 -1.25pp、M5 事件窗 -0.47pp。

## 局限

- **无开源实现**：arXiv 页面无代码仓库（signal.runnable=false）；agent + TSFM + 三阶段（含两级 RL）完整复现成本高；
- 增益集中在事件敏感品类/窗口，稳定期的主要收益来自"不干预"；M5 窗口增益（-0.47pp）相对温和；
- 依赖事件文本/描述输入：赛题通常只给日历与事件表，结构化字段可人工构造，但"语义推理"环节在纯表格赛题中无用武之地。

## 如何用于比赛（比赛映射展开）

- **适用赛种**：数模销量/零售/客流预测且含节假日、促销、价格干预因素的题；Kaggle 零售时序赛（M5 系）。
- **打法（组件移植，不复现 agent/RL）**：
  1. **结构化事件表示**：把日历/促销/价格事件编码为方向（正/负）、幅度、持续时间、峰值强度等字段（哑变量+数值特征+交互项），经"加性（基线+修正）与乘性（门控缩放）"两条路径进入模型——GBDT 加特征即可落地低配版；
  2. **选择性门控**：用无事件基线的残差不确定性（残差方差、分位数宽度）决定事件修正强度；论文可引"无差别干预 +1.68pp WMAPE"论证为何只在事件窗/高不确定性序列启用修正。
- **与既有卡的互补**：CEDAR（arxiv-2608.25871）给出"事件→残差修正"的模块化模式，ReasonCast 补上"何时不干预"的门控与事件的结构化语义，二者可叠用。
- **成本与风险**：reuse_cost=中——特征工程层可落地；RL/agent 层不复现也无需复现；赛前用历史节假日窗口预演确认增益，防止门控误伤稳定序列。
