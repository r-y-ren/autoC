# 表示转向调控 LLM Agent 工具调用率

> 来源：https://arxiv.org/abs/2608.25198 （arXiv v1 提交于 2026-08-25，cs.AI；抓取日期 2026-08-28。摘要称代码已公开，但给出的仓库 YuqiChen4188/Steering-Tool-Use-Propensity 经 GitHub API 核查返回 404（2026-08-28），暂按无可用实现处理）

## 是什么

arXiv 2608.25198（Chen, Siu, Liu, Song, Wang）发现 LLM 的工具调用行为可由**残差流（residual stream）中的单一线性方向**控制：

- 该方向**无需训练**，从模型自身的工具使用偏好信号中提取；
- **推理时干预**、不改提示词：以强度 α 注入该方向，调用率从接近 0% 单调升至 90% 以上，且调用格式保持完好；
- **双向往调**：调低可抑制调用（省成本、避免误触发不可逆操作），调高诱发的调用恰好落在模型自身知识答不出的问题上；
- **泛化**：方向可迁移到未见过的工具（不偏向特定工具），并零训练迁移到稠密、MoE 与多模态架构。

## 解决什么问题

"何时调用工具"是 agent 的核心决策，两头都是真金白银的代价：多余调用加延迟、烧预算、可能触发不可逆副作用；漏调则让模型在只能靠工具回答的问题上"自信地答错"。现有后训练与提示工程方法成本高，且部署后难以按预算实时调整（摘要原文归纳）。

## 相比前方法优势与局限

**优势**：免训练 + 推理时可调 + 不动提示词，三个性质同时成立；结合真实工具执行，单次转向扫描即可描绘成本/精度 Pareto 前沿——开放域 QA 准确率从 0.29 提到 0.56；跨架构零训练迁移大幅降低换模型的迁移成本。

**局限**：
- **代码不可得**：摘要给出的仓库地址 GitHub API 核查 404（2026-08-28），signal.runnable=false，方向提取脚本需按论文自实现；
- 干预残差流要求推理栈暴露内部激活（如 HF Transformers hook 层），API-only 的闭源模型不可用——比赛中最常被用的闭源 API agent 路线吃不到这个方法；
- 摘要层未披露方向提取所需的自生成偏好数据量与计算开销，也未给出各基准的绝对延迟数字。

## 如何用于比赛（比赛映射展开）

- **适用赛种**：黑客松中做 LLM agent（搜索助手、数据分析 agent、运维 agent）类作品，赛点含延迟/预算约束或误操作风险（不可逆写操作）的题面尤其契合。
- **打法（Pareto 调参器，reuse_cost=中）**：开源小模型（Qwen/Llama 系）自托管 + hook 残差流；上线前对强度 α 做一次扫描，把"调用率-成本-准确率"曲线放进作品文档，演示时按评审场景一键切工作点（演示环节切低预算、问答环节切高精度）——这条实测 Pareto 曲线本身就是评委可见的工程深度证据。
- **防误操作卖点**：对会写库、发邮件、删文件的 agent，把 α 调低做"保守模式"，用论文"调高诱发的调用恰好落在模型答不出的问题上"的发现反证其选择性，作为安全设计的亮点。
- **风险**：闭源 API 模型不可干预，赛前确认技术栈全开源；无官方代码，方向提取的自实现需预留半天调试预算。
