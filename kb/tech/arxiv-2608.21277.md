# ConceptTS：LLM 引导的概念瓶颈，可解释多变量时序预测

> 来源：https://arxiv.org/abs/2608.21277 （arXiv v1 提交于 2026-08-21，cs.LG；抓取日期 2026-08-28）

## 是什么

arXiv 2608.21277（Jiang、Chen、Liu）提出 ConceptTS：LLM 引导的概念瓶颈（concept bottleneck）可解释多变量时序预测框架（以下机制描述来自本次抓取的摘要页）：

- **LLM 提概念**：让 LLM 针对任务提出命名的人类可读概念，并生成**可执行标注规则**，把模型内领域知识转化为监督信号——免昂贵人工概念标注；
- **三段互补概念瓶颈**：历史上下文 / 局部预测区间 / 完整预测视野三个粒度各设一个瓶颈；
- **共享解码器**融合三段概念激活产出预测；支持**概念级干预**（改动激活观察预测变化）做解释性检验；
- 验证：北京多站点空气质量数据集上"精度与强黑箱基线相当（competitive）"，同时产出语义有意义的概念激活。

## 解决什么问题

SOTA 多变量预测器表征黑箱，无法回答"为什么给出这个预测"；在需要理解与评估预测因素的场合（可问责、需人工把关的场景）受限。

## 相比前方法优势

- 概念瓶颈思路系统引入 MTSF：解释单位是人类可读概念，而非事后归因分数；
- LLM 生成标注规则替代人工概念标注，工程上可落地、边际成本低；
- 三段瓶颈覆盖"输入语境—局部—全程"三个粒度，且支持概念级干预做假设检验式分析。

## 局限

- 摘要层面仅见**单一数据集**（北京多站点空气质量）验证，跨域泛化未知；
- 无代码、无 venue 信号（arXiv 页面未见作者仓库，runnable=false）；"competitive"措辞表明精度是对标而非超越黑箱——纯精度导向的赛题不占优，概念瓶颈常见的精度税需在题目上实测；
- 概念质量依赖 LLM 提示工程，生成标注规则的执行正确性需人工抽检。

## 如何用于比赛（比赛映射展开）

- **适用赛种**：环境监测/空气质量类数模预测题（其验证数据集正是该类题的经典数据）；以及评审重视"可解释 + 政策建议"闭环的题（预测结果要转化为治理建议）。
- **打法（模板直套）**：空气质量题按其结构组装——LLM 依站点/污染物领域提出概念（扩散条件、供暖季、沙尘事件等）并生成规则编码历史序列；三段概念瓶颈 + 共享解码器输出预测。论文双收益：精度对标黑箱基线，概念激活图成为"机理分析"章节素材，答辩可讲"每个预测都能指出由哪些概念驱动"。
- **概念干预做灵敏度分析**：干预概念激活（如关闭"供暖季"概念）观察预测变化，天然构成论文的情景/灵敏度分析节，评审友好且成本低。
- **成本**：组件皆常规（LLM API + 线性瓶颈头 + 共享 decoder），但无代码需全自建（reuse_cost=中）。
