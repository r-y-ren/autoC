# OnTrack：流式结构感知最优传输做 LLM agent 轨迹的毫秒级实时监控与中止

> 来源：https://arxiv.org/abs/2610.12375 （v1 提交 2026-10-08，37 KB，Babak Barazandeh 等 4 人；abs 页无 Comments、无代码/项目链接，2026-10-10 实抓；补充检索确认无官方公开仓）。本卡内容出自本次抓取的摘要页，未读 PDF 全文。

## 是什么

OnTrack 是一个 **agent 轨迹的流式监控机制**：把 agent 正在执行的每一步及其依赖关系，与**预先录制的成功运行轨迹**做结构感知最优传输比对，偏差超阈即告警或阻断——每步约 **1 毫秒**。摘要给出三种参照访问形态，能力依次退化：完整参照访问 → 仅工具 schema（中间档）→ 无先验知识（此时退化为检测循环/卡顿/重复工具调用等失效模式）。在 SWE-bench 上的数字（摘要自报）：

- **前 8 步**起即可对失败轨迹排序，AUROC 比内容相似度基线高 **0.057**；
- 配套中止策略可省约 **18% 算力**，且 **83% 的中止确实朝失败而去**（5/6 次中止正确）。

论文无代码无 venue（v1 预印本）；同组前作 OTAP（Structure-Aware Optimal Transport for Evaluating Agent Trajectories）把轨迹评估形式化为属性化依赖图之间的散度计算，是本方法的形式化基础（经检索确认关联，非本次 abs 页内容）。

## 解决什么问题

监控自主 agent 的两难：放一个守护 agent 逐步审查，给每步都加上成本与时延；事后看日志评审判定，判定到达时不可逆动作（发邮件、下订单、删数据）已经发生。OnTrack 走中间路线——**轻量流式比对**，让"发现跑偏"的成本与延迟都足够低，从而能在运行中实时干预而不依赖第二个大模型。

## 相比前方法优势

- **开销对比明确**：约 1 毫秒/步的结构比对 vs 守护 agent 每步一次 LLM 调用，监控层不再成为管线瓶颈；
- **实时可干预**：流式判定支持告警/阻断，区别于事后日志评估的"马后炮"；
- **参照访问分级**：从全参照到零先验的能力谱系给出冷启动方案——没有录制轨迹时仍可抓循环/卡死/重复调用这类不依赖参照的失效；
- **有可操作的量化结论**：早期失败预测（8 步内）、18% 算力节省、5/6 中止精度，都是可直接转译为工程指标与演示指标的数字。

- **无代码**：abs 页无链接，检索（2026-10-10）未见官方仓，复现=从零实现流式结构感知 OT + 自建参照轨迹库（reuse_cost 高）；

- 依赖"录制的成功运行"作参照：动态环境或工具接口变动时参照轨迹会过期，维护成本论文摘要层未展开；

## 如何用于比赛（比赛映射展开）

1. **黑客松-数据与算法（agent 可靠性/自主管线）**：差异化演示的最低成本路径——给参赛 agent 管线加一层"轨迹监控仪表盘"：正常参照轨迹、当前轨迹的 OT 距离曲线、超阈即熔断并展示"省下的算力"；无需复现论文全量，流式 DTW/简化 OT 对参照轨迹打分的最小版本即可撑起"我们的 agent 能自己发现跑偏并止损"的现场叙事，这比赛场上常见的"多 agent 分工"作品在评审处稀缺。reuse_cost 高：方法需自实现，参照轨迹需自己录制（赛前把 golden path 跑一遍即得，成本可控）。
2. **双创-文书与申报（自主 agent 产品治理）**：技术方案中"低开销安全层"的论证模板——引用约 1 毫秒/步与 18% 算力节省（注明 arXiv 预印本作者自报）论证监控不构成产品性能瓶颈；"告警/阻断/冷启动三级能力随参照可得性退化"可直接借用作产品的监控分级设计（全量回放库 → 工具 schema 校验 → 循环/卡死检测），对无人值守类 agent 产品的风险控制章节是现成骨架。reuse_cost 中：借设计模式与数字背书，不需复现实现。
