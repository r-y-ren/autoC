# Procedural Graphs：自进化执行结构给 LLM Agent 装显式程序知识

## 是什么

arXiv 2609.09153（2026-09-08 提交 v1，四位作者，页面未列机构；HuggingFace Papers 18 upvotes，2026-09-09 实查）。核心主张：LLM agent 做长程任务、调外部工具时，动作靠"在不断变长的历史上无约束生成"产生，程序性知识（何时、何序、何条件下做什么）全然隐式——轨迹一长就丢目标、错序调工具、重复无效动作。论文提出 Procedural Graph：把程序知识存为 (procedure, relation, procedure) 三元组——知识图谱用 (entity, relation, entity) 回答"是什么"，程序图是它的"怎么做"对偶。运行机制三件套：(1) 每步定位 agent 当前所在的活跃节点；(2) 引导模型把邻域子图转成步骤级引导，偏置但不强制求解模型的下一动作；(3) 图自进化——LLM 改写器对比失败与成功轨迹后编辑图的拓扑与属性，编辑须保持或提升留出验证表现才被提交，被拒编辑保留在图外以阻止重复犯错。从最小骨架出发，该循环能产出匹配或超越人工设计图的程序图，并能修复有缺陷的专家先验；摘要声称在多数据集、多任务类型、多 LLM 上一致超过基于记忆的基线。

## 解决什么问题

长程 agent 的"过程失忆"：不是不知道事实（记忆系统管这个），而是不知道流程——目标漂移、工具错序、原地打转。现有记忆基线存的是历史/事实，无法约束"下一步该做什么"；提示工程写的流程又僵硬、无法从执行反馈中修正。

## 相比前方法优势

- 相比记忆型基线（历史/事实存储 + 检索）：显式编码顺序与条件依赖，检索出来的是"此刻该做什么"而非"过去发生过什么"；摘要称跨数据集/任务/模型一致增益；
- 相比硬编码工作流/SOP 提示：图可从最小骨架自动长出，可从真实执行轨迹里学到人工写不出的分支，还能反过来修复错误的专家先验；
- 相比无监督轨迹微调：编辑以留出验证表现为准入门槛（提升才提交），自我改进有防退化闸门；保留被拒编辑抑制重复试错——两处设计都比"拿成功轨迹 SFT"克制。

## 局限（如实标注）

- 无代码：arXiv abs 页无任何代码链接（2026-09-09 实抓确认，Comments 仅"36 pages including references and appendices, 6 figures, 11 tables"），全部机制需按正文自实现，引导模型与改写器都额外吃 LLM 调用预算；
- 页面未列作者机构、无 venue（v1 预印本），"一致增益"的具体幅度/统计口径要看正文，摘要层无法独立核验；
- 需要可批量执行的环境来产出失败/成功轨迹对并支撑留出验证——评测环境本身就是先决成本；
- 图编辑的 LLM 改写器是新的失败面：改错图会系统性带偏后续动作（论文以验证闸门缓解，但闸门依赖验证集代表性）；
- 成熟度：paper——"论文存在"不等于"技术可用"，入库口径按机制模式而非即插组件。

## 如何用于比赛

1. **黑客松 Agent 赛道（模式移植）**：作品是多步工具调用 agent（数据管道、运维自动化、研究助手）时，借其架构模式做可靠性卖点——维护一张显式程序图（节点=子过程，边=顺序/条件），每步注入步骤级引导；哪怕只实现"人工建图 + 步骤定位引导"这前半套（无需自进化循环），也已与纯 prompt 链作品拉开可讲性差距，直接回应"长任务会不会乱"的评审质疑。reuse_cost 高：无开源实现，最小可用版（建图+定位+引导，去掉改写器）预估 2-3 天，自进化循环赛期内建议降级为"赛后从日志重放改图"。
2. **Kaggle/数模的 Agent 化管线（远期观察）**：若赛题要求可解释的多步分析流程，程序图天然产出人类可读的流程依据（每步为何这么做可指到图上节点）——等出现开源实现再降 reuse_cost 复评。
