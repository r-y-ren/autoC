## 二、v2 新增项（本轮必须新增的四类）

### 1. 报名核对置顶（§0 强化，对应 man-reg）

- 第一轮遗留未决 → 本轮**第 0 天**人工锁定：打开赛站 Overview / Rules，人工核对 Entry Deadline（官方 API Timeline 为模板变量未解析、无数值——以赛站页面显示为准，截图存档并回填待核台账）
- **前置门规则**：报名（man-reg）未完成，不进入任何提交步骤（man-submit 的第 1 项检查即核对报名状态）
- 团队设置沿用：3 人（上限 5 人内）、单账号纪律（rules 明文禁多账号）、奖池口径核对记录

### 2. 每日 ≤5 次与最近 2 次计入纪律（§3 强化为逐次检查单）

- 每次提交前核对：**当日已用额度 ≤5**（与提交台账计数列联动，防止遗忘性超限）
- **每日收尾提交 = 当日最优版本**（保证「最近 2 次计入」里至少含一个最优版）
- 当日额度用尽前 30 分钟自查：最近 2 次提交是否均需保留？
- 只提交本地检查（§1）全过的版本；实验性提交须对应明确假设与本地矩阵依据
- 台账新增列：当日提交序号（1-5）、是否收尾最优提交

### 3. 天梯反馈回填 metrics 流程（§4 新增）

- 每日观察窗口：记录本队 skill rating 与近期对局结果 → 按 `workspace/docs/metrics-keys.md` 键名转录至 `workspace/metrics.json`：`online_ladder_games` / `online_skill_rating`（未发生如实 null）
- 回填触发校准：若线上评级 / 对局形态与本地池明显背离 → 记录校准动作至 `online_feedback_calibration`（替换 / 引入了哪个对手），交 software 侧执行对手池校准
- 口径纪律：天梯高方差，不追单局结论，以滚动窗口趋势判断版本强弱

### 4. 终交前「最近 2 份最优」锁定检查（§6，对应 man-final）

- 终交日（09-30）**禁止新增实验性提交**；如需最后调整，最后两次提交都应是最优候选
- 最近 2 次提交 = 台账最优候选：**commit hash 双核对**（赛站 Submissions 页 vs 本地台账；终版对账键 `metrics.software.final_submission_commits`）
- 两次计入提交的 Validation Episode 均 Passed
- 核对完成由队伍人工签字确认（man-final 验收留痕）；此后榜单 10-01 起自动跑对局至收敛，无法再改提交
