# V56PACK1 — the two-kernel runtime (KERNEL2) and candidate package vrp13_v56gate

**Status: BUILT and PROVEN byte-exact to the MELONHYBRID3 harness on the seats tested. CANDIDATE ONLY.** Not uploaded, not merged to master. It ships only if MELONHYBRID3's `gated` cell and GATE2 pass.

## Design

The runtime is the production form of `S/melonhybrid3/hybrid.py HY_MODE=gated`, with no harness wrapper.

- **Switch:** `plan.KERNEL2_ON`, default False. Its knobs are in plan.py next to ENGINE_GATE:
  - `KERNEL2_CASH_MAX = 2550`
  - `KERNEL2_H0_MERGE = True` (the MH3 v56h1m form)
  - `KERNEL2_PFS_SHIFT = True` (the MH3 pfsh1 form)
  - `KERNEL2_PRELOAD = True`
- **Entry point:** `Runtime.act(obs, config=None)` in `src/kagg3/agent/runtime.py`. When the switch is ON, `_kernel2` runs first.
  - **Step 0:** returns the engine no-op `{"farmer":["PASS"],"hands":[],"market":[]}` on every seat and resets the per-game latch. With PRELOAD on, it also loads a fresh V56 kernel. The load takes about 0.17 s, which moves that cost off the step-1 turn.
  - **Step 1 (latch):** reads the rival's cash, `obs["farms"][1-player]["money"] <= 2550`, which is the same field the harness reads.
  - **Gate fires (`v56`):** the embedded V56 kernel plays every later turn. At step 1 it is first shown the h1 obs relabelled as step 0 / hour 0. Its h0 market rows then go ahead of its h1 rows (cap 10), and farmer and hands come from the h1 call. This is the v56h1m form.
  - **Gate does not fire (`pfs`):** PFS continues. On d0 it is shown hour-1 / step-1, so its d0 plan is built at our h1 and played one hour late. From d1 h0 it is unchanged.
  - **PFS state:** nothing in PFS runs at step 0: tell.observe, the plan cache, the ENGINE_GATE latch, the route_vrp bank and the program engine all stay untouched. PFS's own step-0 resets (vrp_saved, ENGINE_GATE day<1) fire at its shifted step 0, which is exactly what the harness does. On V56 seats PFS is never called again.
- **Kernel file:** `src/kagg3/agent/v56kernel.py` is `S/v56leg/main.py` verbatim (sha256 a1ad0fd1…, Apache-2.0 notices intact) with one provenance line on top: the public notebook "V56", kernel 135260056, script version 351622802.
  - `runtime.kernel2_load()` loads it the way `kaggle_environments.agent.get_last_callable` does: `compile("<string>")`, exec into `{}`, take the last callable (`e410_agent`).
  - It is exec'd, never imported, so each game gets its own namespace and V56's module-global state is per game.
- **config:** `make_agent` now passes `config` through to `act`, because the kernel reads configuration.
- **Packaging:** `scripts/package_submission.py --kernel2` adds `kagg3/agent/v56kernel.py`. It also swaps exactly one main.py line, `rt.act(observation)` → `rt.act(observation, configuration)`.
  - The flag is required if and only if the tree's `KERNEL2_ON` default is True (parsed with ast). A library call to `build()` follows that default.
  - An OFF build differs from vrp12_pfs only in runtime.py and plan.py (30/30 members; `res/pkg_off_vs_vrp12.txt`).
- **Not built: the ZERO hook.** A d1-dawn switch from V56 back to PFS when the rival shows 0 MELON at d1 h0 would go in `Runtime._kernel2`, at the first step >= 24 with `k2_mode == "v56"`. It is marked `[HOOK, not built]` in `act`. From that switch on, PFS would plan d1 on a farm V56 built on d0, the MH2 "v0pfs" body.

## What KERNEL2 gives up on ZERO seats

- The gate fires on all 7 ZERO seats of BAND142. For ZERO, rival h1 cash is ≤ 2,550; 6 of the 7 are one clone at 488.
- There the V56 kernel wins 1/7, against 5/7 for PFS (MH3 cell C: v56h1m on ZERO = 1/7).
- The package therefore gives up up to 4 wins on ZERO. MH3 also has pfsh1 on ZERO at 3/7, so the shift costs PFS about 2 of those wins even without the gate.
- The d1-dawn switch-back hook above is the only way to recover them. It has not been built or measured.

## Not proven

- **Coverage:** only 2 seats and 7 games. The full gated cell on BAND142 (MH3 `gated`, running) and GATE2 are the ship gate. Projection per MH3: W 91→105, flips +23/−9.
- **ZERO cost:** up to −4 W on the 7 ZERO seats (see above).
- **V seats:** they now run PFS shifted one hour. That is 17/20 on MH3 cell B (= PFS 17), not the unshifted PFS.
- **Timing:** step times come from one loaded local box, not Kaggle hardware. The margin is about 2x on the worst PFS turn.
- **Gate outside BAND142:** the 2,550 cash gate has not been validated beyond BAND142. A rival that spends its d0 h0 cash on something other than melon, or whose h0 opener differs from these families, gets the V56 kernel.
- **Live engine:** `tests/test_submission_runs.py`, which plays starter/random for 16 games, was not run, to stay inside the game budget. No live-engine game against a reacting V56 was played with the package.
