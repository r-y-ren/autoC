# LIVEB: a fully out-of-sample live-board leg

LIVEB is a second held-out live-board leg, disjoint from every existing judge
and training set, so candidates selected or gated on LIVE62/LOSS20/LIVE55 or
trained on any flow16x-17x rung can be read on boards nothing has touched.

## ids

`S/liveb/ids.txt` (6 ids, ascending): 106581754, 107172667, 107172903,
107181731, 107182682, 107191952. Built from all 208 `artifacts/tape_actions_town/*.npz`
ids minus the union of:
- `S/live62/ids.txt` (62 ids, the LIVE62 judge leg)
- `S/loss20/ids.txt` (20 ids, subset of live62)
- `S/livewin/live_heldout_ids.txt` (55 ids, subset of live62)
- every `--tape-actions` id in `docs/strategy/*launch_flow1[6-9]*.sh` (147
  training-rung ids across the flow160-179 launch scripts)

202 ids excluded from 208 total; the 6 remaining all have both an opponent
package (`artifacts/panel_opp_town/opponent_tape_<id>/main.py`) and a pinned
town schedule entry in `S/band2100p/town_schedules.json` -- `S/liveb/no_town.txt`
is empty, nothing was dropped for a missing schedule. Per-id opponent name,
episode time, and our result (from `S/kagwatch/56098262.log` where covered) are
in `S/liveb/provenance.txt`. All 6 are losses or outside the kagwatch log
window -- this leg is loss-weighted, not a 50/50 split; read any PASS/FAIL with
that skew in mind.

## how to run

Base leg (flow135_g350, the LIVE theta -- required before any candidate read):
```
S/liveb/run.sh flow135_g350
```
Candidate leg + verdict against the base:
```
S/liveb/run.sh <candidate-name> [worktree] [theta.npy]
```
Both write `S/lossflip/<name>_liveb.csv`, `S/liveb/<name>.log`,
`S/liveb/<name>.summary` (verdict line via `S/liveb/flips.py <name>`).

## cost

6 ids x 2 seats x 1 seed = 12 games for the base leg. Each game took several
minutes at load ~40 on this host during the smoke test; budget accordingly and
run in the background.

## when it's large enough

n=6 is too small to trust a PASS/FAIL alone (MIN_POSITIVE = n/2+1 = 4,
|t| >= 2 -- a handful of boards can flip the verdict). Treat LIVEB as
directional evidence, not a gate, until it reaches >= 15 boards; append new
post-freeze tape cuts to `S/liveb/ids.txt` as they accumulate rather than
rebuilding it, so paired seeds for already-played ids stay stable.
