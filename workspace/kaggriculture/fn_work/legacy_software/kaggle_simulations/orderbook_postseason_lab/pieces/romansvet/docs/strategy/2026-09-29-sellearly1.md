## 2. The switch (`SELL_BY`, worktree branch sellearly1, commit f0d8a7b4)
- **No existing switch does a per-product day of sale.**
  - `SELL_SPREAD` is the opposite: a cap on each day's sale.
  - `WOOL_FIRST_SELL` sets hold 0 for wool only, and needs `WOOL_FIRST_ON`, which also changes the herd.
  - `CARROT_EARLY_HOLD`, `FERT_FLOOR` and `MELON_DENY` are floors that hold more, not less.
  - `MACRO_EXEC` moves the lot hour, not the day.
- **`SELL_BY="PRODUCT:DAY/PRODUCT:DAY"`** (default `""`). In `_sell_hold`, from DAY on the product's reservation is `SELL.LIQUIDATE` (the terminal-day law).
  - So the day's existing lots (`SELL.allocate`, same rows, same `avail`) sell the whole dawn shed of that product.
  - It also covers the provisional (BUY_LAND) allocation, which calls the same function. Nothing else moves.
  - `/` separates the pairs because the switch string is comma-separated.
- **OFF = bit-identical.** With `SELL_BY` unset, `_sell_hold` returns early, as before.
  - The worktree + vrp20 OFF string reproduces REACTCLONE1's banked `pfs` rows on 3 boards x 2 seats (ours / theirs / o240 / o432 all equal, `res/id_off.csv`).
  - Its flood control reproduces JUDGERIVAL2's `jr2_pfs_fl` rows 80/80.
  - Named tests: `tests/test_kernel2_package.py` + `tests/test_package_defaults.py` on the worktree: 8 passed, 1 skipped (the dist/ tarball equality; no dist/ in the worktree).
- **ON fires.** In the smoke (a14, highfrequencyf seat 0 vs flood), strawberry, egg, milk and wool are sold daily from d14, as in the control. Only wool moved: 9 vs 5 units on d17, 4 vs 8 on d18.
