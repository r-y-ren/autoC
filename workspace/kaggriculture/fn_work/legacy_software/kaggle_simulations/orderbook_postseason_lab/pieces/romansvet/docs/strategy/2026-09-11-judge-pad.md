## A. Judge pad for 6,919-gene thetas

### The problem, precisely

`S/lots/policy_lots.patch` appends one block `("lots", (65, 2))` to
`core.policy.SHAPES`, taking `N_PARAMS` 6,789 -> 6,919. The block is last, so a
6,789 theta zero-padded to 6,919 decodes byte for byte (`S/lots/README.md`:
20/20 inertness checks, 19 arrays, 0 differences). But the LAYOUT is a
module-level constant: one python process can only ever hold one of the two.
So the judge has to choose a TREE, and it has to choose it from the theta's
width, before anything imports `core.policy`.

Two failure modes, and only the second is loud:

* **6,919 through `arms-next`** -- `policy.unpack` walks `SHAPES` and stops at
  6,789. The extra 130 genes are silently **truncated**; every leg would run,
  every csv would look fine, and we would be judging a different agent. This is
  the one that had to be closed.
* **6,789 through the LOTS tree** -- `policy.pad` zero-fills to 6,919 and the
  agent is identical, but the judge's B baselines
  (`S/lossflip/flow193_g100_hr_*.csv`) must stay reproducible from the tree
  that made them, so 6,789 must keep routing to `arms-next` unconditionally.

### The routing rule

> **The theta's width picks the tree, and nothing else does.**
> `6789 -> $WTDIR/arms-next` (unchanged, byte for byte).
> `6919 -> $LOTSWT` (default `/root/wt_lots`, env-overridable).
> Anything else -> empty, i.e. still a `FAILED` line and never a guess.

The switch string is the same `hr` composition for both widths:
`policy_lots.patch` adds no switch, and the block is inert at zero.

`watch.sh --legs <name> <theta.npy>` passes the theta path through unchanged;
`legs_for_theta` does the width read and hands `$wt` to all five leg runners,
which already accept it. So the whole autojudge change is **two `case` arms and
one variable** -- no runner, no fetch path, no state file, no leg csv moves.

For `screen.py` the tree must be chosen before `sys.path` is decided, so the
patch reads the leading dimension straight out of the `.npy` **header**
(stdlib, no numpy load, no worktree import) for every `.npy` on the command
line. Mixed widths in one invocation are a hard error -- one tree decodes one
layout. `KAGG3_WT` overrides. It prints the tree it chose.

## B. Drawn-shop rung census (flow209)

The shop-draw CRN only bites where the end-of-day shop is **drawn**;
`sim/eod.py:unlock_shop` lets a recorded town override the draw outright, so on
a pinned board the treatment is a no-op. Built by live construction of the real
`Trainer` rung code (not a static read) -- see `S/shopcrn/census.md` for method
and `S/shopcrn/census.py` for the script.

| rung class | episodes / gen | shop | fitness weight | share |
|---|---:|---|---:|---:|
| pinned tape rungs @ `--rung-weight 4` | 61 | PINNED town | 488.0 | 39.10 % |
| pinned tape rungs @ `--rung-weight 10.2` (top-ten) | 20 | PINNED town | 408.0 | 32.69 % |
| pinned tape rungs @ `--rung-weight 2` | 85 | PINNED town | 340.0 | 27.24 % |
| self-play (pool / theta) | 12 | **DRAWN shop** | 12.0 | **0.96 %** |
| **total** | **178** | | **1248.0** | 100 % |

* **12** episodes have a drawn shop, **166** have a pinned town.
* Drawn share of fitness weight: **0.96 %**.
* `--episodes 179 --pinned-once` gives 166 pinned rungs x 1 episode plus
  `max((179-166)//2, 1) = 6` residual pairs = 12; **178 of 179 budgeted
  episodes are played**, the 13th lost to the odd pair split.
* All four non-tape archetypes sit at `--rung-weight 0`, so after `drop=pin`
  the residual weight vector is all-zero and `opponent_index` takes its
  `arch_frac 0.0` path: every one of the 12 residual episodes is self-play.
* No tape has an all-`NO_UNLOCK` town row, so none falls back to the draw.
* `launch_flow209.sh` **already passes `--shop-crn`** (inherited from the
  flow187/flow206 line) -- the flag is on today and is a no-op on 99 % of the
  objective mass.

**SHOP_CRN worth a run on the flow209 recipe: NO** -- 0.96 % against a 25 % bar.
The corollary matters more than the verdict: the flow209 objective is 99 %
pinned, so the +/-25k YARN_STORE shop lottery is **not** the ES noise floor on
this recipe. Whatever noise remains at B is not the shop draw, and the
shop-CRN caveat in consensus s.82 can be closed for the flow209 family.
