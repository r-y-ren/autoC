# JUDGEALL1: one command for the whole GATE2 judge of a KERNEL2-style candidate (2026-09-28)

Code: `S/judgeall1/`: `judgeall.sh`, `ja_lib.py`, `ja_leg.py`, `ja_ctl.py`, `ja_judge.py`, `mkboards.py`, `boards/`, `base/`, `runs/`.
Nothing new was built into the engines. `ja_leg.py` imports the S/gate2legs1/leg.py production runner, which goes S/bandleg1 → ml1leg → nonv1: `LE.SWITCHES` + the switch string, head_940, theta7659, route_vrp SAFETY_S 1e9 + REPAIR_MS 1e7, actTimeout 600, pinned seed and town, and RG._job scoring. The runtime is imported from the candidate tree through `KAGG3_SRC`. The only addition is the rival's units sold (S/melonvol1/units.py). The JC1 units basis on band seats needs it.

## 1. Command

```bash
cd /mnt/e/_work/kaggriculture3
bash S/judgeall1/judgeall.sh <label> <src_tree> "<switch string>" [workers=2]
# next KERNEL2 candidate (tree on a branch carrying the KERNEL2 switches, e.g. the ship tree + cherry-pick 2791f8c0):
bash S/judgeall1/judgeall.sh k2h0z /mnt/e/_work/<cand_worktree> "KERNEL2_ON=True,KERNEL2_PFS_H0MERGE=True,KERNEL2_ZERO_CASH=433|1033" 2
```

- **Switch string.** Switches are separated by commas. The gene block splits on commas, so a list value uses `|` (`KERNEL2_ZERO_CASH=433|1033`). Quote the whole string.
- **OFF arm.** `OFF_SW`, default `KERNEL2_ON=False`, i.e. the vrp12_pfs body = live sub 56612145.
- **Source tree.** `<src_tree>` is a worktree root (with `src/kagg3` inside) or its `src/` dir. The script refuses if it finds no kagg3 there.
- **Environment knobs:**

  | env | meaning |
  |---|---|
  | `SMOKE=1` | controls only, then `judge.md` |
  | `SKIP_CTL=1` | reuse a passed `runs/<label>/ctl.txt` (use it for a resume) |
  | `JA_LEGS=band,faithful,…` | leg subset and order |
  | `JA_MAX=N` | first N boards per leg |
  | `JA_CONTINUE=1` | keep running after a kill |

- **Resume.** Rerun the same command. `ja_leg.py` skips labels already in `runs/<label>/<leg>_on.csv`.
- **Output:** `S/judgeall1/runs/<label>/`:
  - `meta.json`
  - `ctl_off.csv`, `ctl.txt`
  - `<leg>_on.csv` + `.log`, and `<leg>_on.killed` when the kill rule fired
  - `judge.md`, rewritten after every leg
  - `progress.txt`, a timestamped line per step with the leg's table row
- **CSV columns:** `arm, leg, label, seed, our_seat, ours, theirs, opp_money_h1, our_noop_s0, their_sold, sec, err`. `opp_money_h1` is the rival's h1 money and gives the gate-fired share.

## 2. What it runs

1. **OFF controls.** There is one seat per leg family (`ja_lib.CTL`): band MELON `tape_highfrequencyf_114080894`, band V `tape_team_114081589`, tapes, faithful, pool, clone, self, dev `v56@0s0`, FRESH `0|813835299|1` and held `150`. Each must equal its banked base row byte for byte, ours and theirs. Otherwise the script prints the DIFF list, exits 2 and runs nothing else.
   - held has no banked base. Its control seat is *seeded* into the shared cache `base/held_off.csv`, and only when every other control is exact. After that it is a real control.
2. **Legs, in order:** band-276 → faithful59 → pool → self → clone → dev → held → tapes50 → FRESH300.
   - **band-276.** The 142-seat fast half runs first (116 MELON + 22 ZERO + 4 OTHER), then the 134 V seats.
   - **Base gaps.** A leg whose base lacks seats (held on first use) first runs the OFF arm into `base/<leg>_off.csv`. That cache is shared across candidates and is valid only while the controls pass.
   - **Kill rules** (GATE2LEGS1), checked after every game: at n ≥ 20, soft t ≤ −2, or on reacting legs a gift (dtheirs t ≥ 2 and soft t < 2). A kill writes `<leg>_on.killed` and stops the chain, because the guard fails and so GATE2 fails. `JA_CONTINUE=1` overrides the stop.
3. **`judge.md` after each leg.**
   - **Per-leg table:** n, W base → arm, flips, soft t, dours (t), dtheirs (t), faithful dtheirs (t), gate fired, status. Band also gets rows per family and per set (BAND142 / HOLD104 / NEW2).
   - **Band JC1 breakage guard.**
   - **A:** band family soft Δθ z.
   - **B:** pooled soft t over dev/held/fresh/tapes/faithful/band/pool, and band Δθ ≥ 0.
   - **Gift:** reacting-pooled dev/held/fresh/pool.
   - **Guard:** legs and band sets with n ≥ 20. Clone and self count, as in GATE2LEGS1.
   - **Verdict so far.**
4. **Final (`--final`).**
   - **Live exposure line:** vrp12 games by class, from S/finalslot1/res/famband.tsv.
   - **BTSIM k-ladder mapping:** k = net flips on the 51 BAND142 MELON seats, plus the all-MELON count scaled to 51, mapped to the nearest S/finalslot1/res/kladder.tsv rung for band-LB and live-GW rank.

## 5. What it does NOT cover

- **The package.** No tarball smoke or Kaggle package run. Use S/v56pack1/pkgsmoke.py and the 30_ship.sh centre-coins check. The runtime is the src tree.
- **Speed.** No timeout or step-time audit (S/v56pack1/steptime.py).
- **Hybrid harnesses.** The MELONHYBRID3 `HY_MODE` path is not used. The production runtime with switches is the only path.
- **held100 base.** It is cached from this stream's OFF runs, with no older banked base.
- **Seat duplicates.** The dev and tapes `|1` / `sf` duplicates of the banked GATE2 bank are not rerun. Tapes uses the `|0` replicate only, as GATE2LEGS1 did.
- **Other GATE2 inputs.**
  - The live-clone and self legs are single-rival (V48 clone, vrp12_pfs) and count toward the guard only, not the pooled figure.
  - The BAND284 "both seats" extension and the reacting-pool cross-play (pool agents vs each other) are not included.
- **Hard metrics.** Hard flips and hard Δθ are printed; per GATE2 they carry no threshold.
- **Power.** It is not recomputed. The S/gate2/power.py OC table applies to BAND142/284, and the band here is 276.
- **Pinned towns.** Every leg uses pinned towns. The shop draw across towns is not resampled.
- **Changed defaults.** If a candidate's OFF arm is not the vrp12_pfs body (e.g. it changes non-KERNEL2 defaults), the controls fail by design. Rebase the banked rows first: run the OFF arm on every leg into `base/`, then set a new `CTL`.
