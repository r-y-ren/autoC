## 2. Horizon logic (what the planner models)
- `valuation.remaining_plant_units` / `new_plant_units` (valuation.py:190). An ongoing crop is valued at `fires_between(t_day, first, interval, day+1, min(pay_day, last_fire))`: **tomato's 4 production nights are modelled and truncated at the horizon, not just maturity.** A one-time crop gets the clamped harvest units `clip(pay_day - t_day, first, sat)`. `can = t_day + first <= pay_day` (pay_day = 29 under HORIZON_DROP_ON).
- These units drive the Macro seed ask (plan.py:10591 `u_new -> _candidates`, then `_ask_fill` "past-horizon seeds are refused", plan.py:8163). The brain's `can_mature` gate (brain.py:1230) is maturity-only, but the Macro values multiply the truncated unit count, so a d21 tomato is bid at about 2 fires, not 4.
- ENDFIX1 / LATE_EXEC (`_final_slots`, plan.py:7686) frees a spent ongoing tile (day >= last fire, t_yield 0) for a same-day replant. The replant passes through the same `new_plant_units` horizon, so LATE_EXEC cannot create doomed plantings. The census (shipped LATE_EXEC_ON) confirms this.
- ENDFAMILY/DROPHARV already measured "futile late work 0.0". This census re-confirms it on the current tree: the few doomed plantings are d27-28 wheat and carrot that die unwatered or are left standing.
