# PIPELINE2 — the operator loop, run instead of read

2026-09-19 10:16-10:45Z, branch `master`. PIPELINE1 shipped `S/pipeline/` and `docs/PIPELINE.md` as a
set of wrappers over tools that had each produced a number, but most of the wrappers had never been
executed end to end. This pass ran them. Every claim below is a run with a timestamp; everything that
did not run is marked UNVERIFIED in the manual's own table rather than described as working.

## What ran

**`05_refresh_opponents.sh` — end to end, 10:22-10:30Z.** `MINRATING=2700 MAXEPS=5 P=2 … 3`: the
ladder top 3 resolved (Majkel1337, Unknown Mother-Goose, ymg_aq), 304 of our own episodes were read
across both live subs, 5 new boards selected on rating alone (2,804.2-2,863.8, 3 wins 2 losses), 5
replays downloaded at ~32 MB, 5 cut at the OPPONENT seat both drawn and `--with-town`, all 5 verified
by `build_fresh.py`, town registry 941 → 946, `S/winjudge/{fresh_ids.txt,town_fresh.json}` written.
Then `LEGS=fresh` on the shipped theta banked the base rows.

**The one bug it found.** The script's own footer told you to bank those rows under the label
`ship7692_fresh`. Every report reader opens `S/lossflip/<BASE>_<leg>.csv` with `BASE=ship7692`, so
that label lands at `ship7692_fresh_fresh.csv` and the pairing reports a missing base — the rows are
right and the name is not. The footer now says `ship7692`, with the reason, and notes that
`report_hiband.py` writes `summary_<leg>.txt` so re-using the label cannot clobber the banked
POOLED278 rows.

**`10_train_remote.sh` — reconciled with REALES5 and probed, 10:24-10:27Z.** The script emitted a
launch that the working line does not use: no `KAGG3_ART` (so `reales_clone.py` would have opened a
`/mnt/e/...` path that does not exist on the host), no `--python` (the trainer shells out per board and
the system `python3` has no `kaggle_environments`), no `CUDA_VISIBLE_DEVICES=`, stdout to a stray
nohup file, and a staging step that `rsync --delete`d the whole alphafarm `S/` over a stage that is
deliberately trimmed and then pointed `$STAGE/artifacts` at `~/kagg3/artifacts` instead of the
self-contained panel of symlinks. It now prints and runs the reales5 command field for field,
verified with `DRYRUN=1`, and stages the self-contained tree: `src` `scripts` `pyproject.toml`, the
trainer, `drainpin`, the two 28-board id files, the town registry, the banked ship rows,
`panel_nb/v48`, and 56 opponent dirs recreated as symlinks on the host.

`SMOKE=1` adds the reales5 1-board probe — `--gens 0 --max-train 1`, no `--assert-base`, because the
base cell is a 28-board number and asserting it against one board fails by construction. Run against
the live stage at 10:26Z it played both seats of one board: centre WINS 1/1 train, 1/1 hold.

**The staging refusal.** `10_train_remote.sh` will not rsync while a REALES run is alive on the host,
and says so. A live run's workers re-import `$STAGE/src` on every board, so replacing those bytes
mid-run silently changes the fitness it is measuring. `RESTAGE=1` overrides it.

**`11_train_status.sh` — verified on both live runs, and it had a real bug.** It read remote
`flow250_clone` (log tail, `BASE CHECK … PASS`, pid 1791886) and local `flow249_clone` (pid 91616).
But its PID list matched on the command-line text `--run <name>`, and both a `bash -c` wrapper and the
`ssh` that launched a remote run carry the whole launch string in their args — so "TO KILL" printed
the pids of the operator's own session. It now filters on `comm`, the process's own executable. The
house rule against `kill $(pgrep -f …)` exists because of exactly this failure mode, and the script
that was supposed to make the rule safe was reproducing it.

**`25_clone_leg.sh` — base rows banked, 10:22-10:36Z.** `S/lossflip/ship7692_v48.csv`, 56 boards, 112
rows, WORKERS=4, 14 min. Until these rows existed the leg's comparison block printed `CLONE BASE/CAND
MISSING` and the leg measured nothing. The Δ path was then proved on a 12-id prefix (prefix, because
`--seed-per-opponent` draws seed(i) = base + 1000003·i from the id's position, so the first twelve ids
keep the seeds the base was played on; a reordering would be a different board set). The `reales244`
centre the task named no longer exists on this box — only its `summary_pool511.txt` survives — so the
candidate was the padded shipped centre, and the Δ is the tie-to-the-coin it should be.

**`loop.sh` — one real cycle, 10:32-10:37Z, and `ledger.tsv` has its first row.** Two modes are now
documented and the reduced one was run: `JUDGE_ONLY=<centre>` skips the launch, the wait and the
checkpoint pick; `LEGS_ONLY=hiband` puts the bar on one cell. The cycle judged
`S/heades/centre9273.npy` — the shipped body with a zero macro head — on a 12-board hiband prefix and
read **+0 on every board, 24 rows, flips +0/-0**: the padded centre plays the shipped package to the
coin, which is the loop's own tie-to-the-coin self-test. VERDICT REJECT (t is nan on a zero
difference), promoted no, ship_ready no, one ledger row written. The SHIP bar is not merely failed in
a one-cell cycle, it is **not evaluated** — a 56-board leg is not a 511-board read and JOINTFREE2 is
the standing warning about reading flips off whichever leg was already banked.

`loop.sh` also defaulted to `FITNESS=tape` while `10_train_remote.sh` defaulted to `clone`, so the
loop would have trained the fitness CLONEES1 measured at −245/board against the clone while the manual
claimed otherwise. Both now default to `clone`.

**`00_env.sh`** 10:32Z: 8 PASS, 0 FAIL. **`40_livewatch.sh`**: the trajectory game counts in the

## What is still UNVERIFIED, and why

## The lesson

Four of the six scripts run here were wrong in a way that reading them would not have shown: a
launcher missing the two environment variables that make the remote tree self-contained, a status
reader offering to kill the operator's own shell, a leg whose base rows had never been banked so every
future comparison would have silently measured nothing, and a banking instruction whose label put the
file where no reader looks. A wrapper over a tool that works is not itself a tool that works until it
has been run once.
