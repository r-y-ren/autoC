## 2. Complete grid, Stage A: 108 cells x first 40 MELON band seats = 4,320/4,320 games (100% coverage, 17 min)
Cell = `c<CAP>_k<CARE>_w<WATER1>_m<M3>_f<FEEDFLOOR>`, with GUARD=1 and END=1 fixed, r4c params, greedy. Knob definitions:
- **CAP**: 90 = the existing `caps90.json` (teacher per-day p90).
  - 60 / 120 are **scaled from p90**: floor(x 60/90) and ceil(x 120/90) per key per day (`agent/caps60.json`, `caps120.json`).
  - They are scaled because no caps generator exists in the repo and the teacher npz were not re-read under the budget.
- **CARE** 1/2/3: the BCBODY3 caretaker levels.
- **WATER1**: in the guard, water only plants that die tonight.
- **M3=0**: the r4c params are model3 params, and the r2 non-sequential path cannot load them. In the python engine that path raises every turn, so the agent PASSes all game.
  - M3=0 is therefore defined as **model3 with the coordination inputs blanked**: no earlier-unit claims, destinations or counts, and no previous token. Legality claims are still enforced.
- **FEEDFLOOR (new, added to the caretaker copy)**:
  - While standing animals are unfed and not yet targeted (h2-h22), at least F units are kept on herd duty each step.
  - Duty is filled by preempting working units, nearest first. Units doing FEED, WATER, PLACE, PICKUP or BUILD are never preempted.
  - A unit carrying wheat walks to the animal and FEEDs; one without wheat fetches up to 4 wheat from the shed.
  - F=0 is byte-identical to the old caretaker (proven: the default cell equals the ladder rows).
