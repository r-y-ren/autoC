## The finding that changes the brief

The import-order defect does **not** make a pin fail. It makes it *incapable of
failing*. A pin module doubles as a `--digests` script; run as
`python tests/test_x.py --digests <tmp>/src` it must print the digests of the
**archived** tree. The shared fixtures (`tests/test_budget_order.py:24`,
`tests/test_route_early.py`) do their own `sys.path.insert(0, "src")` and import
`kagg3` on the way in, so any module that imported a fixture before `kagg3`
loaded a *different* tree into the subprocess and compared the tree with itself.

Measured, before the fix:

    $ python tests/test_carrot_hold.py --digests /tmp/nonexistent/src
    early 12326457fd823dfc      # a path that does not exist, and it still printed

and the tree it actually loaded was `/mnt/e/_work/kaggriculture3/src` -- the
**master checkout**, not even this worktree. Eleven subprocess pins were reading a
tree nobody chose. After the fix the same command raises
`AssertionError: the pin loaded ..., not the tree under /tmp/nonexistent/src`.
