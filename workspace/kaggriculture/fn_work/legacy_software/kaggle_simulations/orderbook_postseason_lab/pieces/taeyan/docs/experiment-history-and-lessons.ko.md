## 5. 평가·구현·기록에서 반복하면 안 되는 오류

10. **동명이인 소스.** 이전 MX2 평가의 `state/o_dev/v48_public.py`와 현재 `state/o_dev/v48_clearqueue_public.py`(4b540288…)는 다르다. 전자의 32/32 결과를 현재 V48의 약함으로 인용하지 않는다.
11. **낡은 결론.** “강자는 모두 순수 planner”, “공개 라우터가 많으니 상위권도 모두 tape”, “우리 tape 우위는 exact0뿐”, “base19가 공식 champion이므로 실전 최강”은 이 자료로 일반화할 수 없다. 정책 파일·상대·시점별로 말한다.
12. **연대와 상태.** O 원장의 일부 09-18/09-19 시각 표기는 실제 09-17로 정정됐다([회고](../reports/o-recap-2026-09-17-18.ko.md)). C 원장의 준비/미실행 상태 뒤에 O 원장의 결과가 이어지는 경우도 있다. 최신 날짜라는 이유만으로 더 정확하다고 가정하지 않는다.
13. **운영 사고.** 중복 제출·취소 직전 서버 접수 이력이 있다. 이번 문서가 제출 권한을 주지 않는다. 현행 owner-only 제출, 동결 파일 보존, 단일 캠페인·러너 워커 계약을 따른다.

## 6. 다음 실험을 제안하기 전에 적을 최소 기록

아래를 후보 메모에 먼저 적는다. 같은 효과를 이름만 바꾸어 재시험하지 않는다.

```text
관찰한 실패: 경기/좌석/스텝과 실제 손실, 근거 파일
부모와 실행 경로: 파일/해시, 활성 스위치, 정확한 상대 소스
가장 가까운 선행 실험: 이 문서 ID + 원문 위치
그때의 상태: 음수 / 무동작 / 파손 / 미실행 / 채택 / 보류
이번에 달라진 원인: 부모·실행기·제약·정보·상대 중 구체적 변화
예상 행동 차이: 첫 분기와 보호할 현금·타일·일손·후속 작업
반증 조건: 발동했는데 어느 지표가 어떠하면 종료하는가
평가 범위: 개발/별도 확인, reacting/frozen, 세계 모드, own/상대/margin/승패
```

- 선행 실패 원인이 그대로면 기존 결과를 재사용하고 실험을 늘리지 않는다.
- 파손 수정이나 새 실행기로 재시도할 때는 “새 가설의 성공”과 “옛 실험의 유효한 재검증”을 구분한다. VRP 전환 뒤 예전 상위 규칙이 살아난 사례가 있으므로 영구 금지 목록으로 쓰지 않는다.
- 증거가 부족하거나 서로 충돌하면 **미확인**으로 남긴다. 계획 문서·후보 파일 존재는 실험 완료가 아니다.
- 결과가 나오면 가장 가까운 항목에 부모·판정·원문 링크·재시도 조건을 추가한다. 모든 작성자의 실제 작업은 [HANDOFF 단일 원장](../HANDOFF.md)에 남긴다. 로그 전체를 다시 복제하지 않는다.
