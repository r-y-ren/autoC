# c300 — 우승 경로 재설계와 평가 감사

## 목표와 판단 범위

목표는 특정 구조의 정당화가 아니라 변화하는 Kaggriculture 상대를 이겨 리더보드 1위를 달성하는 것이다. 기존 숫자는 과거 표본의 기록이다. V48의 공개 점수나 우리 최고점으로 현재 강함을 주장하지 않는다. “상위권은 어떤 구조”라는 분류도 원본 정책 또는 관측 행동 이상으로 확정하지 않는다.

이 문서는 Codex c300의 가설·감사 설계를 모은다. 현재 결과와 모든 작업 기록은 [HANDOFF 단일 원장](../HANDOFF.md), 선행 실험은 [공통 이력](experiment-history-and-lessons.ko.md)을 본다. 기존 소스·캠페인·시드 계약은 그대로 보존한다.

## 구조 선택 가설 — 아직 결론 아님

- 고정 tape: 실행 품질의 기준선으로 쓸 수 있으나 가격·경로·현금 교란과 공개 대응에 취약할 수 있다.
- 고정 턴 분기: 경제 묶음을 안정적으로 실행하기 쉽지만 분기 밖 상태 복구와 새 상대 적응에 한계가 있을 수 있다.
- 매 스텝 반응형/planner: 상태 변화에 대응할 수 있으나 근시안 목표·예측 오차·재계획이 투자 사슬을 깨뜨릴 수 있다. 과거 base19의 실패는 모든 planner의 실패 증명이 아니다.
- 검토할 통합 가설: **검증된 실행 계획을 상태·자원·마감 조건을 가진 계획으로 표현하고, 상대 불확실성을 고려해 필요한 부분만 변경**한다. o209/o214/o233/base20-F와 개념이 겹친다. 새 구현 전에 그들과 다른 실행 동등성·인계 계약·전체 경제 비용의 근거가 필요하다.
- 구조별 우승 확률을 현재 자료에서 숫자로 추정할 근거는 없다. 기존 기준선의 실행 신뢰성과 현행 상대에 대한 실패를 확인한 뒤 첫 개입을 선택한다.

## 감사 1: 공식 실행과 고속 실행

실행 전 고정 질문:

1. 같은 소스·seed·좌석에서 native `env.run`과 `fastgame.play(deep=True)`가 관측·행동·종료 상태·현금을 동일하게 만드는가?
2. 기존 `proxy_eval.load_agent`와 공식 `build_agent`의 차이가 결과를 바꾸는가?
3. 정책이 전달받은 관측을 수정해 고속 실행의 공유 상태를 오염시키는가?

범위: base19 동결본, V48 clearqueue, o239_50의 소수 개발 세계·양좌석. 7000/7001은 이미 관측된 개발 자료로만 사용한다. 보호 blind 미사용. 각 실행은 독립 프로세스, 8워커 이내, 전략 환경변수 제거, 기존 캐시 읽기/쓰기 없음. 남은 시간 관측은 벽시계 영향 때문에 동일성 해시에서 제외하지만 실제 오류·종료 상태·호출 시간은 별도 기록한다.

판정: 차이가 한 번이라도 나면 최초 관측/행동 차이와 실제 원인을 찾는다. 일치해도 이 표본 밖의 모든 정책·모드·과거 캐시까지 안전하다고 선언하지 않는다. QA 경기로만 기록하고 전략 개선 증거로 세지 않는다.

정적 점검 단서:

- `fastgame.view`는 엔진 내부 리스트/사전을 공유하고, deep 실행은 schema/structify 및 공식 시간 관리를 우회한다. 기존 check는 주로 현금·일별 현금 비교이므로 완전한 행동 동일성 증거와 구분한다.
- `proxy_eval.game_key`는 실행기/로더/support 코드와 native/fast 모드를 포함하지 않는다. 따라서 기존 캐시만으로 실행기 변경의 동일성을 검증할 수 없다. 과거 결과가 틀렸다는 증거는 아직 아니다.
- 정식 runner는 소스·엔진·support 계약과 실제 오류/행동 해시를 기록한다. 이 계약은 바꾸지 않고 감사 도구를 별도 작성한다.

## 이어서 확인할 것

### c300 첫 구현: 이동 중 첫 작업만 유지하는 VRP (개발 시험 전 고정)

- 부모: 동결 base19 `state/o_dev/p000_base19.py`. 이는 개발 실험 부모이며 현재 최강 부모로 지정하는 것이 아니다.
- 관측: V48 실행 상대, 개발 7000/7001 양좌석에서 이동 직후 아직 유효한 작업을 다른 작업으로 바꾸는 횟수가 경기당 455–553회다. 반대 방향으로 즉시 되돌아가는 이동은 14–29회로 훨씬 적다. 재배정 자체가 손실이라는 증거는 아니며 개선 상한도 아직 모른다.
- 가장 가까운 과거 시도: `vrp_persist`는 남은 전체 경로를 예약하고 다시 최근접 정렬하여 신규 작업을 밀어냈고 −18k로 기록됐다. c300은 **직전 명령이 실제 목표로 향한 이동이고 필요한 물자를 이미 소지한 첫 작업 하나만** 예약한다. 완료·소멸·새 날짜·물자 부족이면 해제하고, 긴급 구조/멜론 러시가 생기면 기존 배차로 돌아간다. 남은 경로는 매 스텝 재계산한다. 구매·생산 목표·판매 정책은 부모를 유지한다.
- 구현 후 같은 4개 개발 조건에서 off 동일성, 실제 발동, 이동/수확/급식/비용/own/rival/margin/승패를 확인한다. 이것은 독립 확인·승격 증거가 아니다. pooled margin 또는 own이 음수이거나 실패 원인이 더 큰 예약 손실이면 넓은 평가 없이 중단한다. 양수여도 작은 이동 최적화 효과만 있으면 이를 #1 경로의 구조 개선으로 과장하지 않는다.
- 후보 변경은 별도 파일로 남긴다. 정식 확인에 도달하면 native runner와 반응형 복수 상대를 사용하고 seed 단위로 집계한다. blind는 아직 쓰지 않는다.

### 현재 상위권 녹음에서의 부모 진단 (실행 전 고정)

- 대상: c300에서 받은 현재 4개 제출 × 최근 2900+ 상대 3경기(12행, 고유 episode 11개). 각 지정 상위권 선수를 녹음대로 두고 반대 좌석을 base19/V48/o239로 교체하는 36개 진단.
- 기존 `replay_lab.evaluate` + `championship_phase1.launch` 재사용. 원본 전체 상태 재현에 성공한 exact accounting 기록으로 원본 재현 캐시만 준비한다. 원본 seed/설정을 보존하고 상점만 원본대로 고정한다. 후보에는 정상 관측만 전달한다.
- 목적: 실행 가능한 부모의 경제 손실 위치를 좁히는 개발 자료. 표본 선택은 최신 경기 기준이며 후보 결과에 맞춰 바꾸지 않는다. **동결 상대 승률·절대 점수는 라이브 승률이나 부모 최종 채택 근거가 아니다.** 상대의 녹음 현금과 재생 현금 차이를 반드시 함께 본다.
- 어떤 모델에도 자동 승격/gate 없음. 36경기에서 숨겨진 오류/1초 초과/불완전 재현이 나오면 해당 행을 성능으로 해석하지 않는다. 정식 반응형 확인과 분리하며 blind 사용 안 함.

- 소스 해시/캠페인 행을 독립 재집계하고, 같은 세계의 양좌석·동일 계보 중복을 독립 표본으로 잘못 세지 않는지 검사.
- 현재 공개 리더보드와 시각이 남는 라이브 목록을 소량 수집. 오래된 최고점·경기 후 점수와 현재 점수를 구분. 새 상대 버전은 별도 ID로 보존.
- 과거 calibration의 동일 자료 적합과 미래 예측을 구분. 새로운 상대 계보/시점에서 별도로 검증하며 frozen 경기만으로 반응형 승률을 주장하지 않음.
- 신뢰 가능한 실패 1건에서 상태 복구/계획 선택/시장 경쟁 개입 중 하나를 선택. 작은 개입이 실제로 발동하고 경제 개선으로 이어질 때만 넓은 평가.

### c301: 현장 작업 완료를 VRP 배정에 포함 (개발 시험 전 고정)

- 선행: 옛 비VRP 배차의 `here`/`collect_here`는 현재 VRP 조기 반환 뒤에 있어 실행되지 않는다. c300은 이동 중 첫 목적지를 고정했지만 현장 작업 완료나 투자 사슬을 보존하지 못했다. c301은 이동 예약을 사용하지 않고 **현재 위치에서 물자가 준비된 실제 작업 한 개**를 먼저 배정한 뒤 나머지를 기존 VRP로 배정한다. 새로운 생산 목표/시장 규칙은 추가하지 않는다.
- 기존 긴급 구조/멜론 러시가 있으면 부모 배차를 유지한다. 작업과 일손을 중복 예약하지 않고, 물자가 없는 현장 작업을 강제로 실행하지 않는다. 원래 입고·종료 회수 분기는 유지한다. 따라서 현장 예약과 실제 실행 수를 따로 기록한다.
- 부모는 c300이 아닌 동결 base19. 개발 조건은 V48 실행 상대 7000/7001 양좌석의 상점 고정 4조건. 새 코드 오류·off 불일치를 먼저 점검한다. own/margin 중 하나라도 평균 음수면 넓은 평가를 중단한다. 양수면 V48/o239/K0006에 걸친 별도 개발 블록에서 확인하며, 이 작은 스크린을 승격 근거로 쓰지 않는다. 시드 탐색이나 임계값 튜닝 없이 1개 구현만 시험한다.

### c302: V48 실행 본체에 기존 o178 투자 묶음 재사용 (기전 시험 전 고정)

- V48의 기존 native h2h 패배 3세계/6조건을 `pair_trace`로 재현했고 최종 현금이 모두 기존 기록과 일치한다. 1607321654 대 o239에서는 V48 우유 266u/64160, o239 324u/77987; 1750783264에서는 V48 계란 83u/4637, o239 195u/10722. 상대 공급까지 달라지므로 이 품목 차액을 그대로 개입 이득으로 예측하지 않는다.
- 새 투자 규칙을 발명하지 않는다. 이미 우리 o178/o239에 들어간 `o171e_day6_goose_4`와 `o170c_day10_livestock_milk3`를 V48 위에 기존 `build_overlay.py`로 이식한다. 전자는 알려진 우유 상점이 없는 개막의 소4→거위4, 후자는 알려진 우유 상점3·계란 상점0일 때 d10 거위3→소3이다. 구매·건물·픽업·배치가 함께 바뀌는 기존 묶음이며 숫자를 바꾸지 않는다. V48 자체의 YARN 치환과 충돌/무동작 여부를 실제로 확인한다.
- 이는 **고정 실행 계획+관측 조건부 투자+기존 반응형 시장 처리**의 혼합 정책이다. 완전 상태 플래너 또는 새로운 우승 구조로 부르지 않는다. base19 배차 미세 수정은 중단하고 더 강한 실행 부모에서 경제 선택을 분리해 시험하는 단계다.
- 원본 V48의 최종 callable은 `agent`가 아닌 `_e335_agent`다. 연결용 어댑터는 이 최종 함수만 `agent`로 지정한다. 기존 실행 순서를 생략하지 않는다. 기존 코드·조건·부모 불변, c302만 새 파일.
- 순서: 선택한 우유/계란 손실 세계 4조건의 발동·실제 축군/수입/마진·오류 확인; 기존 7001 양좌석의 비발동 동등성 확인. 실제 처리가 실패하거나 마진 평균≤0이면 종료. 통과하면 별도 개발 블록을 V48/o239/base19와 평가한다. 이미 본 h2h 세계의 성공은 독립 검증이 아니며 blind·승격에는 쓰지 않는다. 3PET 세계의 작물 구성 격차는 이 개입의 해결 범위가 아니다.
- 별도 native screen 계획: 후보/부모 × V48/o239/base19 × 16시드 × 양좌석 = 192게임, 단일 캠페인 8워커. RNG `202609190302`로 screen16/confirm32/final64를 실행 전에 고정하고 screen만 우선 실행한다. 다음 단계 조건은 양측 health 실패0, 평균 승점/마진/own 증분 양수, 모든 상대 family 마진 증분≥−1000, W→L≤L→W이다. CI가 0을 포함하면 불확실로 보고하며 위 조건 통과 자체를 유의한 개선/승격으로 부르지 않는다. 향후 확인도 공개 실행 상대에서의 개선 증거일 뿐 최신 비공개 상위권을 이긴 증거가 아니다.

### c303: V48 본체에 기존 o199c 작물 전환 묶음 재사용

- 선행은 o199c 및 기각된 o232/o234/o235/o236, 전체 대체 경로 c171이다. V48은 이미 V42 이후 경로를 내장하므로 c171을 다시 이식하지 않는다. 현재 확인한 차이는 V48의 원본에는 o199c의 가격 기반 WHEAT→CARROT 전환이 없다는 점이다. 최악 3PET 개발 세계에서 V48 CARROT133u/45307, base19 299u/77311이다. 이 차액 전부를 회수할 수 있다고 전제하지 않는다.
- c303 = 원본 V48 최종 entrypoint + **기존 o199c 모듈 그대로**(가격비2, d8–26, companion seeds·파종 치환·age3 수확·실제 창고분 판매). 기각된 c302의 가축 변경은 포함하지 않는다. 수요 gate 완화·가격비 재탐색·현금 손실 무시를 하지 않는다. 기존 코드의 관측 기반 생산 전환이 더 강한 실행 본체에서 작동하는지 검사하는 재조합이다.
- 기전 스크린: 1692877162/base19 양좌석의 기존 native 손실 재현과 1607321654/o239 양좌석의 비목표 세계. 실제 씨앗 체결·작물·사료/비료 비용·수확/판매·parent 내부 오류를 확인. 평균 own/margin 모두 양수, 기계 실패0일 때만 새 블록 native screen으로 진행. 이 선택 세계는 개발 자료이며 새 확인 증거가 아니다. 원본 단독과 비교하고 모듈 off 별도 QA본으로 행동 동등성 확인.

### c304: 상태 플래너의 중복 없는 식재 타일 배정 (개발 실행 전 고정)
