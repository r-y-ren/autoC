## 실행 결과 추가 — 처음 실제로 학습한 시장 요청 모델

`state/c308/learn_opening_market.py`로 제출56216119의56경기, d0–5의8064행을 학습했다. 전처리는 관측[t]와 이후 action[t+1]을 짝지었고 파일해시/시드/좌석/제출 ID를 보존했다. 승패·미래상점·상대 private·episode/seed/팀명·수집시각은 입력에서 제외했다. 시간대는 실제 관측 가능한 step/day/hour만 포함했다. 클래스는 순서를 포함한 시장 요청목록58종이며 실제 체결이나 최적행동을 뜻하지 않는다.

상대팀7개를 GroupKFold5로 나눠 같은 경기·시드·상대팀의 학습/평가 중복을 배제했다. 팀은 검증된 계보 구분이 아니며, 이미 서술적으로 관찰한 표본에 대한 탐색이다. RandomForest64개/max_depth12/min_samples_leaf4/random_state308/n_jobs12를 실행 전 고정했다. 프로젝트venv에 sklearn1.7.2를 설치했고 학습 알고리즘을 새로 작성하지 않았다. 이번 결과로 파라미터를 다시 고르지 않았다.

- 시각별 최빈 요청 대조: 전체정확도88.84%, 실제 주문이 있는3539행에서79.71%.

- 상대 공개농장 특징 추가: 전체90.23%, 주문행79.71%. 자기+시장 모델보다5경기개선/38악화/13동일. 상대를 실제로 안 본다는 인과 증거가 아니다. 표본·모델·특징 표현과 random feature selection의 영향이 섞인다.
- 자기+시장 모델의 무주문 오예측358건, 불필요한 주문 예측86건. 모든 모델에서144턴 시장요청이 전부 맞은 경기는0/56. 현장 작업 명령은 아직 모델링하지 않았다.

**판정:** 학습 신호는 있으나 현재 분류기를 그대로 동결/제출하지 않는다. 약91% 요청일치가 실제 개막 실행 성공을 뜻하지 않으며, 체결되지 않는 요청까지 정확히 흉내 내야 할 필요도 없다. 같은 학습셋에서 더 큰 모델을 반복 탐색하기 전에 실제 생산 목표·작업 의존성과 실행 실패를 분리한다. 폴드별 모델을 제출물로 저장하지 않았고, 동결한 데이터/예측/설정으로 결과 재현은 가능하다.

산출물: `state/c308/opening_imitation_v1/{manifest.json,dataset.jsonl,predictions.jsonl,report.json}`. dataset 약32MB. 학습관측을 미래 체결 label과 합쳐 입력으로 사용하지 않는다.

## 거래/실행 label 감사와 공통 개막

- 8064턴 중 주문 발생3539턴, 요청 일부/전부가 미체결된 턴409개.

- d1 첫턴 고용 실제인원은3명42경기/4명11경기/5명2경기/6명1경기. 하루전체는4명53경기/5명2경기/6명1경기였다. 예시110648924는현금5에서HIRE5요청→3체결,두턴후비료판매100→추가1명고용. 녹음의 요청수를 계획된 실제고용수로 읽으면 안 된다.
- 현행엔진 고용비는1,1,2,3,…이므로 현금4와5는 추가수입 없이 모두3명까지만 고용가능하다. r001 옛보고의 “4대5 차이 때문에3명만고용→붕괴”는 **현금1차이만으로 인과 설명이 완성되지 않는다.** 해당 옛경기/원본버전의 재현은 이번에 하지 않았으므로 실패 전체가 틀렸다고 하지 않는다.
- `extract_opening_contract.py`로 성공한 PLANT(씨앗변화+타일변화)를 추출했다. 멜론11좌표는56/56공통이지만 일부 완수시점이넓게달랐다: (3,2)는step14–57,(2,3)은11–37. (1,2)는12로동일. 딸기는(0,2) step87–135,(1,1)62–112가공통. 이는 관측된 목표/타이밍의 분리 근거이지 실행 가능한 DAG를 복원했다는 뜻은 아니다.

## 판단

수동으로 작은 규칙을 한 개씩 고치는 방법만으로 #1을 추구하는 것은 탐색 범위와 속도에 한계가 있다. 사람이 실행·데이터·평가 계약을 검증하고, 시뮬레이션 검색/학습이 결합된 경제적 결정을 탐색하게 하는 방향을 우선 검토한다. 딥러닝이 반드시 필요하거나 특정 구조가 우승 확률이 가장 높다는 증거는 아직 없다.

우선 검증할 구조는 **학습하는 경제 계획 선택 + 검증 가능한 실행기**다. 투자·식재·토지·고용·판매의 의존성을 포함한 실행 가능한 계획 후보를 선택하고, 이동·급식·수확은 계약을 만족하는 실행기가 처리한다. 수동 2~3개 미세 노브 선택만 학습하는 것으로 끝내지 않는다. 행동 공간에 좋은 계획이 없으면 어떤 학습기도 해결하지 못한다. 기존 실행기를 사용한다는 이유로 그 경제/실행 정확성까지 보증하지 않는다.

## 가장 가까운 선행 시도와 실제 재확인

- H05/o209: 상태→후보 행동→강제 롤아웃→정책표→실행 구조가 이미 있다. 과거 소수 독립 시드, 폴백 혼입, 일부 표의 음수 성능 기록이 있다. 새 이름이나 신경망으로 바꾼다는 이유만으로 재시도하지 않는다.
- `o_tools/shadow_dataset.py`, `shadow_cf.py`, `macro_compile.py`, `compile_policy.py`와 기존 러너를 우선 재사용한다. 검색한 `tools/o_tools/src/agent` 범위에서 완성 PPO 학습기를 확인하지 못했으며, 프로젝트 전체에 없다고 단정하지 않는다.
- 기존 `o_results/shadow/dataset.jsonl`를 직접 재집계: 788경기, 4,728행, 각 슬롯 1,576행. 모든 행에 seed/submission_id가 없고 rating은 전부 null. 원본 replay와 조인해 복구하기 전에는 시드·제출 버전별 분리나 최신 상위권 학습셋이라고 부를 수 없다. 이 숫자는 학습 성능 결과가 아니다.
- 시간 계약: `SLOTS`는 상태 step150/196/241을 사용하면서 구매 label 구간은144:192/192:240/240:288이다. 기존 재현기 `replay_lab.tape_policy`는 obs step t에 replay step t+1의 action을 사용한다. 따라서 해당 label은 상태 이전/상태 생성까지의 요청을 포함할 수 있다. 미래 선택의 지도학습 정답으로 바로 쓰면 안 된다. 실제 영향 행 수는 아직 측정하지 않았다.
- label은 `BUY_ANIMAL` **요청**의 합계이며 체결 확인이 아니다. 상태에서 요청을 모방하는 학습이라면 요청 label 자체가 틀린 것은 아니지만, 시간 정렬이 필요하며 구매 성공/경제 성과 label로 읽으면 틀리다.
- 승자 또는 Majkel인 행을 골라 요약하는 것은 관찰 통계다. 그 상태에서 그 구매가 승리를 일으켰다는 정답은 아니다. 이 도구의 문제를 별도 롤아웃으로 평가한 모든 과거 정책표의 오류라고 확대하지 않는다.
- `macro_compile.py`: 결과 경로 존재만으로 캐시 재사용(부모/엔진/상대/seed 계약 검증 없음), 개별 경기행 bootstrap(같은 seed 양좌석/상대 간 의존성 미반영), n은 독립 시드 수가 아닌 비교 행 수. subprocess returncode도 확인하지 않는다. 모두 재사용 전 보완 대상이며, 과거 결과가 실제로 오염됐다는 판정은 아니다. 기존 world bank의 dev 범위에는 보호 blind와 겹칠 가능성이 있어 새 실행은 명시적 허용 seed 목록만 쓴다.

## 다음 개발의 순서와 진행 조건

1. 기존 추출기를 별도 버전으로 확장해 결정 직전 관측→이후 요청→실제 체결을 분리한다. episode/seed/seat/submission/source/engine/time을 보존한다. 정책 입력에는 그때 보이는 정보만 넣는다. 사후 상점/최종 승패는 입력 금지. 정상 재현된 원본에서 먼저 시간 정렬을 확인한다.
2. 최신 실행 가능한 여러 정책을 교사/상대로 사용하고 실제 관측 상태에서 실행 가능한 경제 계획들을 비교한다. 리플레이 모방은 초기화/후보 생성용이고, 더 나은 행동의 판단은 실제 엔진 롤아웃으로 한다. 미래 상점이 행동에 따라 달라지는 native 환경을 유지하며 고정 상점은 별도 기전 진단에 한정한다.
3. 우선 작은 가치 예측 모델 또는 정책표로 시작한다. 같은 게임 예산의 무학습 검색·고정 부모와 비교해 학습의 추가 가치를 확인한다. 탐색 후보를 고른 데이터와 별도 seed/상대 버전 평가를 분리하고 seed 단위 불확실성을 산출한다. 학습/평가 계약은 결과 전에 고정한다.
4. 학습 이득과 처리량이 확인되면 과거 정책+다양한 실행 상대+자기대전의 상대 풀로 반복 개선한다. 자기대전만으로 일반 강도를 보증하지 않는다. 주 목표는 최종 승/무/패이며 현금·생산 shaping은 보조로만 사용하고 그 편법을 검사한다.
5. 12 CPU 워커의 실제 games/s·오류율·메모리로 데이터 비용을 산정한다. 효율 저하 시10/8. 곧바로 수십만 경기를 실행하거나 GPU가 반드시 필요하다고 가정하지 않는다. PPO/대형 신경망은 작은 학습 문제에서 일반화 증거를 얻은 뒤 선택한다.

재시도 근거는 구체적인 시간/체결/출처 계약 문제, 기존 희소 표의 지지 부족과 상대 변화다. 이를 수정해도 전략이 강해지는지는 별도 검증 사항이다. 보호 blind7240–7255, 동결 코드/캠페인, 소유자 전용 제출 규칙은 유지한다.

공개 참고: [macro RL+BC 저자 보고](https://www.kaggle.com/competitions/kaggriculture/discussion/741743), [RL 실험 보고](https://www.kaggle.com/competitions/kaggriculture/discussion/740022). 전자는 약30만게임, 후자는 단일 상대 학습 후 다른 상대에서 성능 하락을 보고했다. 독립 재현 결과도 현재 #1 증명도 아니다.
