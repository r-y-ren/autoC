# 第八轮：扩大对抗、研究领先者、筛选可提交策略

目标是尽可能提高下一次提交的稳定胜率，争取3000～3200分。线上反馈尚未产生；本地收益不能换算成该分数。本报告把对抗证据、回放推断和未通过的实验分开记录。

## 先纠正验证方法

上一轮主面板只有6个独立世界，换边后仍然只有6个独立地图。本轮先冻结20个开发世界及40个独立确认世界，另留40个备用世界；源码与对手哈希随每组任务固定。对局使用原版官方环境1.32.7，默认720状态，双方换边。逐局可续跑，双方stderr及已暴露的内部错误都要检查。

统计以世界为单位重采样，同图换边及不同对手不作为独立地图。还必须注意游戏自身的随机数耦合：农场空格决定杂草抽样次数，之后才抽商店，因此策略改变农场，也可能改变相同种子下的后续商店。

主要文件：`league_round8.py`、`compare_round8.py`、`research/round8/PROTOCOL.md`。原始记录为`results/round8_*.jsonl`；不要只看汇总胜率而丢弃失败对局。

## DSM 与 Vadim 的研究结论

新增两队各24场公开研究回放，共48场，另各5场封存。48场原局都在官方环境中精确复现双方金币。这只能证明回放解析与引擎一致，不能说明已复刻两人的私有程序。

两队生产路线会很早分化。第216步，各自24个示范已经对应24种不同农场状态；即使拥有48条示范，也不能仅按商店名称自由拼接路线。工人位置、种植日龄、动物、携带物和投入品必须共同满足衔接条件。

直接照抄原始购买请求也不可靠：原局有大量因资金或条件不足而没有执行的请求。新对手改变市场收入后，它们可能突然成功，造成额外雇工或买入，反而打乱布局。本轮把已成功的采购作为示范合同，保留空槽，再在真实状态下执行。

DSM严格状态兼容代理在20个随机开发世界对v7取得29胜11负，值得认真研究。但另8个世界、三种对手的48局只有28胜20负；它没有在所有对手上占优。最差代表局中出现缺工、缺水死亡和原子播种失败，即使内部fallback计数仍为0。运行正常不能替代生产审计。

工程上已将该研究代理从1,154,164字节减至563,095字节，1438动作逐一等价。官方文件冷加载首动作0.233秒。这个减载不改变策略，也没有被包装成强度升级。

具体资料：`research/round8/top2/STRATEGY_FINDINGS.md`、`research/round8/DSM_CANDIDATE_CROSSCHECK.md`、`research/round8/dsm_candidate_diagnostics/summary.json`。进一步的现金顺序修复单列实验，须验证后才能决定是否采用。

## 主候选的开发结果

选定版本保留v7全部生产与市场基础，加入R148仓库保护、ADV提前出售、IG清空无货卖单；ADV在第696步前结束，让原收官规划接管。19株生产修复通过动态接口接入。

20世界 × 6对手 × 双席，共240局，与v7使用同一任务集配对。平均对战积分提高12.5个百分点，世界聚类95%区间约2.9～20.8个百分点；平均配对金币差改善562.94。这个阶段参与了选择，所以它是开发证据，最终判断另用未参与调参的40个世界。

## 新一轮因果诊断：资金到账顺序

原DSM示范重构程序的三个严重败局不是简单的路线长度问题。第241步开局现金27，两笔雇工依次需要34、55；同回合工人实际运回的牛奶足以卖出筹款，但卖单排在雇工之后，导致先雇工失败、后收到现金。缺少的两名工人恰好负责后来死亡的5株草莓与1株甜瓜。

新分支只在现金不足时，将已计划、物理动作结束后具有可用库存的卖单前置，保留单位动作、购买数量与非卖单相对顺序。三个有意选择的开发诊断分别改善38,832、40,059、43,283本地金币差，两个原赢局不变。这是因果修复证据，不是五个独立泛化样本。

第一份修复源有提交入口错误：重复定义`agent`没有改变Python字典插入位置，官方加载器误选三参数helper。240次联赛尝试全部在正式对局前失败，计为失败执行，**不计240局完整对局**。新源`round8_top2_dsm_contract_entry.py`只补充唯一末尾入口，官方完整720状态、719动作与旧显式策略完全一致。SHA为`23768116945ebd7500b2e2298616ff6dd974d27ce2c839643cc7d3e3d4cada57`，两份源及失败证据均保留。

独立审查还找到了库存投影的动物回仓满仓边界，以及混合买单漏判现金短缺的范围。构造状态确实重现，但24条公开路线17,256步中未发现因此新增的实际损害；它们仍列为限制，而不是以零fallback掩盖。进一步提前草莓购种的局部反事实虽然保住播种，却导致后续小麦取料失败与种子欠量，因此没有加入冻结候选。

详细证据为`research/round8/top2/CONTRACT_FINDINGS.md`、`CONTRACT_REVIEW.md`、`SEED_TIMING_FINDINGS.md`。新候选完成同样240开发局后，只有总体积分至少达到原主候选才进入40世界确认。若两者均进入确认，三组配对比较按预先追加的协议校正多次选择；`assess_round8.py`负责独立判断，`publish_round8_selection.py`仅复制通过的原归档字节。

该开发门槛现已完成：DSM现金修复候选171胜51负18平，积分75.0%；市场融合候选169胜71负，积分70.4167%。DSM修复对六个对手分别为：v6 33/7/0、v7 29/11/0、Orderbook 29/11/0、Master2965 29/11/0、Fieldcraft 32/8/0、DSM严格代理19/3/18（胜/负/平）。它对Orderbook和v7弱于市场融合候选，对DSM严格代理明显更好；总体门槛通过，因此源代码原样进入40世界确认。完整开发报告为`results/round8_selection_development.json`，不能把该选择数据当独立确认。

另外核对了两队真实账号、203个赛事公开主帖及匿名可见Code条目；本次未取得可归属于他们的本赛题方法说明或完整源码。搜索覆盖限制见`research/round8/TOP2_PUBLIC_METHODS.md`。不能把上述重构程序写成“DSM源码”或把另一比赛的技术帖子当成本赛题方法。

下一次线上反馈仍非常关键：本地对手存在共同代码祖先，公开回放代理与真正会自适应的领先者程序有差别。更高胜率是有依据的改进方向，3000～3200必须由线上对战检验。
