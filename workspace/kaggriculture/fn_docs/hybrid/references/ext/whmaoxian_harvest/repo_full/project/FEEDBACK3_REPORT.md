# 反馈信息3与 v6 真实对战审查

2026-09-22。公开对战数据截至北京时间 14:54:11；submission **56416104**。这份分析分别核对了用户上传的自测文件和另外下载的真实排行榜对局。

## 结论

当前瓶颈主要是策略差距。v6 能正常运行，但最近 50 场只有 8 胜、30 负、12 平。小额亏损中存在可以直接定位的冗余种子采购和小麦先卖后买；较大的亏损则显示，固定生产路线没有充分利用后期番茄需求。节省几十或几百金币值得做，但不能据此声称能达到 3000 分。

## 用户上传的文件不是排行榜败局

`反馈信息3/111485103.json` 是 MauoXX 对 MauoXX、seed 0 的提交自测。结果为 71,345 对 72,013 金币，双方 DONE，719 个动作。双方分别通过官方 `get_last_callable` 加载冻结 v6，持续处理全部观测，**各 719/719 个动作一致**。源码 SHA-256 为 `10f58185b916392ca39697c83f67f455df81a74dfb6eb1aacd60fd81d50c9970`。

两份日志均无标准错误输出或超时，最大动作耗时分别 0.648、0.651 秒。原始官方引擎复现后的全部 1,440 个观测一致（仅忽略计时字段），金币也完全一致。只增加观察包装，没有改写引擎处理逻辑。

该自测双方没有仓库溢出，也没有终局未售出产品或可收获产出。两席差额主要是草莓收入相差 709、肥料收入反向相差 41。双方用同一策略仍可能因杂草、路线和市场交互得到不同结果。这不能解释用户提到的真实评级回落。

## 最近四败的具体原因

选取最近四个败局、两个胜局，再加最大败局，共七场完整下载并重放。每场都逐项验证原始观测、最终金币和收支恒等式。

最近四个败局中，我方的全部动作都与冻结 v6 一致。将 v6 放在对手实际获得的观测上持续运行，对手分别有 699、669、714、667 个动作与 v6 相同（分母均为 719）。因此可以说动作非常接近；不能仅凭此认定对手提交了同一源码。

### 冗余胡萝卜种子的可复现修补

111915639 的 seed 为 1820091094。我方终局剩 8 颗胡萝卜种子，对手为 0。双方截至第 646 步的胡萝卜种子买单相同；第 657 步我方买 3，对手只买 1；第 658、662、670 步，我方又买 1、3、2，对手均不买。双方胡萝卜产出收入相同。

实验 `experiments/round7_seed_economy.py` 只在第 648 步以后，统计策略自身固定终局路线、且在胡萝卜替种截止日之前的剩余小麦/胡萝卜播种机会，以此作为未来胡萝卜需求的上界。当前库存已经覆盖这些机会时，裁掉多余的胡萝卜采购，并同步调整父策略的种子采购记账。没有读取真实回放未来状态，也没有禁掉所有胡萝卜采购。

开发种子 1820091094 换席对原版 v6：**两局均多 160 金币**。每局双方胡萝卜播种都是 75 次，实验版最后剩 0 颗种子，原版剩 8 颗。无运行错误，最大动作耗时低于 0.244 秒。这只是针对已观察失败的开发测试；合入前仍需新种子、多种对手和完整发布验证。

## 最大败局：番茄生产规模不足

对局 **111747876**，seed 688041503，v6 以 120,835 对 142,587 负于 yomogii，差 21,752。双方完成正常，v6 没有仓库溢出或终局产品遗留。

第 432 步（第 18 天）已公开的商店是 3 个 FARMERS_MARKET、1 个 PIZZA_SHOP、1 个 BRUNCH_SPOT、1 个 PET_CAFE，已有明确的番茄需求。对手在该天第 436–454 步种了 **19 株番茄**，v6 只种 **10 株**；对手利用三个工人分配新路线，而我方使用两个。

对手最终卖出 152 单位番茄，得到 59,574 金币；我方卖出 80 单位，得到 34,483 金币。仅番茄收入就相差 **25,091**。对手全局人工多花 2,728 金币，种子与其他投入也更多，最终仍有明显净优势。这是按已知需求扩大生产并安排运输、收获的实例，并不意味着任何商店组合都该种 19 株。

冲击 3000 的更大改进应继续研究：在多个番茄需求店出现时，是否扩大第 18 天番茄配置；怎样为新增番茄安排水、肥、收获和卖出；扩大后是否会挤掉更高价值的已有作物。需要用不同商店组合和能反应的强对手验证，不能直接复制这一场全部动作。
