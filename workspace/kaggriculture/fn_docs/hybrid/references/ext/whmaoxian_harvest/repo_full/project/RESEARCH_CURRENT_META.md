## 本轮代码实验

公开 V53 提供更多生产路线、开局识别和对手出售预测。One More Wheat 修改小麦收获时间与闲置工人任务；Pipe16 同样强调工人利用。它们有共同上游，不能把三者当成三个完全独立的算法家族。

另做了一个研究候选 `experiments/v6_top10_market.py`：在 V53 上加入研究组十队的实际成功出售序列。选择依据只使用当前可见的商店、对手农场和过去销售匹配；不读取当前比赛的种子、身份或未来信息。只有历史匹配和农场结构同时满足条件才替换预测，否则保留原策略。研究回放的未来销售仅作为历史样本预测，是否能泛化必须在另一组回放检验。

研究组与验证组按整场 episode ID 分开，避免一场比赛以两个队伍身份同时进入两组。对原回放执行动作时，原始双方最终金币必须精确复现。验证脚本和原始报告均保存在项目内。

**固定动作回放诊断不是与真实前十智能体交手。** 替换一方后，另一方不会重新规划，会产生反事实偏差；因此其胜率只能辅助发现问题。能反应的公开代码对战，以及最终 Kaggle 真实匹配，才是升级依据。各报告还记录席位、种子、完成状态和动作耗时。

## 接下来如何逼近 3000

先保留已经在真实对战获胜的 v5，新增版本必须和 v5、更新公开策略同种子换席对照。扩展样本时按日期、对手和商店组合隔离，尤其检查低价倾销、仓库溢出、末日搬运与资金断档。每次仅保留有独立验证收益的改动。

若规则策略到达瓶颈，再做宏观策略学习：利用每日强手回放做行为克隆，动作采用种植/扩地/雇工/出售计划，再以自博弈和多对手池优化胜负。先建立可靠训练吞吐、验证集与计算预算，再启动长时间训练。本轮没有证据保证任何提交达到 3000；不应把公开作者分数、回放胜率或几局胜利当作这样的证明。

最终本轮实测与发布决定见 `ROUND_RESULTS.md`。
