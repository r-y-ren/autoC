# 雇工路线调度器设计（WORKER ROUTE SCHEDULER）——四层架构 v1.0

- **版本**：v1.0（2026-09-02 12:48，主会话起草；用户定调"策略选择 → 今日任务包 → 路线求解器 → 机械执行"）
- **定位**：替换 `_schedule_units_v72`（Phase A 红线分配 + Phase B 逐回合贪心）为**黎明一次求解的日路线执行器**。归入 `docs/phase_branch_plan.md` §9 的 R 系列轨道（本文件取代原"匈牙利→v9 转正→EDF"三步走，合并为一次架构切换 + 分里程碑门禁）。
- **本次讨论的关键裁决**（2026-09-02，用户）：
  1. 引擎确定性 + 农场主权（对手碰不到我方田畜）+ 义务自造性（种植/买畜/买地皆我方决策）⇒ **当日可在黎明完整固定**；
  2. 红线不再是运行时类别——它是任务表里 deadline 最早的字段，由求解器前置消化；
  3. 每回合层**不再分配任何东西**：只做机械执行 + 市场单 + 一个只读断言，断言失败的唯一反应是**整体重建当日计划**（回到求解器），绝不现场微调。
- **要消灭的实测病**：idle-PASS ~50%（tetsuya 13%）、连续性 47-57%（tetsuya 78%）、任务无限饿死（荒草 +2/+3/局、收割滞后）、v10.5 九工人震荡类（结构上不可能再发生——没有每回合重分配的舞台）。

---

## 1. 四层架构总览

```
┌─ L1 策略选择（已有，phase_branch_plan.md）
│    _macro_plan → 阶段 × 分支 → plan 参数包 + 阶段寄存器
↓
├─ L2 今日任务包 _build_mission（新，黎明 h0-2 一次）
│    plan + 黎明观测 → 全量任务（带 deadline/价值/依赖/场景标签）
│    + 当日 capex 事件表（种植窗口含浇水容量预留 / 买地场景分叉）
│    + 可行性检查（每任务 ETA < deadline，不可行→砍尾或举容量赤字）
↓
├─ L3 路线求解器 _solve_routes（新，黎明 + 事件触发）
│    分区（家区）→ 簇内排序（deadline 类 × 价值密度）→ 最近邻成路
│    → 2-opt 抛光（每步换位后重验 ETA）→ 输出路线承诺（含逐站 ETA）
↓
└─ L4 机械执行 _execute_routes（新，每回合）
     沿线走、到站执行；等待时做被动填充；
     市场层照旧逐回合下单（价格逐回合动，不属于雇工算法）；
     断言：每件 deadline 任务 已完成 or ETA 仍可达 —— 失败→触发 L2/L3 重建
```

**单分配器原则**：任务→工人的分配只发生在 L3；L4 永不分配。事件（场景切换/断言失败/工人集合变化）的唯一出口是重建，不是微调。

## 2. L2 今日任务包（_build_mission）

### 2.1 数据结构

```python
mission = {
    "day": d, "player": p,
    "plan": plan,                       # L1 输出（分支参数包）
    "scenario": "base",                 # 场景变体激活态：base / LAND_OK / ...
    "tasks": [task, ...],               # 全量任务（含各场景变体任务，按 scenario 过滤）
    "events": [                         # 当日条件事件（黎明已知其时点与条件）
        {"hour": 8, "kind": "BUY_LAND_NE",
         "variants": {"ok": ["LAND_OK"], "fail": []}},   # 场景标签
    ],
    "capacity_deficit": [],             # 可行性赤字（回传策略层：禁止再种植/再买畜）
}

task = {
    "key": ("WATER", x, y),             # 稳定主键（确定性排序用）
    "op": "WATER", "x": x, "y": y, "act": ["WATER"],
    "deadline": 23,                     # 小时；None=无截止
    "v": 240,                           # 终局价值估计（沿用 _crop_future_value 系）
    "cls": "OBLIGATION",                # OBLIGATION | YIELD | BONUS | LOGISTICS
    "deps": [...],                      # 前置任务键（如 water 依赖 plant）
    "need": None,                       # 载货需求（FEED→WHEAT：先 PICKUP 后配送）
    "scenario": "base",                 # 属哪个场景变体
    "units": None,                      # 可执行工人限制（沿表现有 eligible 语义）
}
```

### 2.2 任务来源与 deadline 标注

| 来源 | cls | deadline | 说明 |
|---|---|---|---|
| 喂全部牲畜 | OBLIGATION | **h16**（保守提前，引擎真死线 h23 晚间刷新；留 7 小时裕量） | 头数黎明已知；数量=头数（CARE 超发是引擎 no-op，不生成） |
| 浇全部在地作物 + **当日新种** | OBLIGATION | **h21**（留 2 小时裕量） | 引擎规则：当日种下即断水，晚间未浇即枯——**种植任务与其浇水任务同包出生**（§2.3） |
| 收成熟作物 | YIELD | 当日（过熟衰减） | v 随熟度/价格带衰减 |
| 照料 | BONUS | h23 | 加成项，密度最低 |
| 轮作 DIG / 杂草 DIG | BONUS | None | 深夜窗口（沿 WEED_DIG_HOUR_MIN≥20 语义：排在路线尾） |
| 放置牲畜/建造 | LOGISTICS | 当日 | 依赖购买事件场景 |
| 拾取/归还（PICKUP/DROP） | LOGISTICS | 与依赖任务绑定 | 载货腿（§3.2） |
| d29 末日 | 全部 | — | 特化模板：归还（红线级）+ 只卖不买（沿现有 last_day 分支） |

### 2.3 当日 capex 时点收编（新增职责，治 ep104585743 类）

种植/买畜/买地的**时点决策**从"市场层随缘"改为任务包内事件：
- 种植：策略层给出"今日配额 N 格 + 窗口（默认白天 h8-16，PLANT_HOUR_MAX 语义）"；任务包生成 N 个 PLANT 任务 **+ N 个配对 WATER 任务**，容量预留即自动成立；
- 买地：事件 h8（钱够即发，沿用现有 BUY_LAND 门），场景标签 LAND_OK，配变体任务集（新象限的建/种任务）；
- 买畜：事件 h0-2 黎明（沿 _buy_pace 步速确认语义不变）。

### 2.4 可行性检查（前置消化原 Phase A + V-T3）

```
对每条路线（L3 产出后回验）：
  eta_i = Σ(行走 + 操作) 累加
  任一 eta_i > deadline_i：
    1) 砍同簇内价值密度最低的 YIELD/BONUS 尾部任务 → 重验
    2) OBLIGATION 仍不可行 → 记 capacity_deficit（策略层当日禁止再种植/买畜；
       这是"种 10 格死 16 格"的结构性预防）
```

## 3. L3 路线求解器（_solve_routes）

### 3.1 分区（cluster-first）

- 工人家区 = 当日首格所在象限（沿 v9 `_route_state` 语义；黎明雇工后即固定——**引擎 hands 黎明重置、日内集合不变**，可全日规划）；
- 任务按 `_quadrant_of` 归区；载货腿跟依赖走；
- **负载均衡**：某区任务时间 > 工人数 × 24 × 利用率（ROLLOUT_UTILIZATION 语义），溢出任务按（价值密度 − 跨区行走成本）划给最闲邻区——取代 CROSS_SECTOR_VALUE_EDGE 的每回合软门槛，成为唯一的跨区机制。

### 3.2 簇内成路（EDF × 价值密度 + 依赖）

```
构造（最近邻变体，紧迫感主导）：
  候选按 (deadline 升序, 密度降序) 排；
  从当前最紧迫未构造任务出发，贪心选下一站：
      next = argmax over 候选 of ( 紧迫分 − λ·距离 )
      紧迫分 = w1·(deadline 临近度) + w2·密度 + w3·老化(aging：昨日未完成的 +α/天)
  载货腿：FEED 前自动插入最近仓口 PICKUP（need 语义），构成依赖边；
抛光：
  2-opt / Or-opt 仅在**同 deadline 类**段内换位（跨类换位破坏 EDF 序），
  每次换位后重算该段 ETA，不可行即回滚；
输出：
  route = {"worker": ui, "sector": "NW", "stops": [key...], "etas": [h...]}
```

- **aging 老化因子**：任务带 `age`（跨日未完成 +1），密度 ×(1+0.25·age)——荒草/收割滞后的断根项；
- **确定性**：全部排序键终结于 (key) 字典序，同输入必同输出（黄金测试前提）。

### 3.3 与现有代码的复用关系

| 现有资产 | 处置 |
|---|---|
| `_build_tasks` 的任务生成逻辑（价值/eligibility/水窗护栏/载货） | **平移**进 `_build_mission`（占新代码 ~60%） |
| v9 `_route_tasks` 的分区/事件重建/巡游思想 | **吸收**进 L3（分区与重建触发器），影子路由退役 |
| `_schedule_units_v72` Phase A/B、STICKY/CROSS_QUAD/BUCKET 旋钮 | **删除**（结构替代：路线即连续性，deadline 即红线） |
| FEED_RED_HOUR | 语义转为 feed deadline=h16（不再运行时升级） |
| 现有 executable() 合法性检查 | **保留**在 L4（发射前最后一道） |

## 4. L4 机械执行（_execute_routes）

```
每回合每工人：
  cur = 当前站；在目标格且 executable → 发动作，标记完成，前进；
  否则 → 向 cur 走一步（沿 _step_towards；一次性引擎核对：确认无阻格）；
  等待态（库容满等）：被动填充——相邻 CARE/COLLECT_FERTILIZER/走向下一簇；
市场层：照旧逐回合（价格逐动，天然逐回合域；SELL 优先级已有库容释放语义）；
断言（毫秒级只读）：
  for t in tasks if t.deadline and not t.done:
      eta_now(t) 可达？ 否 → REPLAN(event="slip")
重建触发（唯一出口，回到 L2/L3）：
  场景切换（quads 变化）| slip 断言 | 工人集合变化 | 库容满 DROP 失败 | 种子耗尽
```

- **永不崩溃**：L4 整体套现有 try/except 兜底，重建失败回退 v72 残留副本一版（过渡期保险，M5 后删除）；
- **末日特化**：d29 任务包为归还+倾销模板，断言对归还任务按红线 deadline 校验。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 路线僵化错过日内新富（远端高价收割） | 场景/事件触发重建 + 均衡溢出机制；M3 影子指标专测 |
| 求解质量差（成路劣于贪心） | M3 影子对比是硬门；λ/老化系数进消融矩阵（单变量） |
| 阻格导致 _step_towards 卡死 | 一次性引擎核对（有无不可走格）；必要时 BFS 绕行（小棋盘代价可忽略） |
| 库容×市场耦合（DROP 时棚满） | 任务包留容量裕量；市场层 SELL 释放优先级已有；DROP 失败→断言→重建（插倾销腿） |
| 确定性漂移（跨版本行为对比失效） | 黄金哈希锁定任务包与路线；任何哈希变化必须显式登记 |
