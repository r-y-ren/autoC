# 雇工路线调度器设计（WORKER ROUTE SCHEDULER）——四层架构 v1.2

- **版本**：v1.2（2026-09-02 13:19 增补 §2.6 容量定律与 deficit 前馈 + M1 定标任务；v1.1 12:59 引擎实证版；v1.0 12:48 起草）
- **定位**：按"策略选择 → 今日任务包 → 路线求解器 → 机械执行"四层架构重构雇工调度。
  **本版为引擎实证版**：v1.0 的四个开放风险全部经 vendored 引擎源码核验关闭（§1 事实表）。
- **范围裁决**（用户 2026-09-02）：当前 `agent/main.py` **只作行为参考**，实现走重构而非
  平移改造——v1.0 中"六成平移 _build_tasks / v72 过渡期回退"的表述作废；行为等价性用
  黄金回放对照保证，不在新代码里保留旧调度器副本。
- **讨论裁决**（2026-09-02，不变）：
  1. 引擎确定性 + 农场主权 + 义务自造性 ⇒ 当日黎明完整固定；
  2. 红线 = 任务 deadline 字段，求解器前置消化；
  3. 每回合层不分配，只执行 + 断言，失败唯一出口 = 整日重建。

## 2. L2 今日任务包（_build_mission）——按事实表修订

### 2.1 数据结构（同 v1.0）

task = {key, op, x, y, act, deadline, v, cls, deps, need, scenario, units}；
mission = {day, player, plan, scenario, tasks, events, capacity_deficit}。

### 2.2 deadline 分级（F2/F3/F5 重写）

| 集合 | 判据（黎明可算） | deadline | 语义 |
|---|---|---|---|
| **D1 今夜必死** | 作物 streak≥1 / 当日计划新种；牲畜 streak≥1 | 浇 h21 / 喂 h16 | 硬保证对象（§5 定理） |
| D2 明夜必死 | 作物/牲畜 streak=0（用宽限） | 次日 D1 | 正常仍当日做（优先级次之）；只在容量赤字时显式动用宽限 |
| D3 产钱窗口 | 非连续产作物 age∈窗口（F5） | 当日 | 漏浇=永久减产；v 按窗口剩余价值标注 |
| D4 收割/照料/DIG | 过熟衰减 / 加成 / 无 | 当日/无 | 密度排序项 |

### 2.3 喂食的前置条件（F4）

黎明检查：棚仓+随身小麦 ≥ D1∪D2 牲畜数；不足 → mission.events 注入 h0 BUY_PRODUCT WHEAT
（市场层优先级 95 已有），断言覆盖"到喂食腿时点小麦是否到位"。

### 2.4 EOD 预算（F6，新增硬约束）

```
日终检查（黎明排程时解不等式，日内断言复核）：
  Σ(棚仓现有 − 当日计划卖出 + 计划收割入仓) ≤ 100
  不满足 → 增卖计划（log 曲线小麦优先）或削减收割顺序尾
```

### 2.5 卖出排程耦合（F9）

计划卖出分散在固定小时段（如 h6/h12/h18），保证任何 DROP/日终归还前一回合已有卖出落地
腾位。市场层仍逐回合按门控微调**卖什么**，但**何时必须有卖出**由任务包排程。

### 2.6 容量定律与 deficit 前馈（v1.2 新增，与 phase_branch_plan §5.3 对偶）

> 分工裁定：**策略层（branch plan §5.3 容量前置门）负责只生产可行计划；本层负责证明
> 或标记**。本节是两层之间的焊点。

**容量定律**（经验定标，M1 前为初值）：

```
最大资产单位(d) ≈ 24 × (1+H) × 0.75 ÷ 2.4
资产单位：莓/麦/瓜格=1，萝卜格=0.5，牲畜头=2；crew 12 ≈ 90-97 单位
定标锚：Renji ~81 / DevilQ ~92 / tetsuya ~91 单位均跑在 crew 12（不同组合同收敛）
```

**前馈接线**：

1. `_build_mission` 黎明计算 units_tomorrow（现有 + 已排 capex 事件增量），对照定律值：
   - > 0.85 → 使命内的 capex 事件（种植配额/买畜）**就地缩量到界内**，并写
     capacity_deficit 供策略层下日参考——**超限计划在黎明即被截断，不进求解器**；
   - < 0.65 → 报 slack 余额（策略层按单位日收入降序补线，兜底=小麦）；
2. 调度侧 deficit 语义随之收窄：从"事后红旗"变为"对 bug 与未知项的保险"——
   正确实现下（F7 日零随机 + 策略层前置门）**断言与 deficit 在常态都不触发**；
3. 峰值日：mission 对 D3 产收夜叠加日做峰值校验（错峰种植由策略层控制，本层只验证）。

**M1 定标任务（新增交付物）**：telemetry 按资产类别实测"回合/单位/日"系数
（浇水/收割/喂食/照料/走路分项），与参考回放（v10.9 + tetsuya + top-20 语料）交叉，
回填定律的 2.4 与利用率 0.75；同时裁决开放问题——C1 的 crew 15 是否过量配置。

## 3. L3 路线求解器（_solve_routes）

### 3.1 分区（v1.1 修正：F6）

- ~~家区=当日首格象限~~（全员出生棚仓口，退化）→ **负载均衡指派**：
  按任务簇（象限×cls 工作量）÷ 工人数 分派，工人黎明统一从棚仓出发（前 1-3 回合为

## 4. L4 机械执行（_execute_routes）

```
每回合每工人：到站且 tile 态未完成（F4/F8 去重+合法性）→ 发动作；否则走一步；
季中无归还腿（F6 自动）；d29 模板：DROP（查 room）→ SELL，随身清零离场；
断言（只读，毫秒）：D1 已完成 or ETA≤deadline；EOD 预算投影 ≤100；
  失败 → REPLAN（场景切换/物料断档/断言），新计划==旧计划则停止重建（幂等闸，F7 下
  正确实现永不触发）
市场层照旧逐回合（卖什么），何时必须有卖出由 §2.5 排程。
```

永不崩溃：整体 try/except → PASS 兜底（提交纪律不变）。

## 5. 保证定理（审查结论：能否保证完成任务）

**定理（proved-or-flagged）**：在 F1/F6/F7（无阻挡、日零随机、工人集合日内恒定）下，
求解器输出的每条路线其逐站 ETA 是**精确**的；因此：

1. **断水枯死**：每个 D1 作物任务 ETA ≤ h21 当且仅当黎明被排入路线——
   **要么被证明覆盖，要么进 capacity_deficit**（显式分诊：按价值排序部分覆盖 +
   策略层当日禁增义务）。不存在"以为浇了实际没浇"的中间态。
2. **断粮逃亡**：同构；另含物料前置（小麦库存 §2.3）——库存不足在黎明即暴露，
   不是 h15 才发现。
3. **末日归还**：季中归还被 F6 引擎自动完成（任务包无需排腿）；d29 的 DROP+SELL
   按 room 逐腿验证，随身清零是断言项。
4. **EOD 溢出销毁**（F6 唯一静默损失源）：由 §2.4 日终预算不等式前置消化。

**不保证的**（诚实边界）：路线的**最优性**（同约束下是否有更短路线）——这由 M3 影子
门（与参考回放的分歧统计）和消融矩阵背书，不由定理背书。调度器也不能无中生有容量：
15 头牲畜×喂食腿超过全队 24×n 回合物理上限时，任何算法都只能选择谁先死——
本设计的价值是让这个不可能在**黎明显形**（deficit → 策略层停止扩栏），而非深夜暴雷。
