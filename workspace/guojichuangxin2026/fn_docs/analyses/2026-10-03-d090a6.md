## 四、改进提案

### P1 真数据面接入+批量跑批 [高]
- 现象：快照 runs=2/90；hit_rate=0.0 且模型通道未启
- 假设：run_eval 职责要求按失控判据计时，现 risk 通道 model=None（基线滞后 5s）+PX4 未接
- 改进方向：PX4 SITL 真跑接入 spawn_sitl；train_tcn 合成重训后接入 eval；三场景×30 次跑批入库
- 预期信号：快照 runs≥90；lowbat lead_p10_s ≥3s（合成训练下）；hit_rate(lowbat)≥0.3
- 分流：参数/逻辑级
### P2 口径修正（时延/命中率按场景分列） [高]
- 现象：confirm_p90=0.0s；motor hit_rate=0.0
- 假设：run_eval 突发时延从事件 onset（=确认拍）起算而非注入时刻；hit_rate 误套突发
- 改进方向：manifest 记 inject_at_s，时延=t_confirm−inject_at；hit_rate 仅渐进场景输出
- 预期信号：confirm_p90∈[0.1,0.6]s；突发场景无 hit_rate 字段
- 分流：参数/逻辑级
### P3 验收深度补齐（sw-boot 三步+归档规约） [中]
- 现象：smoke_boot 仅 compile；runs 落点漂移
- 假设：smoke_boot 职责=sw-boot 验收本体；数据源条目=fn_docs/results/
- 改进方向：smoke_boot 加"合成会话起+服务探活+回放 API 探活"；open_run_dir 归档步或 runs_root 统一
- 预期信号：sw-boot 单命令输出三项 PASS；新 run 产物直落（或归档至）fn_docs/results/
- 分流：参数/逻辑级
### P4 设备实测包（m2b 对应） [中]
- 现象：hw-edge/hw-sdr 验收项 0 实测；sdr_check 设备分支未真跑
- 假设：适配器代码在、设备缺席（外部依赖）
- 改进方向：B210 标定脚本+Orin NX bench_edge 部署脚本（设备到位即跑）
- 预期信号：sdr_check 设备在场分支 PASS；bench_edge 出 P95 实测 ms
- 分流：待外部依赖（代码侧可先行备脚本）
### P5 产品化包装（激进项） [低/远期]
- 现象：无 pyproject/安装器/用户手册/长跑验证
- 假设：演示级→可交付级的结构性缺口
- 改进方向：pyproject+一键安装+用户手册+1h 长跑稳定性+交付盘镜像
- 预期信号：外部机器 pip install 后 demo.sh 一次成功
