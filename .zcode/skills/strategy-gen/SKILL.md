# K-02 strategy-gen：参考方案供给（v2 纯参考）

## 输入

- `kb/INDEX.md`（唯一入口；需要细节时按索引定位到条目再精读）
- `config/profile.yaml`（未填写则先向用户收集，或声明按"通用学生队低配"假设）
- 用户指定：赛事 ID 或方向描述

## 流程

1. **矩阵评分**：对 INDEX 中候选赛事逐个打分（时间窗匹配 2–10 周最优 / 技术契合度=KB-2 卡片与该赛
   获奖模式重叠——**"大显身手"信号显式化：近 90 天入库新卡 × 该赛 patterns 分布命中，作为加权项** /
   通吃度=同一作品可复投数 / 画像匹配 / 竞争密度）。**每格标注证据强度**（该赛 patterns 有/无、
   KB-2 卡数）——证据不足的维度如实降权并告知"该维度基于有限数据"，禁止假装有依据
2. **grilling 前置步**：以 `kb/INDEX.md` 与相关条目为语境，对用户做**完整 grilling**（mattpocock
   grilling 语义：决策树多轮问答，frontier 问空为止、无轮次上限，用户喊停即止）——至少澄清：
   选赛意图与优先级 / 时间窗与人力约束 / 作品范围边界 / 技术栈偏好与风险容忍 / 一鱼多吃期望。
   纪要落 `kb/briefs/<方案书同 slug>-grill-notes.md`（与方案书同名对应）
3. **方案书（三节，纯参考）**：按 `config/templates/brief-template.md` 产出：
   - **赛事**：情报摘要（逐条回链条目 ID + 抓取日期）/ 对比矩阵 / 大显身手信号行（具体卡片 ID）
   - **方案**：一句话主张 / 一鱼多吃路线 / 范围边界（做什么、不做什么显式排除）/ 推荐结论
     （明确第一名 + 理由 + 备选；无可推荐窗口时诚实兜底，禁止硬推）
   - **技术栈**：构件选型表（每项引用 kb_tech_ids / 实抓来源）/ 合规与风险（mode 三分判定：
     prep/apply/assist，依据该赛 ai_policy 原文）
   **禁止**：milestones、acceptance、接口契约、fn-ladder 需求种子等任何推进指令
4. **入库**：`kb/briefs/<日期>-<赛事slug>-<方案slug>.md` + `kb/briefs/README.md` 登记一行；
   `--to <战役根>` 时复制一份到 `<战役根>/docs/briefs/`（项目资料归项目，工作流侧留正本）
5. **摘要呈用户**（通知，非闸门）：三节要点 + 入库路径；要求修改则改后重新入库（追加修订行）

## 纪律

推荐结论必须引用具体 KB 条目 ID 并携带抓取日期（铁律 1），禁止凭印象；ACM 方向只出训练体系类
参考方案；方案书是**纯参考信息**——不得充当推进契约、不得影响后续推进（铁律 2/边界）。
方案书系工作流生成参考（非外部抓取资料）；若其中摘引外部原文，原文仍归 `<战役根>/references/`
并登记 INDEX（铁律 3），`--to` 副本只放生成文本。
