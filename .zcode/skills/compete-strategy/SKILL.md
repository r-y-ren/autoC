# compete-strategy：对抗比赛从零制胜（控制论九步）

## 核心模型（先建立这张图，后面全是它的展开）

把比赛写成控制系统：

```
状态 X = (双方资源, 价格/分数, 场面, 时间...)      ← 引擎源码定义全部细节
动力学 X(t+1) = f(X(t), 我的动作 u, 对手动作 u', 随机 rng)   ← f 就是引擎
目标 J = 终局分数差（成对）/ 池内评分（全局：BT/Elo）
```

**策略 = 选一组想影响的状态坐标（"参数"），设计杠杆 u 把它们推向有利方向，让 J 变大。**
两条关键认知：

1. **策略的正确形态是控制系统**，不是文档。观测器（估隐藏坐标）+ 前馈（预设资产）+ 反馈（在线规则）+ 防御（净账护栏）+ 整定（调参）是同一系统的不同零件——"查表派/规则派/学习派/搜索派"不是流派之争，是在**最合适的坐标上用最便宜的技术**。
2. **决策面是三维立方体**：时间轴（开局/中盘/终局）× 领域轴（生产/市场/用工/土地）× 认知类型轴（常量/资产/算法/信念/旋钮）。"本质是确定参数"只覆盖旋钮那一格——**价值密度最高的是资产格和算法格，最低的是旋钮格**（实证：末梢常量在平台区，改一处参数 286 局差 0-1 局；磁带/检索库/清算器才是分差主体）。

## 九步流程（顺序硬性，跳步必返工；每步有产出物与验收）

下行拆解四步 + 上行构建五步——同一推理链走个来回：

```
分数 ← 战胜对手 ← 资源 ← 买卖/用工 ← 参数(状态坐标)     ← 下行：拆
  ↓        ↓        ↓        ↓          ↓
定J     画对手池  拆资源流  提参数分级  选杠杆开回路      ← 上行：建
终榜 ← 迭代验收 ← 净账 ← 分层装配 ← 设定点轨迹(资产)
```

### 第 0 步：合规与入口判定（先于一切）
- **查该赛 ai_policy 是否允许 AI 辅助**：官方赛事（宝可梦官方、部分电竞）可能禁 AI 辅助——不允许则本 skill 只许用于训练/分析，不许产参赛件；允许则记 mode（prep/apply/assist）+ policy 原文摘引进合规台账。
- **技能边界**：strategy-gen 管"选哪个赛、登记战役、出交付蓝图"；**本 skill 管"这个赛怎么打"（玩法制胜）**。若战役尚未登记，先走 strategy-gen。
- 产出：合规判定一行（mode+policy 依据）。死法：打完才发现违规——作品作废且有纪律风险。

### 第 1 步：定 J 和迭代标准 + 判决池 v0
- 读规则写死"分数怎么算"（终局钱/胜场/名次），定迭代标准 = **池内稳健胜率**（对多原型的稳健口径；不用平均胜率——非传递环 A>B>C>A 时两者背离，实证过单挑尺与全场尺选出相反的件）。
- **判决机是一等产出物，不是隐式依赖**（后续第 8 步全部迭代靠它量；实战中这套基建是数周工作量，晚建=走到迭代步才发现没尺子）。最小判决池 v0 = **自镜像对照（噪声地板）+ 一强锚 + 一弱锚**；能本地重放引擎则附对拍认证（重放官方回放逐拍一致）。
- 产出：目标函数声明一行 + 选优尺定义 + **判决池 v0 可跑**。验收：拿两个已知强弱有别的候选排序，尺子排对；自镜像 h2h≈0.5（噪声地板基线）。
- 死法：优化目标错位——越努力越偏（实证：用单挑强弱选优、终榜按全场稳计，白走数周）；迭代步没尺子——第 8 步停工补建。

### 第 2 步：画对手池
- 公开回放聚类成原型（行为指纹：开局一致度/交易节奏/资源结构），画**原型对抗矩阵**（谁克谁）。
- 产出：原型画像卡 + 对抗矩阵。验收：原型跨局稳定（排除版本混样）。
- 死法：对"平均对手"优化——非传递世界里没有平均对手。

### 第 3 步：拆资源流，找杠杆
- 对回放做"赢家 vs 输家"的资源流分解（钱/分被哪些流量解释），找解释力最大的流。
- 产出：资源流分解表 → 战区图雏形（时间×单步价值×可离线度）。
- 死法：跳过直接写策略——兵力凭兴趣部署（实证：中盘兵力过重，而分数大头在开局+终局）。

### 第 4 步：提参数表 + 可控性分级【引擎源码六问法】
- 对引擎源码跑六问，列全部状态坐标，按四级分类（**详见 references/engine-six-questions.md——拿到引擎源码时先读它**）：
  **可控**（我的动作）→ **可影响**（双方共推：价格/对手收入，策略主战场）→ **可观测不可推**（对手隐藏资源，观测器由来）→ **不可控随机**（抽签/发牌，方差预算）。
- 产出：状态坐标总表 + 可控性等级（模板 T1/T2 见 references/templates.md）。
- 死法：只读规则文本不读引擎实现——规则有三层皮（宣传页/正式文本/引擎源码），**真规则在代码里**；实现缝（静默失败/截断/边界）= 免费价值 + 防御刚需。

### 第 5 步：选战场 + 测转移函数
- 只在"可影响"级开控制回路；对每个坐标做**阶跃实验**测转移函数：我推 X 单位 → 坐标动多少、自伤多少、对手伤多少（本地引擎可测）。
- 产出：转移函数表（杠杆→效果曲线→自伤曲线）。验收：曲线带测量误差带。
- 死法：无对象模型上控制器（实证：手写回路全对但"效果很差"——缺的就是这张表）。

### 第 6 步：定设定点轨迹 = 资产化
- 每个坐标的"目标值随时间的轨迹"**从语料来**（高分玩家回放统计），不是拍脑袋；可计算段用求解器（如终局清算=数学题，别做在线判断）。资产规格书模板 T3。
- 产出：资产库（序列/表/求解器）+ **常量血统表**（每个数字：来源、样本量、置信）。
- 死法：小样直觉入决策层（"6 局直查"）；把该资产化的内容写成叙事文档——叙事承载不了几千个定标数字。

### 第 7 步：分层装配
- 装五个回路：**观测器层**（估隐藏坐标）/ **控制器层**（推价格/对手收入等）/ **调度层**（推资源利用率）/ **清单层**（执行设定点轨迹）/ **防御层**（净账护栏：自伤上限、破产线、静默失败自检、清队）。
- 产出：完整件。验收：每个回路带净账护栏。
- 死法：推参数赢了、钱输了（实证：砸价把对手打崩同时把自己实现价砸到 0.6×base）。

### 第 8 步：闭环迭代
- 单变量 A/B；验收只看两个数：**净账 ΔJ**（不看"参数动没动"）+ **池内稳健胜率**；每个数字带血统。
- 产出：迭代台账（registry：提案→预期信号→判定，模板 T5）。
- 死法：一次改多处；描述性验收（"感觉更稳了"）；无打分的改进循环=盲飞。

### 第 9 步：监控与再适应（常设）
- 对手池漂移监控（换血窗**分段统计**，不混池平均）；版本更新时重跑第 4 步（引擎变了参数表就变）。
- 产出：监控跑批 + 换血判定记录。

## 冷启动降级路径（开赛第一天用这个顺序，不是九步的 1→9）

九步是**成熟态全景**；开赛第一天没有回放语料，第 2/3/6 步的语料前提不成立。首日真实顺序：

1. **第 0/1/4 步先行**（合规→J+判决池 v0→引擎参数表）——这三步不依赖语料；
2. **可计算段求解器先行**（第 6 步的求解器分支）——终局/确定性段是数学题，不需要任何对手数据；
3. **自镜像迭代起步**——种子件（最傻但完整）互打+判决池 v0 校准，先让尺子转起来；
4. **语料边打边攒**——对局积累出回放后回填第 2/3 步（对手池/资源流），资产开采（第 6 步统计分支）随语料量滚动进行；
5. **对手池成形后**升到完整九步。

**无回放语料的退路**（与"无源码退路"同级的常见情形）：①自镜像+合成对手（手写 2-3 个极端风格种子代理当占位原型）②社区攻略/高玩直播当"待验证假设"③规则推演的收益上限先摸清（哪些段可算）。语料一旦出现，占位原型立刻被真实指纹替换。

## 工具选型速查（第 6/7 步选技术用）

| 坐标形态 | 控制论对应 | 工具 | 成本 |
|---|---|---|---|
| 离散+可统计（序列/表） | 前馈 | 语料开采→查表/磁带 | 最低，**永远先试** |
| 分支少+对手原型可枚举 | 博弈预测控制 | 搜索/极小极大 | 中 |
| 手写骨架+少量连续旋钮 | 控制器整定 | 轻量学习（ES/多臂老虎机） | 中 |
| 海量数据可自产+高维模式 | 端到端策略 | 深度学习/自对弈 RL | 最高，前三种边际收益之和被超过才上 |
| 可精确计算的段 | 最优控制 | 求解器（数学） | 一次性，**确定性段必用** |

选型律：**让工具的维度匹配你负担得起的数据量**。预测类 ML 先问一句"这量是不是解析公式已确定"——是则出局（实证：价格=库存确定函数，LSTM 连 persistence 基线都打不过）。

## 纪律红线（每条都是实证换来的）

1. **证据纪律**：每个进决策层的数字带血统（来源+样本量）；样本 <30 只许标"方向性"，不许进定标；观察性结论（回放相关性）必须过受控单变量检验才许入件（实证：带内"三级台阶"观察两级翻车）。
2. **净账纪律**：任何杠杆验收以 ΔJ 计（Δ我−Δ对手−自伤），不以"目标参数动了"计。
3. **单变量纪律**：一次改一处，判负即回滚；同面不可堆叠。
4. **尺子纪律**：评测口径与最终排名口径**严格一致**（成对 h2h ≠ 池内 BT；两者非传递下会反向）；每次读数报块构成+噪声地板（自镜像 0.5）。
5. **对拍纪律**：一切资产带"逐拍对齐率 vs 真实回放"；复刻/调试靠 first-divergence 对拍，不靠"实现了他的策略"这种描述。
6. **叙事纪律**：决策内容不写宣言（`hold iff price > EDGE` 式），写**资产规格书**（生成器+定标数据+验收数字，模板 T3）；文档只承载基建（观测器/调度器设计），资产承载决策。
7. **专名纪律**：比赛名/目录/账号等专名一律程序化派生（从 URL/列表拷贝），禁手拼——实证 7 例拼写污染伪造假信号。
8. **描述性验收禁用**："效果很差/感觉更稳"不可验收；只收可复跑的数字。
9. **派发纪律**：语料统计类重活（第 2/3/6 步的聚类、回放分解、资产开采）**按分片派子代理执行**，主会话只收结论不收原始转储——主会话是瘦协调者，不亲自跑大数据。
